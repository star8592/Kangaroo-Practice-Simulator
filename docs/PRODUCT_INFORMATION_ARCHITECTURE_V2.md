# 国际数学竞赛训练中心：统一身份与页面信息架构 v2

**制定日期：2026-10-08 · 状态：设计基线，待逐阶段实施及验证**

**适用：** `socthink.cn` Web / 微信小程序。**权限准绳：** [ACCESS_MATRIX_V1.md](./ACCESS_MATRIX_V1.md)，不重定价、不撤回既有免费内容、不改变现有付费部署门槛。

## 1. 产品判断：先训练，后建档，按需付费
首次打开 ≠ 被迫登录；微信身份识别 ≠ 获取个人资料；账户免费等级 ≠ 已付费。先以一键进入训练建立价值感，再让家长理解长期档案、错题、家长管家和增值服务。

- **体验层**：游客可浏览、做公开样题/基础计算、查看基础分数和解析；升级不遮挡结果。
- **身份层**：小程序静默换取自身会话，Web 游客匿名可浏览；在“保存/找回/跨设备”时绑定站内学生。
- **数据层**：数据始终按学生隔离；家长-学生关系是经核验的关联，不是姓名同名自动合并。
- **权益层**：free/plus/pro 和后端 grant + quota 独立于登录渠道；会员只为新增增量能力收费。

## 2. 统一的信息架构：Web / 小程序同一产品，不同导航容器

| 一级业务域 | 首屏必须可见的任务 | 游客可用内容 | 登录/身份完善的触发点 | PLUS/PRO 增值展示 | 已有 Web 路径 / 小程序入口 |
|---|---|---|---|---|---|
| 首页 | **开始计算**（主 CTA）；次 CTA **练竞赛题**；我的近期赛事 | 核心训练入口、公开赛事、推荐免费样题 | 不阻挡入口，首次会话后台建立 | 不用在首页堆满 VIP 卡 | `/` / 小程序 `home` |
| 计算训练 | 年级/能力点 → 即刻开练 → 判分 → 基础讲解 | 全学段基础计算、错因即时反馈 | 长期保存、同步到学生档案时提示绑定 | 智能定制练习、个性化打印、长期趋势 | `/arithmetic` / `arithmetic` |
| 竞赛中心 | 赛事 → 组别/年级 → 年份/卷型 → 试题开始 | 赛事介绍、公开真题与样卷、基础模拟与评分 | 长期成绩归档 | 新增受许可高级题库、智能组卷、AI 解题 | `/competitions` + `/exam/[examId]` / `competitions` + `exam` |
| 我的赛事 | 重要事项优先：近期考试、报名、截止、下一动作 | 公共赛事日历 | 个人订阅/提醒、家庭个性化赛历 | 家庭管家高级分析 | `/student/calendar` / 小程序 `events`（二级页） |
| 我的 | 当前学生、最近成绩、错题、奖状、成长记录、设置 | 新设备仅显示临时记录；可选保留 | 长期历史、跨设备恢复、账户绑定 | 个人诊断/报告、会员权益与配额 | `/student`、`/review`、`/student/settings` / `profile`、`review` |
| 家长中心 | 切换孩子、看成绩、管理权益和赛事任务 | 内容说明页 | 经家长身份校验后进入 | 家庭席位、订阅/订单/用量 | `/parent`、`/parent/login` / “我的 → 家长中心” |
| 会员服务 | 我能获得什么、已购状态、权益明细、到期时间 | 透明价格/权益说明 | 下单或查询本人账单时认证 | PLUS/PRO、按次包，未上线不销售 | Web“我的/家长中心”下；小程序“我的”下 |

**导航原则：** 小程序仅保留四个主 Tab：**首页 / 计算 / 竞赛 / 我的**（与现有 `app.config.ts` 兼容），赛事管家挂在竞赛与“我的”场景内；Web 宽屏采用相同的业务名称和主次关系，不照搬底部 Tab，也不再用“登录”作为导航的产品主入口。Web 导航可显示独立“家长入口”，但其权重要低于“开始计算”。

## 3. 不同身份看到同样的入口，打开后按权限呈现

| 情景 | 页面呈现 | CTA 和返回行为 |
|---|---|---|
| 匿名 Web 访客 | 首页和赛事公开、试卷免费可做 | 直接开始；个人持久化才提示“保存成绩”；取消可继续 |
| 临时游客 `guest` | 基础训练/基础成绩 + “临时记录”说明 | “保存到学习档案”，绝不显示成付费解锁 |
| 小程序微信首次识别成功 | 自动取得内部 free 身份，无显式注册表单 | 直接首页；首次需要创建学生档案时询问昵称/年级等最小资料 |
| 已存在但**未绑定**的站内学生 | 新微信账户历史可能为空，不能误认数据丢失 | “绑定已有账号”，双边身份验证、冲突处理、可取消 |
| 已绑定免费学生 | 历史成绩、错题、标准报告同步 | 高级能力处明确“体验/会员能力”及权益差别 |
| 家长 | 学生切换、报告、赛事提醒、会员与订单 | 需要经认证的家长登录和绑定孩子；不能因微信 ID 相同自行合并 |
| PLUS/PRO | 与免费用户相同主导航，增值能力在任务页就地出现 | 显示剩余额度、服务期限、明确失败不扣额 |
| 订阅已到期 | 基础历史仍可读，已完成成绩/报告不消失 | 增量生成入口解释续费，不篡改旧记录 |
| 离线/鉴权服务异常 | 若有本地题库则可作答并保存草稿，或提示可重试 | 不出现空白屏、无限加载、循环返回登录页 |

**界面反模式**：打开就是账号/PIN 表单；首页只罗列少量小字而缺乏可点的训练任务；游客点击公开试卷出现空白；没有数据却显示一排“0 分” KPI；把标准评分、解析当作收费诱饵；因为微信 code2Session 失败而强制关闭核心功能。

## 4. 必须落实的账号模型与边界

```text
      WeChat Mini App -- wx.login/code -- server code2Session
                                         |
 Web password/email / Web WeChat OAuth --+--> auth_identities --> internal account_id
                                                              |
                                                  +-----------+----------+
                                                  |                      |
                                              student_id            parent_id
                                                  |                      |
                                     attempts/mistakes/reports     family_memberships
                                                  |                      |
                                    ownership check <------------- linked students
                                                                         |
                                   verified order/payment --> entitlement_grants
                                                                         |
                                    canAccess(capability, student, verified grants, quota)
```

- 服务端维护渠道凭据与用户身份映射，`provider+appid+openid` 强唯一。WeChat UnionID 有则可用于**已核实后的关联辅助**，不能假设始终存在；不同 AppID 下的 OpenID 不能直接比较。
- `wx.login` 的 code 一次性使用，服务器交换后生成自己的会话 token；绝不把 AppSecret、session_key 或家长支付密钥下发客户端。
- `anonymous`、`guest`、`student`、`parent` 及 free/plus/pro 维持原有策略语义；一个微信已识别账号默认 free，不自动变成已验证家长。
- 登录 token 更新与答题提交幂等化；同一考卷进行中不得因刷新/权益变更丢题或丢交卷。跨设备归并须确认数据主体，并保留可回滚关联记录。
- 未成年人信息按最小化原则处理，手机号、头像、昵称、微信隐私接口按功能必要性和适用的平台隐私保护要求另行请求/声明。

## 5. 页面内容模板与视觉优先级

### 5.1 首页
1. Hero：主标题“每天练计算，随时打真题”，唯一显著按钮 **开始计算**，次按钮 **竞赛实战**。
2. 当前可执行任务：年级/题型选择，直接开始，不要求先填完整档案。
3. 有个人数据时展示“上次做到哪儿”，无数据时展示“推荐新手训练”，**不渲染全零占位仪表盘**。
4. 赛事模块：仅展示现在有效、与你年级相关的下一场比赛与报名关键日期；完整赛历二级进入。
5. 轻量说明：公开体验与会员增量价值；不得全屏推销。

### 5.2 考卷/训练页
- 选题筛选要清楚；“开始训练/开始考试”是可识别的主按钮。
- `/exam/au-amc-pre-a-sample-2` 对游客必须真正展示 **25 题**：文字、公式、图片、选项、提交、基础成绩，不得出现 0 题或空状态误导。
- 用户交卷后免费显示答对错和标准题解；先有结果，再引导保存进档案；高级 AI 题解仅在具体任务节点解释配额/升级。
- 考试状态跨刷新恢复，不将微信自动登录与交卷动作串成竞态条件。

### 5.3 我的/家长
- “我的”首位展示**正在学习的孩子**和切换入口，旁边为可读的身份状态（游客临时 / 已保存 / 家长已关联），会员标记次级。
- 账户绑定、历史数据、学习报告、错题、证书、赛事提醒、订单权益、帮助、隐私和注销有清晰分组。
- 家长切孩子不串成绩；一个孩子仅一份学生主档案，账户合并前明确说明“已有记录不自动合并”。

## 6. 权限在页面和 API 上的共同约定

- 页面可以提示会员价值，但权限检查必须在服务端具体资源 API 再执行：题卷读取、开始考试、交卷、题解、历史、PDF、智能生成、消耗配额。
- 公开功能允许匿名与游客，注册功能需要已核验的学习/家长身份，高级功能需要经后端验真的 grant 和额度。
- 返回 `login_required`：在所需环节引导轻量认证；`upgrade_required`：提供实际收益和权益详情；`source_unavailable`：解释资源不可用而非骗付费；`forbidden`：不泄露他人学生资料。
- 全站共享同一文案：“免费体验 / 保存记录 / 会员增强”；不同端不出现“Web 免费、小程序收费”的权限漂移。
- 首页不含侵入式身份提示；训练中途不强跳订阅页；尝试高级能力后关闭升级弹窗可原路返回。

## 7. 分步落地（顺序约束）

| 阶段 | 范围 | 验收门槛 | 当前状态 |
|---|---|---|---|
| A 权限基线 | `ACCESS_MATRIX_V1.md` + `src/lib/access-policy.ts` + `GET /api/access/me` | 匿名/游客/免费/PLUS/PRO 的规则测试；保持公开样题免费 | **已有基线代码（PR #46 合并），未据此认定端到端生产完成** |
| B 身份桥接 | 小程序会话自动恢复、失效降级；Web 账号关联、家庭关系边界 | 失败不空白，首次微信不误绑、真实设备回归 | **待按本文件验收/补齐** |
| C 页面统一 | Web 顶部导航、首页 CTA、计算/竞赛/我的模板；小程序相同术语和任务层级 | 三类用户一条主线，公开样题 25 题，手机/平板/桌面可用 | **待实施、验收** |
| D 账本与授权 | 事务权益数据、配额、退款、支付异常；来源/所有权鉴权 | 后端拒绝测试、隔离、超额、退款、幂等通过 | **账本代码已合并 PR #47；生产数据库、支付适配与灰度尚未验收** |
| E 灰度上线 | 限流回滚、发布日志、用户验收；按既定 P2–P5 门槛逐步放量 | Web+小程序同主体权限一致，付费链路经审核、线上稳定 | **未验收** |

**执行纪律**：不在工作区混合其他开发分支；不动真实支付密钥；不为 UI 改造清空用户数据；先回归公开用户路径，再灰度部署；每阶段分别报告“设计/代码/构建/实机/公网”证据。

## 8. 验收样例（E2E 与权限）

1. 无 Web Cookie：访问首页、公开赛事、`/exam/au-amc-pre-a-sample-2`，试卷 25 题完整可见、提交有基础成绩。
2. 初次打开小程序：展示首页和“开始计算”，没有自动弹登录/PIN；成功静默登录为 free、失败可降级使用公开功能。
3. 第二次打开：在绑定同一学生情况下恢复历史；**未绑定**时明确说明不会自动出现原网站成绩。
4. 学生 A/B、家长 X/Y：家长只可看已合法绑定的孩子；切换孩子后成绩与权益分别核验，不能越权。
5. 免费/PLUS/PRO：既有免费能力一致；新高级功能根据服务器返回不同入口/配额。
6. 过期/退款/重复回调/网络断线/交卷与令牌刷新并发：基础记录留存，权益正确，失败不扣次数、不漏交卷。
7. 中英文、不同屏宽（含三星平板竖屏）体验一致；按钮可发现、文字不小到难读、没有空白页/全零 KPI。
8. 检查后端 API，不以 UI 隐藏替代鉴权；代码覆盖登录失败、401/403/404/429、权益缺失和资源不可分发等状态。
