# SOC THINK｜OCR技术中立测评与引擎选型（2026-10-31）

## 执行摘要

**暂不指定单一OCR赢家。** 2026年高性能识别至少分三条技术路径：传统/非生成式OCR（PP-OCRv6）、专业文档解析型小型VLM（PaddleOCR-VL-1.6、MinerU2.5-Pro、GLM-OCR等）和通用视觉大模型（已装Qwen3-VL 8B、ChatGPT人工疑难复核）。中文印刷文字、数学公式、扫描卷的几何图、视频/屏幕截图对各模型考验不同。不能以通用大模型参数量或单张样图的成功推导生产准确率，也不能把厂商自报的相对提升认作第三方统一排名。

真实Z890现状：RTX 5070 Ti 16GB、现有Ollama实际为127.0.0.1:11534、已装qwen3-vl:8b、FFmpeg/FFprobe/Pillow；当前未装Tesseract/PaddleOCR/Pix2Text。**已实测1张自制中文数学图，Qwen3-VL识别中文字、两道计算题和LaTeX分数且返回私有文件/哈希回执。**7项原有媒体处理回归通过。它是功能性冒烟测试，不是质量Benchmark，不能宣称“Qwen比专业OCR准”。现阶段正式采集与OCR选型分离；已建立用于客观计分的脚本 `scripts/evaluate_ocr_engines.py`，已通过6项回归测试。

## 可靠公开依据与日期

### 1. 同一文档解析基准 OmniDocBench v1.6_full
直接参照 [OpenDataLab/OmniDocBench 官网仓库](https://github.com/opendatalab/OmniDocBench)。1651页真实文档，覆盖文字、公式、表格、阅读顺序及中文与英文等。其项目README的2026-10-31抓取结果（注：不同模型的数字可能来自各自提交/公布，非全部第三方独立重跑）：

| 模型 | 类型 | 综合分↑ |
|---|---|---:|
| OXR-1.0 | 专业VLM | 97.03 |
| TeleOCR 1.2B | 专业VLM | 96.91 |
| OvisOCR2 0.8B | 专业VLM | 96.47 |
| PaddleOCR-VL-1.6 0.9B | 专业VLM | 96.34 |
| MinerU2.5-Pro 1.2B | 专业VLM | 95.75 |
| GLM-OCR 0.9B | 专业VLM | 95.22 |

**分数不是中文小学生数学试卷的正确率，不是“每100字准确96字”；更不能把不同发布者、版本、不同评测集的分数混排。** 衡量公式时参考FormulaCDM，文字参考TextEdit，阅读顺序参考Read Order Edit。

### 2. 实拍/屏幕/弯曲等特殊情况 Real5-OmniDocBench
[Real5-OmniDocBench测试集及原始表](https://huggingface.co/datasets/PaddlePaddle/Real5-OmniDocBench)。基于1355文档页，分别模拟扫描、纸张弯曲、屏幕拍摄、光照、倾斜共6775张图片。PaddleOCR-VL-1.6综合93.19；结果并非中文考试截图专用准确率，而且数据集由PaddleOCR团队建设，应纳入来源利益关系判断。对我们小红书、微信、手机拍摄画面的相关性高。

### 3. 不同基准可能得出不同排序
[AllenAI olmOCR-Bench](https://github.com/allenai/olmocr/blob/main/olmocr/bench/README.md) 采用约1400文档、7000+检查点，区分老扫描、数学、表格、多栏、微字等。不同评测设定下MinerU、PaddleOCR-VL、Marker的结果差异明显。它证明应按我们自己的真实用途复现而不是盲信单榜。

### 4. 非VLM文字OCR
[PaddleOCR 3.7 / PP-OCRv6官方发布](https://github.com/PaddlePaddle/PaddleOCR/releases)：2026-06-11，非生成式轻量文字OCR，tiny/small/medium，medium约34.5M参数；其声称相对旧版在自有测试集有更好性能，**这是厂商自报、不是独立对当前GPT-6的评测**。值得作为中文印刷批量速度与确定性基线，不意味着它能一次理解复杂几何图或将所有公式正确转LaTeX。

### 5. 公式和数学试卷专用
- [Pix2Text](https://github.com/breezedeus/Pix2Text) 同时做中文/英文文字、公式定位、公式OCR、版面和Markdown输出，核心公式检测MFD和识别MFR 1.5；作为开源、可本地运行的独立公式对照组。
- [PaddleOCR PP-FormulaNet_plus](https://www.paddleocr.ai/main/en/version3.x/module_usage/formula_recognition.html) 官方推荐其中M/L变体用于中文公式；这是公式局部区域的识别模块，不能替代整页题目结构解析。
- [Mathpix OCR API](https://website.mathpix.com/pricing/api) 是付费专业数学OCR对照项：网页公开标注每张图片$0.002、PDF每页$0.005起、一次性设置费$19.99。价格会变化，实际计费前按官网核验。不是默认付费主线。

## SOC THINK 的专业横向对比实验：先准备，再决策

**评估集建议**：先做200页真实、有权使用、已确证答案或老师能校对的代表性资料；按8类各25页分层抽样。

1. 中文印刷清晰试卷；
2. PDF扫描、低清复印和倾斜；
3. 小红书/微信图片排版、手机截图（授权范围内）；
4. 数学公式（分数/根式/上标/不等式/负号/集合）；
5. 几何图、函数坐标图与题图；
6. 表格、多栏和混合图文；
7. 手写答案、涂改/部分遮挡；
8. 已有权处理的视频合法截图（字幕与题目混合）。

**测试引擎（相同输入）**：PP-OCRv6-medium（非VLM基线）、PaddleOCR-VL-1.6（专业文档）、Pix2Text+PP-FormulaNet_plus-M（公式专线）、本地Qwen3-VL 8B（已有）、ChatGPT人工疑难复核/额外比对。另可将MinerU2.5-Pro、GLM-OCR、Mathpix作为补充候选，部署成本许可需核实。每页同一像素图、同一文字渲染和预处理，记录模型精确版本、GPU、推理参数、并发、时间和耗电/价格，严格防止不同清晰度输入产生不公平排名。**没有对照输入、未运行的引擎不填写成绩。**

**评测指标**：
- 字符错误率CER：字级编辑距离/参考文字字数；数学符号不作宽松替换。
- 数字序列准确：题号、负号、数字、小数点丢失会直接影响题意；额外统计逐题数字序列完全一致率。
- 公式：逐个人工确认LaTeX语义/结构，独立统计公式正确率；LaTeX简单字面相等只作为自动代理指标，不能取代图像校对。
- 题目切分/版面：题号漏检、多栏串行错序、选项缺失、图形连接错误。
- 额外内容/幻觉：输出相对于人工原稿的插入、无来源补写、对不可见部分“猜答案”，要独立统计并分类。
- 吞吐和成本：每页端到端时延、峰值显存、失败/重试、硬件与API成本。
- **不能把“字数识别率96%”当产品可用度；错一个分母、负号、题目条件就可能使该题不可用。**

统一计分程序 `scripts/evaluate_ocr_engines.py` 接受经人工审核的JSONL参考稿和不同OCR引擎的JSONL输出；通过原始样本ID匹配后生成每引擎整体/按类别CER、数字完全一致率、公式字面匹配代理、关键符号召回、假添加比例代理、耗时及最差样本。未标人工核对的参考稿必须在统计中注明；各模型有效样本数不一致时禁止直接判胜。与原版复核/商业使用许可是独立状态。

## 预备选择（不是最终冠军）

1. **清晰中文、简单试卷**：先尝试PP-OCRv6-medium，成本低、部署简单、保留文字区域坐标。
2. **整页复杂试卷**：PaddleOCR-VL-1.6优先进入AB试验；MinerU2.5-Pro/GLM-OCR当备选。对整页题目、表格、公式按不同能力单独验证。
3. **公式**：Pix2Text或PP-FormulaNet_plus-M，必要时再用专门的数学API做错误样本对照。
4. **难题与冲突**：由ChatGPT/其他大型多模态模型在独立图像上二次核对，**只指明哪一字/公式与图像不符**，绝不根据常识改原卷；必须由原画面及审核结果定稿。
5. **最终资产**：原图/视频、精确帧时间点、OCR文字、可溯源题目块、审核状态、真实来源字段分开；不把从第三方图片中提取的文字直接宣称拥有商业转载权。

## 2026-10-31 本机两引擎同图A/B实测（更新）

鉴于初步比较出现错误，实际在Z890私有隔离Python3.12环境安装 [RapidOCR 3.10.0](https://rapidai.github.io/RapidOCRDocs/main/install_usage/rapidocr/install/) + ONNX Runtime 1.31.1，CPU使用其默认 **PP-OCRv6 small** 文字检测/识别模型；与原有本地Qwen3-VL 8B（Ollama，RTX 5070 Ti）对照同4张自制中文数学图片。RapidOCR运行环境和权重均在项目 private/ 下，**不修改系统Python、原商城或生产GPU服务**。完整人写参考文本和两引擎逐页输出仅存在本机私有 `private/ocr-benchmark-20261031`，Git只保存汇总指标和由自己绘制的4图哈希，不外传原图。

4张图分别是：清晰中文数学、带负号/平方/根号/小数的算式、几何文字/选项/不等号、模拟低清屏幕截图。此处的“人工标注参考答案”是制作图像时使用的原始文字，并不是AI互判结果。

| 指标 | RapidOCR 3.10 PP-OCRv6 small / CPU | Qwen3-VL 8B / Ollama GPU |
|---|---:|---:|
| 同一4张样图全部返回 | 4/4 | 4/4（但低清图内容不完整） |
| **数学记法规范化字符错误率**（越低越好） | **0.00%** | **10.05%** |
| 规范化后题目数字序列完全一致 | **4/4** | **3/4** |
| 单张本机识别调用耗时（有实际计时记录的样本） | 0.67–1.23秒，4条 | 8.61–13.84秒，3条 |
| 原始字面CER（**不适合直接用来排名**） | 5.94% | 37.44% |
| 重要风险/误差 | 一些全角括号变为半角 | 低清图第二题中途停止，遗漏后续题目；表达式转LaTeX造成字面差异 |

**不要将0%误读为真实试卷100%准确率！** 样本总数只有4，且是干净的自制练习画面。数学记法等价转换只处理确定的符号同义格式（如 `\\frac{3}{4}`、`3/4`，`\\sqrt{49}`、`√49`），保留错误的数字、负号、题意；人为认可的字面/LaTeX等价可能掩盖排版细节，正式卷需逐题对图检查。两引擎的单张耗时对比也非同硬件/冷启动/保活条件的公平吞吐实验；RapidOCR仅跑CPU文字识别，Qwen3-VL执行整图生成式转录，因此不得据此宣称10倍性能差。

**这里最有意义的发现**：对于几张标准、结构规整的中文试题，*非大模型*的OCR不但快，而且比通用小VLM更稳定地完成全文抄录。这说明首选引擎不应继续盲目设为Qwen3-VL，初步路线是**非生成式OCR提取干净文字 → 专业文档模型处理复杂公式/排版 → ChatGPT等大型视觉模型处理冲突疑难页**。

但我们目前还未对RapidOCR与PaddleOCR-VL-1.6或当前ChatGPT做真实中小学卷的三方测评，更没覆盖自有真实截图中的竖排、几何图、手写、视频移动画面；生产引擎选型应依照200页分层试验作决策。

**可复现性**：`scripts/create_synthetic_ocr_eval.py` 生成同样的自制图与gold JSONL；`scripts/evaluate_ocr_engines.py` 支持原始字面CER与有限LaTeX等价规范化CER；`scripts/export_ocr_synthetic_ab.py` 从Z890私有实测账本导出脱敏数据 `data/discovery/ocr-synthetic-ab-20261031.json`；`scripts/test_evaluate_ocr_engines.py` 与 `scripts/test_ocr_synthetic_ab.py` 验证异常值、来源指针、数学符号及非公开字节未进入仓库。
