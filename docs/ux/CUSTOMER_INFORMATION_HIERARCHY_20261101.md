# SOCTHINK 客户信息层级与页面文案约束（2026-11-01）

## 核心目标
客户一眼看明白：**这是什么 → 有什么 → 花多少钱 → 怎么用**。技术可以复杂，页面只呈现当前决策需要的信息。不能用删掉关键证据或功能来冒充简洁。

## 页面优先级
- 首页：一个主要搜索、已开放服务、七个考试类别。取消重复分类栏；详细目录可手动展开。
- 考试目录：已开放的可点击考试先呈现，筹备中按需展开。直接访问锚点和手机菜单跳转必须显示目标分类；搜索回车无需依赖 JavaScript 才能提交。
- 资料列表：标题、年份、年级、题量、时长、可用链接。专题背景资料与授权解释下沉，合法性边界不删除。
- 商品列表与详情：真实样张、文件名、格式、题量、最终价格、支付状态及主要操作醒目。先看货，再看付款指引；数字商品政策入口保持可见。
- 测评中心：首屏先选量表/练习。测量目标、时长、题量、免费结果与完整版售卖状态可见；信效度、常模和适用边界需要明确可查，不得包装为诊断。
- 职业产品：已完成教程与模拟考试优先；岗位研究、来源与技能候选在下一层。手机先展示两项直达操作，避免重复大块引导卡。
- 考试答题与报告：题干、输入框、提交、成绩和解题证据优先，不能为了紧凑删除题目素材、纠错、回退和帮助。

## 文案和排版
- 标题只表达用户任务，不反复说明平台建设过程或内部术语。
- 一个功能只出现一次主要入口；必要的解释放在次级位置，避免大段宣传句挤占结果区域。
- 重要文字和操作建议从16px起；商品标题至少20px、价格约28px以上；辅助信息可以小，但不能替代核心内容。
- 电脑和手机均要防止水平溢出，手机优先真实触控按钮，不是单纯缩小桌面版。
- 数量来自真实数据，不能拿考试方向冒充已上架产品。
- 购买政策、真实支付状态、交付与售后、来源和适用边界不能为了省字被删除。
- SEO/GEO 的结构化内容、元数据和完整说明留在专门页面或可展开区域，首页首屏不能堆砌关键词。

## 验收
1. 独立生产构建、TypeScript、相关现有业务测试通过。
2. 浏览器实际点进首页、考试、资料、商城、购买、测评和职业训练。
3. 390 / 768 / 1440px 检查视觉层级与水平溢出。
4. 手机菜单、筛选、锚点、登录、支付说明、商品样张及下载入口可达。
5. 真实收款和用户数据不得被视觉改造影响；未付款不得显示成功交付。
6. GitHub main 与生产 SHA 一致才可宣称正式上线；遇 CI 阻塞先查根因，不为了过时文案断言恢复旧版废话。

这份文档是简明设计准则，不增加额外发布门禁或重复审批。
