# Native 二维码支付截止时间：服务端、网页与订单一致（2026-10-31）

## 问题

项目在 `POST /api/payments/wechat/checkout` 使用
`time_expire = now + 30min`，但此前把生成的二维码一直留在页面，
依赖每 3 秒查单后出现 `paid/closed` 才消失。
订单支付期限到了，而官方主动关单仍可能在 35 分钟以后确认，
这中间浏览器显示一张**已经不适宜使用**的收款二维码。
用户可能误以为还能付款，形成投诉和重复支付风险。

[微信 Native 开发指引](https://pay.wechatpay.cn/doc/v3/merchant/4012791891)
说 `code_url` 本身的最长有效期可达到 2 小时；
但该站订单**自己指定了更早的 30 分钟截止时间**，
因此以**订单自己的更早截止时间**为准，而不是把二维码固定展示 2 小时。

## 整改

- `src/lib/native-qr-expiry.ts`：服务端基于同一
  `time_expire` 计算剩余秒数；在生成和发送二维码前再读取服务端时钟，
  预留 5 秒缓冲，避免过期数据被发送。仅返回 TTL，不依赖设备绝对时钟。
- `NativeCheckoutPanel`：客户端用单调时钟 `performance.now()`
  和服务端返回的 TTL 计算展示期限。用户切换窗口/标签后立即复核，
  原有 3 秒交易状态核查仍进行；超过截止时间自动隐藏二维码，
  但**继续核对同一个原订单**，不假设已关闭或已退款。
- 未收到可信 TTL 或它越界时不显示二维码；
  网页明确提示「等官方确认原订单状态，勿重复付款」。
- 已付款时展示「已购内容」，不再错把单份考试/资料称为会员升级。
- 客户端不能通过改变本机系统时间让二维码延长展示，
  也无法通过向后端提交 TTL 覆盖官方订单截止时间。
- 使用 `scripts/test_native_qr_expiry.ts` 离线模拟到期、边界时钟、
  客户端单调时钟；质量 CI 中直接执行。无真实下单、无商户秘钥。

## 仍需真实资金验收

这只是避免**过期码在前端误展示**，不等于新站已能收款。
生产账本、商户受控配置、合法商品、微信官方查单/退款及正式收款验收
仍按 `ops/payment/PRODUCTION_ACTIVATION.md` 的单账本主链路处理。
