# SOC THINK：一个微信账号，购买考试和资料（2026-10-30）

本文件取代面向用户的“家长→添加孩子→学生 PIN→做考试→家庭席位”流程，
适用于全年龄、全考试种类，不应只按 K12 数学定义用户。

## 正式用户流程（唯一）

微信扫码／微信内授权 → 自动识别**一个微信账号** →
浏览考试、测评、数字资料 → 免费直接使用，付费先显示**真实单价与交付** →
微信付款 → 只有官方签名查单与同一账本结算成功后开放已购服务 →
“我的账号”查看订单、使用记录、有效期／退款。

**账号身份只认经过微信授权验证的业务 account ID**；不能从请求头中的
UID、手机号、个人资料或客户端“VIP/paid”标志直接授权。
一个账号可以自己学习、替别人购买或使用考试，前台不要求提供家长/孩子关系。
内容版权、年龄与数字商品平台经营规则仍分别适用。

## 本次已实现

- `/login` **仅展示微信登录**，使用原有正式微信 OAuth/官方 QR 组件、
  签名回调与 HttpOnly 会话；桌面扫码、微信内授权共用一个网站账户。
  首次授权自动注册；不再展示家长/学生/邮箱注册选项。
- `/account` 是唯一公开账号中心：已购订单、当前已验证权益、选择考试资料、
  退出登录；`/parent` 和旧家长登录页面仅重定向，不再展示孩子 CRUD。
- 网站顶部只显示“微信登录／我的账号”，不显示切换孩子、家庭管理。
- 免费用户保留原样题，正式考试使用**签名微信登录身份**，不再要求第二次学生 PIN。
  `guest_family_{HMAC}` 作为历史学习记录内部 ID **不变**；原先未验证的游客 token
  仍禁止正式考试；管理员与小程序 Bearer 身份保持隔离。
- 正式购买与订单轮询始终基于同一个微信账号对应的 server-side ID；
  旧数据库列 `payer_parent_id` 暂只作内部兼容别名，绝非第二账号。
- PLUS/PRO 家庭席位从公开权益模型删除，不能再营销不存在的 3/5 个学生席位。
  以前账号和考试记录暂不销毁；旧 family 表/接口停止作为购买主流程。
- `scripts/test_single_wechat_buyer.ts` 校验同一微信账号稳定的考试身份、
  不同微信隔离、游客拒绝完整试卷、公开权益无家庭席位等。

## 尚未达到的真实付费条件

- 当前 `billing_products` 仍是 PLUS/PRO 时间制模型，**尚无真实、可售的
  “单张试卷／单份资料”SKU 及商品交付授权**。下一次应以订单所属
  `product_id` 为唯一购买依据，为试卷或资料建立服务器授权检查；不要再
  从“家庭席位”“学生数”推导购买权限。
- 正式生产账本、实际微信商户密钥配置、单实例官方查单补偿 worker、
  完整官方退款和真实资金到账验收仍缺，生产收款开关不得提前打开。
- **微信跨应用身份**：网页网站授权与微信小程序的 OpenID 不可直接相等。
  若需要网站与小程序同一购买身份，必须由同一开放平台体系下微信官方返回的
  UnionID（若实际提供）核实绑定；当前小程序关联在商户平台显示“已失效”，
  因此本次并不宣称跨 AppID 订单已打通，也不得凭昵称/头像自动合并账号。
- 历史学生数据保留，不能擅自删库或一次性把旧学生记录归给付款人；
  后续仅通过授权迁移再决定旧账号的成绩如何展示在“我的记录”中。

## 工程验收

1. 未登录可以看免费样题；不可以读取受限正式卷／他人账单。
2. 微信扫码/微信内 OAuth 成功后，**无需添加孩子/PIN** 即可进入正式卷；
   答题、提交、阅卷、报告与同一稳定账号 ID 对应。
3. 同一微信跨登录会话恢复原训练历史，不会产生第二个孩子账号；
   换微信访问不到他人的成绩、订单或付费资料。
4. 真金白银订单：商品价格及有效期显示→付款→官方查单成功→权限打开；
   退款最终成功后权限撤销但保留历史考试记录。
5. 真实手机版购买与扫码付款路径分别在对应官方渠道完成验收，
   不能拿一次本地 CI 模拟代替生产钱款/交付回执。
