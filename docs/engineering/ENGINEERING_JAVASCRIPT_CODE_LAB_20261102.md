# SOCTHINK｜软件工程师JavaScript实操第一批正式蓝图与验收

**研发日期：2026-11-02**。归属：中国国内职业与工程能力测评 #238。产品：`/skill-labs/code-lab`；独立于心理/人格测评，和SQL实验室平行。

## 真实产品范围

- 共6项原创软件工程工作样例，每项4组明确预制输入，合计24组真正执行结果：
  1. 已付订单ID去重与数值排序（数据正确性）。
  2. 付款/退款状态金额统计（支付口径）。
  3. 指数退避及上限（可靠性）。
  4. 历史测试结果中检测间歇性失败（质量保障）。
  5. 按服务汇总ERROR级生产日志（可观测性）。
  6. 库存增量事件归并、负数及零值保留（事件处理）。
- 用户直接编写JavaScript函数并运行，而非四选一或由AI主观评价。
- 每题有接口签名、业务要求、可见样例、代码编辑框、按需提示、真实运行回执、逐项错误反馈、进入下一题、练习完成报告。
- 精确得分：每个任务4组输入全部通过才标记“完成”。尝试次数与通过状态仅保存在当前页面内存。刷新不恢复；代码不向服务器上传。
- 仅适合**免费编程学习/岗位准备**，不具备实名监考、重复次数防作弊、心理效度研究、企业标准录取评价、职业资格证书能力。
- 所有题目与完整判题用例位于浏览器可得到的应用资源/仓库内，**不是保密测试集**；对真实招聘需要另建企业级服务端出题与审计，不能在当前页面冠以“企业认证”“独立隐藏试题”。

## 实际执行系统与安全边界

官方技术文档参考：QuickJS WASM https://github.com/justjake/quickjs-emscripten 及 https://www.npmjs.com/package/quickjs-emscripten 。版本精确锁定为 `quickjs-emscripten@0.32.0`，由 `package-lock.json` 记录完整依赖树。

运行链路：

1. React页面 `CodeLabClient` 通过 `new Worker(new URL(...))` 创建独立Worker，**用户源码不经API，不发送服务器**。
2. Worker `src/workers/code-lab.worker.ts` 初始化 `getQuickJS()`，传递题号、源码给 `gradeCodeWithQuickJS`。
3. QuickJS WASM 新建runtime、设置内存上限16MiB、最大栈256KiB、每组调用时限850ms并注册中断处理器。
4. 每个测试用例使用新的QuickJS context，候选函数没有任何浏览器DOM、网络、Node或应用账号接口，QuickJS不开启模块加载器。
5. 每题四组输入将真实返回值解析为JSON并以稳定键顺序比较结构；对错误、返回值不可序列化、非法代码、超时都有明确反馈。
6. Worker外部另设12秒硬终止，发生死循环、初始化错误、未知Worker异常时不阻塞全站页面；用户可编辑后再运行。

**边界**：WebAssembly解释器资源耗尽和浏览器本身安全模型仍要防御性对待。此运行时不是可运行系统命令、访问文件、联网或执行Python的通用IDE；不能开放任意npm依赖或赋予服务器凭据。

## 验收合同

- 静态题库：6个独立任务ID，24组测试，4组/题，版本 `code-lab-original-20261102-v1`。
- 单元测试：`scripts/test_code_lab.ts` 使用真实QuickJS WASM执行六份测试专用参考解，24/24通过；原始starter全部不得意外满分；错误结果应拒绝；死循环须被中断；网络/浏览器/Node相关全局变量必须不存在；5000字符上限、未知任务拒绝。
- Playwright：`tests/e2e/engineering-code-lab.spec.ts` 在桌面和手机上完整跑6项真实Worker/WASM代码并生成报告；错误代码不解锁下一题；尝试访问网络失败；从职业服务页和技能主页可以进入唯一正式入口；不出现水平滚动。
- 合并及生产验证：沿用受保护主分支PR→GitHub正式质量与浏览器CI→CI绿色才合并→`socthink-auto-deploy.service`不可变运行制品+自动回退→公网发布SHA与真实浏览器6项可执行验证。
- 与其他业务边界：不更改SQL的3组数据与8任务、不更改40题招聘原始评分、不更改职业岗位24题正式模拟的签名会话、不介入微信支付和权益报告。
- 浏览器用户可完全看到交付结果，不得声称“来自真实招聘公司面试题库”或“国内常模”。此产品评测的是给定例题集合上的代码正确性，而非一般工程师潜力。

## 2026-11-02：编程工作区视觉与空间改造

针对用户对代码编辑器过小、不像真实工作台的反馈，**仅修改展示与交互，不改QuickJS沙箱、题库、计分、支付或登录**。

- 正式路由单独放宽到1760px容器上限，不影响站内其他内容页的1440px布局。
- 进入实操后压缩介绍区域，让编辑框靠近第一屏；工作区桌面为主编辑区＋参考样例侧栏，宽度低于1200px时改为上下排列。
- 编辑器保持真实可编辑的textarea（不是冒充VS Code/终端），增加深色文件栏、可切换“扩大编辑区”、实时源码长度状态、格式清晰的深色**实际执行结果**。输入/预期样例保持可见，其他运行细节收进可展开区。扩大模式只调整布局，不丢失源码或评分状态。
- 输入交互：保留键盘、可访问的编辑器label与textarea焦点，用户自行调整编辑器高度；手机使用16px字距避免输入聚焦缩放。
- 基线公网Chromium 1920px：编辑区926×280px，首个编辑框顶部约611px；优化后的候选版1920px：1225×549px，顶部约495px；1024px基线629×280px，候选版923×549px、顶部约478px。数值取自实际浏览器布局测量，不是设计稿估算。
- 新增 Playwright 桌面/手机用例验证编辑框尺寸、不同视口无溢出、扩大/退出按钮真实工作、源码保留与执行结果；既有6项真实实操、SQL、职业考试及付费报告同时回归。
- 生产发布仍需正式CI全部通过、原子部署自动回退和公网浏览器复测。
