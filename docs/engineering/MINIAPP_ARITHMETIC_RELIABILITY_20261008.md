# 小程序计算训练可靠性与成绩幂等性（2026-10-08）

## 问题

微信小程序计算训练原先直接在「完成本轮」调用 `POST /api/miniapp/arithmetic/session` 的 `finish` 动作。服务端每次都向 `private/arithmetic/sessions.jsonl` 追加一条记录。同一用户因按钮连点、网络超时重试或两台终端同时请求，都可能产生重复训练记录，污染累计轮次、正确率及后续能力画像。

原有复盘页若 `GET /api/miniapp/review` 失败，只弹 Toast 然后一直显示加载中，没有“重试”与“返回”路径。

## 本次修复

1. **后端为准，幂等保存**：训练 ticket 映射为确定的训练 ID，使用共享私有数据目录下的原子文件夹锁序列化保存；已有同一 ID 的训练记录返回原成绩和同一时间快照的计划，不重新写入。不同答案重试被拒绝，不能篡改历史。
2. **失效进程恢复**：写入进程异常退出导致的孤立锁在超过 10 分钟后允许恢复，未过期的锁禁止并发覆盖。依赖各服务进程使用同一规范会话数据目录；跨物理节点的强一致性还需共享存储/事务存储来保障。
3. **会话唯一性**：训练 seed 使用安全随机数，而不再从毫秒时间推导，避免同一学生两台设备同毫秒启动相同年级/模式意外共享 ticket。
4. **前端同步防连点**：通过 `useRef` 锁阻止 React 重绘前的两次按钮触发；执行期间显示加载状态并禁用输入、提交、下一题和开始按钮。答题成功后冻结输入；网络失败允许保留原题、原答案和原提交请求重新尝试。
5. **复盘恢复**：显式区分复盘加载中、失败、成功；失败时展示信息、“重新加载复盘”和“返回竞赛”，避免永久转圈。

## 自动测试

`npm run test:miniapp-arithmetic-idempotency` 使用 OS 临时目录隔离私有用户/成绩存储，验证：
- 重复提交返回完全相同的成绩和计划，数据库文件仅追加一次。
- 同 ticket 篡改答案与越权 student 被拒绝。
- 并发保存锁阻止写入；超过 10 分钟的孤立锁允许安全恢复。
- 同一毫秒重复启动产生不同 ticket。
- 源码中同步按钮锁、答题提交禁用态与复盘重试入口存在。

该测试纳入公开质量门禁和小程序构建门禁，同时执行已有 API roundtrip 与 Taro 8 页 TypeScript/编译检查。

**证据边界**：源码测试、独立构建和官方微信预览不等于真实微信 GUI E2E。三星 S8 当前前台是闲鱼，未强行切换；尚无 Windows/macOS 微信开发者工具。G3/G4 仍为 BLOCKED，需用微信体验码在真实设备执行开始→答题→交卷→复盘和断网恢复后才可签发 QA 回执。

## 进一步风险

目前成绩文件仍是 JSONL。原子目录锁只对**共享同一底层存储**的进程有效；如果未来多个服务器独立存放学生成绩，必须迁移到有唯一索引和事务约束的 PostgreSQL 存储，才能证明跨节点 Exactly-Once。当前不能以“单机幂等”替代“多节点一致性”证明。
