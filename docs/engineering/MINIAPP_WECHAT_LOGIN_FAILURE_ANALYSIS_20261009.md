# 2026-10-09 小程序真实微信登录失败诊断

## 已确认事实

生产 nginx 日志在 10 月 9 日 11:50–12:00 期间记录 18 次 POST /api/auth/miniapp/wechat 全部 HTTP 401，User-Agent 类型为 MicroMessenger（仅按用户代理聚合，不识别具体用户）。这些客户端请求到达服务端，因此不能再将这批登录失败统一归因为小程序端 request 域名阻断。

旧接口遇到微信 jscode2session 返回 errcode 时一律给 HTTP 401，但没有服务器端记录 errcode，无法确认具体根因。目前不能断言是 AppSecret 错、code 无效、code 重复使用还是微信端服务异常。

## 本 PR 的最小可观测性补丁

- 服务端只记录 event、微信数字 errcode、映射后的有限 reason 字段。严禁记录 code、AppID、AppSecret、OpenID、session_key、上游 errmsg、任何含隐私的请求 URL。
- 40029/40163：一次性凭证可能无效，401。
- 40125/40001/40013：微信配置需要检查，503。
- 40164：IP 白名单不允许，503。
- 45011：过频，429；-1：繁忙，503；其他：通用 502。
- 客户端仍只获得通用、可读中文错误和机器安全原因；不返回密钥或 OpenID。
- 测试使用 mocked fetch，检查 7 组失败与 2 种上游异常，并断言任何敏感数据均不得出现在后端日志。
- 这是一项**Web 后端**诊断修复，不改变小程序 UI，不上传小程序正式版。待 CI 通过后可单独部署后端，依靠后续真实微信请求得到数字 errcode，再查原因并实施针对性修复。

## 尚待验收

未有真实合法 wx.login code 可以主动在服务器上重放，因为 code 必须由微信客户端刚获取且单次使用。禁止写入日志或复用截获 code。小程序完整登录→计算→竞赛端到端验收仍然 BLOCKED。
