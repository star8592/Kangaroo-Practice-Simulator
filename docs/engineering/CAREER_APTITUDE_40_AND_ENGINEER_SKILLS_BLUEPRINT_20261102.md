## 1. 本轮已实现的产品（已编写，不等于正式环境已上线）

- 名称：招聘通用能力 · 40题。
- 正式源文件：src/lib/career-aptitude-bank.ts；页面：/assessment-center/career-aptitude-40。
- 五类能力各8题：言语理解、数量运算、逻辑推理、资料分析、二维空间/方位。
- 40道全部原创，固定选项和题目解释；出题日期2026-11-02；正确选项分布每个字母各10题。
- 本卷规则：45分钟、本地计时，未答0分，完整答卷可跳题与标记，末题或主动提出后先检查再交卷，到时自动交卷。
- 分数：正确题数 / 40，以及五类正确题数 / 8、逐题复盘；不生成百分位、IQ、CATA分数、某企业通过率或职业胜任力证书。
- 当前会话安全属性：本浏览器标签页 sessionStorage 暂存答案和截止时间；刷新继续，关闭标签页或切换设备不保证恢复；没有服务端会话、签名成绩、AI监考或防作弊能力。
- 当前使用范围：免费个人练习和备考。不开放企业招聘考核，不以此直接评价人事任用、录取或劳动权益。
- 视觉：复用已上线的 SOCTHINK 蓝色设计体系和测评组件，窄屏题干优先、答题卡默认折叠。
- 职业服务页提供真实链接，另外直连已有的 SQL 实操。用户看不到未建成的工程师产品入口。

## 3. 工程师实操产品线：不把概念题冒充职业能力

国家职业标准来源：https://osta.mohrss.gov.cn/skillStandard
国家专业技术人才更新项目：https://zsgx.mohrss.gov.cn/
国家职业标准是职业画像和技能范围的依据；本站不得因此声称职业资格认定资质。

### 3.1 数据/SQL工程师（已有真实可用基础）

现有入口 /skill-labs/sql-lab，当前4项实际SQLite工作任务，经系统测试可以执行查询、返回结果与评分；是“技能练习”，不是全国统一资格认证。
后续开发真实项目式任务，不以“会背SELECT”替代专业能力：
- 数据预处理：给出重复订单、退款、漏值的模拟数据，定义去重、空值以及核对规则。
- 多表关联：订单、商家和付款状态分离表；区分LEFT JOIN失配与行数膨胀。
- 指标口径：明确收入、退款、毛利与分母，独立校验聚合口径。
- 质量验收：同一SQL针对已知输入、边界输入和新版本输入运行；给出行数、字段、数值差异证据。
- 沙箱必须只读或受限、限制CPU/内存/时间，不允许读取生产数据或网络。

建议评分协议：60%可复现查询结果、20%边界与异常用例、10%稳定性/约束、10%解释与复盘。以上为未来设计草案，未接入当前SQL评分，不得声称已上架。

### 3.2 软件工程师（下一批建设）

岗位分支分别建档：后端Java/Python、前端、测试工程、算法、平台/SRE。首批不要一套卷混用所有岗位。
- Java/Python：基础类型、异常处理、集合、接口、可测试性，代码编辑/执行与隐藏用例。
- 测试工程：需求理解、测试边界、等价类、日志、复现脚本与失效分类。
- 平台/SRE：日志与告警归因、网络排障、配置安全、回退、自动化恢复；只能在隔离沙箱运行故障恢复练习。
- AI应用工程：提示词和模型接口只是其中一部分；还应有证据评估、RAG检索质量、数据安全、失败回退、成本限制。
- 以真实任务完成情况和修复证据为结论，不用模型凭印象宣称“工程师能力95分”。

### 3.3 电气/嵌入式/机械（领域专家审核后启动）

电气/嵌入式需要真实原创电路图、故障条件、测量与仿真；机械/质量需要工程图、公差、工艺与FMEA案例。必须由专业人员核对答案与图纸，不能用通用语言模型一次性生成并直接公开评分。

## 4. 数据契约及后续工程工作

在公开发行前保持“一条正式实现路径”的工程原则：
1. examBlueprint：岗位、测量维度、题型、题数、用时、版本、来源、受测者边界。
2. itemBank：题目ID、原创权属、独立答案复核、解析、版本、难度、反馈和撤回记录。
3. assessmentRun：分阶段签名会话、可靠保存/恢复、时限、空题、审核状态。
4. deterministicScorer：机械可复算的答案与代码/SQL测试结果，LLM建议仅作可解释辅助。
5. reportEntitlement：免费原始成绩/逐题复盘与真实已开放的详细付费报告权限分离，不伪造支付成功。
6. 质量观测：题目争议率、放弃率、单题耗时分布、答题准确率分布与样本覆盖、付费转化；不从少量自选样本推出常模。

本轮自动验收：
- 单元测试：40题、5维各8题、答案位置均衡、40个独立核对的正确答案、满分/零分/空白/无效输入。
- 浏览器：考前知情、跳题、标记、刷新后恢复、空白扣分、完整40题、超时自动交卷、桌面/手机响应和收费边界回归。
- 正式发布要求：GitHub PR、完整平台测试、不可变制品、自动回退、公网登录/作答/报告实测，以及生产提交SHA核对。

未来若切换为付费细报，必须先形成真实交付内容和服务端权益验证，不能将无常模的结果包装成官方资格证书或企业录用预测。
