# 微信小程序支付：智量巧算与商户配置隔离

审计日期：2026-10-08。当前收费状态：未启用。会员目录仍是 preview；任何收费按钮不得开放。

## 已核查的事实

- 本小程序及服务器的 AppID 是同一小程序；本次提供的 WECHAT_PAY_APPID 属于不同的公众平台应用，不能直接用于本小程序下单。微信支付商户平台需要单独绑定本小程序 AppID。
- 现有 PAYMENT_PROVIDER=wechat_native 对应扫码支付，不能直接在微信小程序内使用。普通小程序支付使用 JSAPI 下单和 requestPayment，但会员/AI题解属数字商品，必须先核实本账号是否应接入公众平台的“虚拟支付”能力及其资质要求；不得用其它支付方式规避相关规则。
- 本次提供的另一项目 PEM 路径在 Z890 主机存在：商户证书、私钥、公钥有效且证书序列号与商户配置一致、商户证书与私钥匹配。但**生产服务器尚未部署**这组密钥，不能将本地路径直接粘贴为生产环境路径。
- 现有 WECHAT_PAY_NOTIFY_URL 指向另一应用的订阅回调。它的 POST 请求返回 401；不得复用。预定独立新地址是 https://socthink.cn/api/payments/wechat/notify ，**目前没有该项目的真实回调处理器，不能注册使用**。
- 微信支付 API v3 key 曾在聊天中明文分享，应在正式上线前通过商户平台轮换；密钥不得写入 GitHub、日志、小程序代码或 Web 前端。
- 当前数学项目有交易账本 schema 和内部结算原语，但是没有生产账本数据库、正式验签/查单/退款支付适配器，也没有微信小程序收费 UI。不能声明已完成收费。

## 只读检查

在未来实际运行支付服务的主机以其真实安全环境运行：

    node scripts/check_wechat_pay_readiness.mjs

在开发机器测试逻辑：

    node scripts/test_wechat_pay_readiness.mjs

只读预检查仅验证配置、文件格式与防错，不向微信发出收款请求，不显示密钥值；检查通过也不等于微信支付商户账号权限已获准。

## 逐项验收

1. 商户平台“产品中心→APPID授权管理”确认该商户号授权了“智量巧算”小程序 AppID；公众平台确认授权申请。支付产品的开通状态也须核实。
2. 在“支付与交易→虚拟支付”确认该小程序目前可申请的服务类型、开通状态、商品/套餐配置、OfferID、AppKey、回调/签名协议；以官方后台实际开放的产品为准。
3. 为本项目建立独立的生产账本 Postgres、证书和密钥存储；完成不影响现有业务的证书复制与密钥轮换。
4. 开发独立回调：严格验证平台公钥签名、timestamp/nonce、防重放、AES-GCM解密；向平台独立查单，并核对商户号、小程序 AppID、订单、金额、币种、支付状态，确保重复通知不会重复发放权益。
5. 覆盖取消支付、超时、重复订单、退款、补单、家长账号权限和学生授权、Web/小程序跨端权益一致性和账本恢复；通过模拟测试/实机灰度后再启用收费开关。
