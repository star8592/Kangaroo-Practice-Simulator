# SOC THINK｜中国职业与工程师能力测评市场研究及产品蓝图

调研日：2026-11-02。主战场：中国国内。上位工作项：GitHub Issue #238。
定位：求职者/学生的备考与能力成长；招聘机构的岗位训练与评价工具是可选的后续服务。不能向客户展示虚构的录取预测、官方认证或心理学常模。

## 结论

国内不应只做 MBTI/人格：真实市场可拆成职业兴趣/性格、通用认知能力、职业情境判断、行业岗位专业知识、工程师工作样例与可执行实操。最有差异化的不是重复贴更多性格问卷，而是针对中国真实招聘中的工程师与岗位实操构建可验证的测评项目。

“正在销售/企业提供”和“用户真的愿意为本平台付费”是两种不同证据。以下优先级根据官方供给、已有技术基础与可落地性提出，是产品研究判断，不是声称已经测得搜索量、销量或转化率。

## 中国用户导向的产品树（内部规划，未建成不得上架）

| 一级 | 子项 | 用户想解决的问题 | 产品路线 |
|---|---|---|---|
| 职业方向 | RIASEC兴趣、大五、职业价值观、工作风格 | 我更愿意做什么，如何探索岗位 | P0：保留现有自编RIASEC30、IPIP50研究预览；价值观/工作风格需原始量表或自编审校 |
| 通用招聘能力 | 言语、数字、逻辑、资料分析、图形空间 | 校招/社招常见通用能力题如何准备 | P0：独立完整试卷 + 分技能训练 + 可核对逐题解析 |
| 逻辑推理 | 条件推理、三段论、论证评价、表格推理、图形规律 | 逻辑思维与推理速度具体哪里薄弱 | P0：独立题库、时间约束、正确率与稳定性复盘，不输出IQ |
| 软件工程师 | Java/C++/Python/前端、算法、系统设计、测试 | 能否实现、修复或解释真实代码 | P0：选择与编码混合；沙箱实跑、隐含测试与复杂度解释 |
| 数据与AI工程师 | SQL、数据清洗、Python、统计、AI工作流 | 能否完成完整数据/AI工程任务 | P0：复用SQL实验室，加入数据集案例、输出校验与日志证据 |
| 运维/网络/安全 | Linux、故障定位、网络协议、服务恢复 | 能否定位生产异常并安全修复 | P0/P1：隔离容器/模拟日志，验证真实命令与结果 |
| 电气/嵌入式/硬件 | 电路、测量、MCU/FPGA、调试、信号处理 | 能否读图、计算、定位电子系统问题 | P1：原创电路图、仿真与自动判定；不直接操作危险设备 |
| 机械/制造/质量 | 工程图、公差、工艺、FMEA/SPC | 能否阅读图纸并分析制造质量问题 | P1：在现有工业质量24题基础上独立构建项目任务 |
| 产品/运营/供应链/金融 | 数据分析、业务场景、采购决策、风险识别 | 能否解决岗位业务问题 | P1：复用现有商品运营和采购24题，逐步扩充职业场景 |
| 管理与职场能力 | 情境判断SJT、沟通、协作、冲突与计划 | 面对具体工作情境怎样作出合理选择 | P1：场景与答案经过多专家评分审查，非“性格判断=能力高低” |
| 央国企/编考 | 职业能力、资料分析、言语、判断、职业素养 | 针对当前招录规则备考 | P1：每类官方公告与最新版次独立建档，不能假定统一模板 |
| 职业压力与心理状态 | 工作压力、满意度及专业筛查 | 自我观察与需要进一步支持的信号 | P2：先做授权、资质及伦理审核，不提供在线医疗诊断 |

不要将“工程师测试”做成只有概念性选择题的空壳，也不要把职业资格考试与招聘能力摸底混为一谈。

## 首批建议开发蓝图

### A. 通用认知正式模拟卷
- 研究假设：5个维度，每维度约8题，合计40题；预计40–60分钟作为初始可测版本。**这是本站拟议卷面，不是北森或某企业官方设置**，需结合实际用户完成情况修订。
- 题型：言语证据判断、数量/数据运算、形式逻辑、图形/空间、资料分析。
- 报告：维度答对数量、用时、错题类型、可复现正确答案与训练建议。没有足够常模证据只给卷面表现，不能写“超过全国XX%的人”。
- 专业验证：原创题目二次解答、图形矢量可读性、答案唯一性、难度与区分度、重复性分析；公平性和可访问性审查。

### B. 软件/数据工程师能力正式实测
- 不固定单一题数。以实际岗位任务蓝图确定：知识题 + 编程/SQL/故障诊断 + 结果复核。可借鉴牛客指南中的混合题型，但不复制其受限题目。
- 能力模型：基本功、工程实现、调试与测试、性能与可靠性、结果解释与证据。
- 评分：自动化用例、输出校验、SQL结果对账、静态/安全检查及限定人工审查。LLM可以生成评分建议但不可替代真实执行回执。
- 报告：已证实能完成什么、哪些错误阻碍工作、如何练习。禁止把一次测验推算为“可拿某公司offer”的概率。
- 安全：代码/SQL仅在隔离沙箱运行，无生产凭据、不可访问真实用户资料与内网。

### C. 电气和机械工程师
- 初期先分别制定技能矩阵与20–30个真实工作场景，审校通过后按专业难度制定完整卷面。
- 电气：图纸与元件、计算、保护与信号诊断；机械：图纸、材料与公差、工艺、质量分析。
- 不套用软件工程师考试模板；图示、计算和参数必须经过专业审查与独立复算。

## 产品与交易规则

- 第一级导航建议使用整齐短名称：职业方向｜通用能力｜逻辑推理｜软件技术｜电气机械｜业务岗位｜管理沟通。具体入口只展示真实上线的项目，其他只在后台研发清单出现。
- 主页面只回答：测什么、适合谁、多少题、多久、开始。来源与方法藏在二级可展开说明，不挤占主要视觉区。
- 每套考试要有候考说明→正式作答→答题状态→检查交卷→免费基础结果；详细报告只在商品真实已上架并验证权益后收费。
- 题库与计分须具备版本、来源、许可、制作时间、审校责任及固定复现数据。职业身份、心理学验证、行业通行标准分别标注，不互相冒用。
- 不要因为资料网站出现“XX人已测/YY题”就把它当成本站真实付费需求。真实需求要以后续站内点击、开考完成率、报告购买率、退款争议与客服提问作证据。
- 保留现有大五50题、职业兴趣30题、推理20题、阅读16题、3套24题岗位模拟、SQL实训，不删除真实有效功能。原6题热身卷已废弃，不重新上架。

## 工程实施和维护

数据链路建议为：
- marketEvidence：市场线索、原始链接、查阅日期、来源级别与可复制限制。
- examBlueprint：岗位、能力维度、题型、建议时间、参考原始考试规则版本。
- itemBank：原创题、标签、难度、答案、解析、独立复核与更新日期。
- assessmentRun：正式考试会话、作答与评分的证据；心理自评与技能实测分别计分。
- reportEntitlement：免费简报和经正式收费系统验证的付费报告权益。

所有新项目坚持一套正式数据流，测试通过后发布、异常自动回退。不增加无意义的人为门禁、分支兼容与重复入口。

实施顺序：完成通用认知和软件/数据工程师两套可完整使用的试测→采集真实题目质量、完成率与用户反馈→扩展电气/机械与商业岗位→建立效度、难度与常模长期研究。项目跟踪见 Issue #238。
