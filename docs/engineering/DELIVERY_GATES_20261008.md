# Socthink 数学平台工程交付门禁（2026-10-08）

适用：Kangaroo-Practice-Simulator、socthink.cn、微信小程序共享后端。

最高原则：**构建通过 ≠ 交付完成。交付必须有对应 Git SHA、用户路径和运行证据。**

## 根因与约束

游客考试权限事故的本质是：匿名 401 测试存在，但带有效签名的 guest token 仍被后端当成学生；部署只验证服务健康与 SHA，未验证业务权限。每个关键功能必须有肯定用例、拒绝用例、故障注入和浏览器/设备实际动作证据。

## 交付状态机

| 门禁 | 证据 | 失败处理 |
| --- | --- | --- |
| G0 可验收需求 | 用户路径、权限矩阵、负面分支、风险、验收条件 | 不开始实现 |
| G1 服务端合约 | 匿名/游客/正式用户/付费权限，负面测试必须确实能失败 | 阻断合并 |
| G2 构建检查 | TS / ESLint / 依赖审计 / Web + 小程序独立编译 | 阻断合并 |
| G3 Web E2E | Chromium 桌面/手机视口真实点击首页、登录、进入试卷、答题、交卷、成绩 | 阻断合并 |
| G4 生产候选 | 独立端口运行实际构建，15 个权限断言、公开目录和基础计算测试 | 禁止切换 |
| G5 生产回执 | 精确 SHA、已启动服务、线上同一权限测试 | 回滚/失败告警 |
| G6 微信设备 | 微信开发者工具点击、Android/iOS 真机登录/作答/弱网复测 | 不得宣称微信端实机通过 |

微信小程序的 Taro 编译、REST 通过和 Web 浏览器 E2E 均不能替代 G6。

## 已固化的命令

- npm run test:exam-access：单元与路由权限验证。
- npm run test:exam-access-live-contract：测试活体哨兵的成功、故意开放、SHA 不匹配三种结果。
- BASE_URL=https://socthink.cn npm run test:exam-access-live：无用户凭据的在线权限哨兵，匿名/Web guest/miniapp guest 各 5 个拒绝断言。
- E2E_ALLOW_SYNTHETIC_FIXTURE=1 npm run test:e2e:smoke：仅在隔离 checkout 运行合成用户/合成 25 题试卷，不允许生产运行；含桌面/手机真实点击、开始、答题、交卷和成绩页。
- npm run verify:public：仓库质量门禁。
- GitHub CI 增加单独的 Web browser click E2E 作业；微信独立构建仍在单独 Job。

自动部署在候选实例、切换后的本机服务分别运行活体权限哨兵。GitHub Production Receipt 在精确 SHA 匹配后再检查公网权限；每天的小程序生产 API 巡检复用相同哨兵。

## 必须保持的纪律

1. 独立 worktree / 分支 / PR，尊重现有未提交工作；不得将本地草稿直接覆盖线上。
2. 主业务动作应在真实浏览器中点击，不仅检查 HTTP 200；考试必须验证登录、开考、答题、评分和结果。
3. 身份和权限的判定由服务端进行；付费授权需通过验证的权益记录，严禁信任客户端 VIP 字段。
4. 候选失败阻断发布；已推广的实例健康或权限失败使用不可变版本回滚。
5. 汇报必须附上 commit、CI、预发布、生产回执、测试记录，清楚区分 PASS、FAIL、BLOCKED。
6. 生产环境仅允许无损、低频巡检；合成学生考试测试不得在生产启动。

## 当前明确未完成的交付

微信开发者工具 UI 自动化、两种真实手机的微信体验测试、全站按钮的穷举操作覆盖、异常与告警闭环仍不具备充分证据。这些是后续强制门禁，不允许笼统宣称“所有页面、所有设备已验收”。

GitHub 主分支保护目前要求 quality、billing-ledger、Miniapp build and API contracts。新浏览器 Job 上线并成功后应加入必需检查；更新时保留原有严格同步、禁止强推和管理员规则。人工代码审批规则为 0 人批准，是否进一步升级需兼顾单人高频开发。

浏览器关键路径 CI 不允许自动重试掩盖 flaky：第一个失败即视为红灯；必须消除竞态并重复运行验证。\n
