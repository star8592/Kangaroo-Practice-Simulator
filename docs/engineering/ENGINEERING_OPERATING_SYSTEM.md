# 全球数学赛事管家 · 工程开发、发布与运维统一标准

**状态：实施中（2026-10-10）**。仓库：star8592/Kangaroo-Practice-Simulator。本文是默认工程主流程，原有分散说明作为执行细则，不得降低这里的发布、安全和验收门禁。

## 0. 最高原则

Delivery First · Evidence-based Done · Small Batch · Fail Closed。完成以可复验的用户行为、正式 SHA、生产健康和持久化证据为准，而非模型自述。沿用已有 Next.js/Taro/Playwright/CI/不可变发布架构，不另造未经验证的新框架。Web、中国与国际赛事、计算、考试、家长、微信小程序平等纳入。

状态必须逐一标明：计划 → 开发中 → 本地通过 → PR CI 通过 → 主线 CI 通过 → 已部署 SHA → 公网 UAT 通过 → 持续运行。Web 上线≠微信上线；timer enabled≠任务完成；官网网页抓取≠官方日期复核；站内提醒≠微信通知已送达。

## 1. 唯一生命周期

1. **需求 Discover**：issue 包含用户角色、业务价值、可观察的验收标准、影响页面/API/地区/考试/支付、非目标、明确已知假设；第三方规则附官方来源/审核时间。短需求由 AI 推导默认方案，不反复要求用户填表。
2. **设计 Choose**：复用现有组件和 API；重大架构/数据决策记 ADR，需记录备选方案、失效模式、兼容与回滚。每个任务从 origin/main 创建独立 git worktree；不得在其他任务的脏工作区施工。
3. **施工 Build**：小步提交、单一问题单一 PR、接口契约优先；删除与迁移使用 expand→migrate→switch→contract；强制保护账号权限、考卷答案、家长隐私和支付资金。
4. **验证 Verify**：单元+负面用例、集成+权限隔离、真实 Web 桌面/移动端点击、微信 Taro 构建，适用时需 DevTools+安卓实机；失败/断网/重试/重放/幂等均需验证。
5. **审查 Approve**：PR 模板记 Why、Scope、风险级别、正负测试、数据安全、回滚、影响双端、验收证据。若证据缺失须写 NOT VERIFIED，不能声称已完成。
6. **发布 Release**：只有四项 CI 检查均过才能 merge；main CI → 生产拉取 CI-green 提交 → candidate smoke → 不可变原子切换 → public SHA 与 Production Receipt 一致 → 线上真实 UAT。旧 SHA 保留供回滚。
7. **运营 Operate**：监控用户关键操作、各 API 错误/延迟、磁盘、数据备份/恢复、worker 健康、官网采集健康、支付/微信异常；告警形成可行动工单。
8. **复盘 Improve**：先恢复业务、保留证据，再做根因、时间线、侦测缺口、回归用例、预防复发。仅重跑成功不算根因整改。

## 2. 风险级别与评审

| 等级 | 举例 | 必备证据 |
|---|---|---|
| L0 低 | 文案、纯说明、无行为样式 | PR、lint、界面/设计检查 |
| L1 一般 | 赛事列表、计算/竞赛普通交互 | L0 + 正负行为、真实桌面/移动浏览器 |
| L2 高 | 登录、考试会话、计费 UI、定时任务、持久化状态 | L1 + 身份越权/重放/幂等/恢复、Web/小程序 parity、回滚与运行时核验 |
| L3 关键 | 真钱、数据库迁移、密钥、角色授权、发布和回滚器 | L2 + 隔离环境故障注入、数据快照和恢复演练、独立技术审核或项目所有者明确批准 |

2026-10-10 实际 GitHub branch protection 已要求 4 项 CI，但 required approving review count = 0；**不可谎称 GitHub 已强制独立批准**。单人项目须在高风险 PR 中单独保留审阅/授权证据；有第二审阅人后才适合开启强制批准与 CODEOWNERS，不能擅自锁死主线。

## 3. 标准发布链与门禁

Issue → 风险分类/可选 ADR → 隔离 worktree → 单测/集成/安全/前后端真实 E2E → PR → 四组必需检查 (quality、Web browser click E2E、Miniapp build and API contracts、billing-ledger) → main CI → 服务器自动部署 → 候选真实烟测 → 原子切换 → 公网发布 SHA → 生产验收 → 定期运维。

微信小程序：正式 upload 还需干净 checkout、精确 remote/main SHA、同 SHA 的微信开发者工具/安卓实机 QA 回执、微信平台审核和已发布证据。只有 Taro 编译通过不能声称已在微信上线。全球赛事：历史学校名单/官网变更先入审核队列；复核当届、地区、受众和有效期后才可以作为日期提醒。关注≠已报名，站内提示≠微信订阅推送。

## 4. 安全与数据（NIST SSDF）

密钥仅保留受控运行环境，不进入 git/PR/log/浏览器包。学生/家长账户、答题/行为数据和 PDF 私有资源在 API 端鉴权；必须测试游客、已停用账号、跨学生、重放和 session 过期。支付回调必须校验签名、持久化幂等、异常补偿。迁移前要建立可复原快照，先演练，再执行。每次依赖升级有锁文件、供应链审计；扫描通过不等于零风险。发现泄露必须轮换而不只是删除文件。

## 5. 生产可靠性 SRE

至少监控：公网 /api/release 的 ok/SHA、首页/登录/计算首题/正式答题提交、PDF 下载、家长页面、微信登录/支付、后台定时任务最后一次成功时间、每个官方来源错误、剩余磁盘、数据库/JSON 写入错误、备份年龄。所有监控有负责人、异常阈值、处理动作；不得只收集日志而不处理。

拟定可用性 SLO：Web 月可用率 99.9%，另监测考试与支付关键路径；**这是拟定目标，不是已证明的历史成绩**。RTO、RPO 在隔离恢复演练前为 UNKNOWN，不能给出承诺。数据备份需要每日、加密、异机保存，定期真正恢复并核对内容，Git 历史不是用户数据备份。

P0：考试无法提交/权限泄漏/资金错付/全站停机，立即停止发布、恢复/回滚、保护证据；P1：主要链路受阻或官方消息系统系统性失效；P2：局部视图或个别来源不通。故障不是有日志就算闭环，必须包含侦测、分级、处理、恢复、验收、无责复盘、回归测试。

## 6. DORA 五指标与工程看板

每两周生成：部署频率（仅正式成功）、变更前置时间（提交→生产）、变更失败率（生产干预/回滚）、失败部署恢复时间、部署返工率。原始证据来自 GitHub commit/CI、生产 release receipt、事件和回滚记录。并跟踪真实浏览器通过率、微信实机验收率、任务失败率、数据备份最近成功时间。无法得知的指标为 UNKNOWN，不写成 0。

## 7. 自动控制 vs 人工工作

ops/engineering/controls.json 是机器可检查的控制目录；scripts/verify_engineering_controls.py 与其单元变异测试在公开质量门禁中执行。控制脚本检查的是仓库 wiring 和安全不变量，**不是生产运行证明**。生产使用 ops/engineering/production_readiness.sh 只读核验并输出真实证据。任何 control 中的 OPEN 风险都应在基线审计中列明、分配责任和安排实测。仅 PR 文本模板不能替代 CI 和 Github branch protection 的真实设置。
