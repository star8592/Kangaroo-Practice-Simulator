# SOC THINK 职业实操：微信单账号历史成绩闭环与付费边界

版本：2026-11-01 v1，工作分支 `feat/career-account-history-20261101`。
状态：**已经有实现与本地正式构建/浏览器验收；未合并、未生产上线**（以最终 GitHub、部署 SHA、公网回执为准）。

## 1. 产品行为

- 游客或未登录者：免费答题，真实服务端评分与逐题讲解；本地浏览器保留未交卷草稿，不会生成云端成绩。展示简单的微信登录入口，但不强制登录才能练习。
- 已经通过现有微信登录的账号：提交时由现有 `userFromRequest` 确定稳定学习身份；**前端不传 userId、ownerId 或可信分数**。服务器根据本地原始答案计算分数后，写入当前账号自己的历史记录。手机和电脑登录同一账号后可取回相同记录。
- 微信小程序现有 Bearer 身份：复用现成签名会话及私有 user key；不引入新账号系统。不代表网页版家长和小程序 OpenID 已被合并到同一身份，必须由现有官方绑定机制解决，不能通过名称猜测或强绑。
- 可打开历史报告：成绩、时间、案例版本、逐题对错、正确答案与解析；不会将他人 UID 或哈希暴露给浏览器。
- 重测：创建新答题编号，可以重复练同一案例；未完成付费权益前，练习和客观报告继续免费。

## 2. 服务、存储与身份

现有正式主站 `/opt/socthink-math/private/users` 与不可变发布目录 `/opt/socthink-releases/current/private/users` 指向同一私有数据目录；无需独立数据库、定时任务和第二套登录。

- `POST /api/career/practice/[id]/grade`：100%服务端判分，匿名免费；已验证微信学习 ID 才自动保存，响应包含 `saveStatus=saved | failed | browser-only`；**保存失败不能假称成功**。
- `GET /api/career/practice/history?caseId=...`：最多50条当前用户自己的概要；`?attemptId=UUID` 返回本人该份完整报告；其他账号返回404，未登录401。
- `src/lib/career-attempt-store.ts`：每个合法微信学习 ID 的 SHA-256 命名目录；独立 UUID v4 文件，`wx` 排他创建临时文件、`fsync`、`hardlink` 原子无覆盖提交；防止并发同编号冲突。目录0700，文件0600，记录中不存微信 OpenID、支付信息、手机号或真实姓名。
- `attemptId` 只作为幂等提交编号，不是授权凭据。服务端验证当前微信 owner、案例 revision 和答卷指纹；重复提交同一编号返回已有结果，换答卷则409。
- 未登录身份不能以任何客户端值 `ownerId`、`userId`、`score` 越权保存。报表 `Cache-Control: private, no-store`，避免 CDN 缓存私有资料。
- 存储按当前单机共享目录原子操作设计，不能虚称多区域数据库的 exactly-once。变更数据位置前必须制定数据库迁移、历史还原及并发策略。

## 3. 验收和失败回退

`npm run test:career-account` 使用临时用户根目录验证：
匿名、游客、微信网页身份、微信小程序Bearer；本人可读/不同账号不可读；满分、错卷、白卷、历史列表、报表详情、幂等重试、不同答案编号冲突、401/404/400、目录权限。

`tests/e2e/career-account-history.spec.ts` 在**仅本地 loopback + 显式 /tmp 临时用户根 + E2E_ALLOW_SYNTHETIC_FIXTURE=1** 时运行模拟微信登录、实际点击交卷、刷新后恢复、另一个浏览器读取和不同账号隔离，覆盖桌面 Chrome 与 Pixel7 模拟手机浏览器。无真实用户凭据写入 CI。

GitHub `.github/workflows/ci.yml` 先完成现有浏览器 smoke，用另一个隔离根目录再独立启动 Next 测试此账号历史流程。原数学考试、支付和用户数据门禁保持不变。

发布仍使用现有 `socthink-auto-deploy.service` 不可变候选 → 内容/考试库存/权限验收 → 晋升 → 失败自动回退，并且只以 `/api/release` 的精确 SHA 和真实公网页面交卷验收作为“已上线”的依据。

## 4. 现有收费系统的真实边界

已经存在 `src/lib/billing-ledger.ts` PostgreSQL 交易账本、Native 微信支付回调、经官方核验才结算的正式授权、`billing_item_entitlements` 和服务器控制的商品目录。不得创建第二套支付账本，更不能以浏览器 VIP 标志判断已付费。

目前 `billing_products.content_kind='report'` 的销售路径 **仅允许** `measurement-center` 注册的两类自我探索测评报告。职业实操的自动评分记录**不是**已验证的可销售报告；不能通过伪造商品行将其当作测评报告收费，不能把尚未存在的“职业高级报告”放到线上付款。

下一阶段须单独完成：定义真正增值的职业岗位深度报告（维度、算法口径、解释边界、可复核样例）、对应内容类型与数据库迁移、归属校验、订单支付核对、授权有效性/撤销/重放测试、受限下载交付和退订售后政策。所有流程通过后再启用真实收费 SKU。不得以收费开关掩盖数据或报告尚未准备好的事实。

## 5. 已识别的现实限制

- Web版已验证的微信家长账号和微信小程序Bearer OpenID是两个原有身份空间；只有同一身份才能跨设备看到相同成绩。没有证据证明两者自动互通，不得宣传为“微信跨所有客户端自动合并”。
- 历史成绩是当前案例版号的评分快照，未来升级题目必须保留历史版本和清楚的分数可比性。
- 这是原创训练的实际表现，并非企业真实笔试、录用预测或职业资质评定。
- 账号云端成绩保存仍需隐私保留期、删除能力和增长容量预案；在未完善前不要无限承诺永久保存。
