# SOCTHINK · 超级智能测评平台 / 执行总图

**Owner direction, 2026-10-30.** Authority: [Epic #144](https://github.com/star8592/Kangaroo-Practice-Simulator/issues/144) and [ADR-001](./SUPER_ASSESSMENT_PLATFORM_ADR001.md). This document is an implementation map, not evidence of product launch.

## 1. 产品不是七个孤岛，也不是一个试卷工具

一个品牌（SOCTHINK），一套可执行的测评核心，多条业务线。面向学生、家长、大学生、求职者、教师、培训机构、招聘企业；Web、移动 Web 和微信小程序共用一套目录、账号关联、权益与测评记录。职业领域第二条**真实**产品线必须优先做 SQL/数据清洗/AI 实操，不以单页目录或简历投递替代平台能力。

**用户价值链：** 搜索真实需求 / 进入免费样本 → 看清内容、来源和价格 → 开考或做实操 → 保存进度与提交 → 可核验评分 → 图文/音视频解释 → 定向局部练习与复测 → 自主购买权益或向教师授权 → 真实学习/技能进步。购买不是第一个动作；不卖无法解释价值的空报告。

## 2. 四种工作台 + 统一移动信息架构

| 角色 | 首页第一问题 | 可执行入口 | 下一步 |
| --- | --- | --- | --- |
| 学习者 / 求职者 | 我现在应该测什么？ | 搜索测评、免费试做、继续上次 | 交卷、证据、复测、升级 |
| 家长 / 学生 | 孩子在哪些能力上进步？ | 已有数学、错题、进度、计划 | 家庭授权、复习与真实结果 |
| 教师 / 企业 | 怎样给一个群体可靠布置与评估？ | 创建合法考试蓝图、邀请/批量分配 | 班级/岗位报告、人工复核、计费 |
| 运营 / 内容管理员 | 什么内容可靠、什么业务赚钱？ | 来源审核、质量门禁、交易对账 | 发布与回退、纠错、转化/成本 |

**手机端原则**：外部入口按“发现—待完成—我的”组织，考试内部进入专注模式（题目、答题、进度、交卷）；复杂评估管理下沉角色工作台，而不是把几十种功能挤到一屏。未上线类别只可了解规划，不出现伪造“开始测评”“立刻购买”。桌面端保持更丰富的筛选、题目与结果并排工作流。免费和付费权益在服务端一致裁决，小程序不是第二套业务数据库。

## 3. 一个不可分裂的后端核心

```text
Web / Mobile Web / Miniapp / Teacher / Enterprise
     |       unified identity / authorization / entitlements
     v
Catalog + Assessment Blueprint -> Start/Resume -> Immutable Submission
                                      |
                        trusted Assessment Evaluator
               math | writing/voice | SQL/code sandbox | scale
                                      |
                     Grading Evidence + Human Review
                                      |
                      Explanation / Report / Retest
                                      |
                        Analytics + Reconciliation
```

建议长期 Rust 模块化单体承担稳定、高并发、强一致核心；已可工作的 Next.js 数学及微信/支付路径通过适配层逐步迁移，**每个领域的评分与业务行为必须经过双跑对账**，不启动平行账号、平行订单、平行学习画像系统。

### 领域对象与强约束

- **Source / Item / Rights**：来源、版权/商业权利、原件哈希、题目修订、答题/图表/多语言媒体版本、审核状态。OCR 候选 ≠ 可用题目；不明权利不可公开出售。
- **Blueprint**：领域、版本、难度、格式、计时、题量、出题策略、评分依据、预计耗时；同一可打印/在线试卷不复制内容主表。
- **Attempt**：本人会话、服务端授权/时间、版本钉住、提交不可篡改、重试幂等、断网恢复、跨端接续，不能只信任前端报分。
- **Evaluation**：每题验证依据、rubric版本、程序/容器实际执行证据、复核人、置信区间或不确定性；不能将模型输出作为确定性评分事实。
- **Report / SkillProfile / Retest**：成绩和技能推断分层；低样本显示证据不足；跨领域不能把不同单位的分数任意混合；复测前后保留版本及时间。
- **Entitlement / Order**：沿用既有身份/支付账本，签名回调、防重入、消费配额、退款回收、账单对账；未验证交易不得显示收入。
- **Production / Operations**：单一发布渠道、自动回退、库存/账号/旧成绩不损失、异常分类、公开链接可达、真实手机验收、生产SHA。

### P1 执行核心现状与边界

当前统一 P1 工作在独立分支中构造**可测试的纯执行内核**：校验本人授权结果、已持久化提交的哈希、题目及蓝图版本，调用注入式领域评分器，逐题检查证据并产出统一结果；非计分量表明确返回无分数。原数学采用只读 shadow adapter，通过现有 `gradeExam` 判分并验证与旧分数精确一致。**该模块目前不负责持久化、订单、沙箱运行、AI 打分，也不等于 P1 完成**；真实数据库/事务、用户会话、错误恢复和分数双跑接线仍需继续实现。

## 4. 一个内容工厂，而不是每门学科一套爬虫

有来源线索 → 版权/许可审查 → 下载或用户授权私有导入 → OCR/公式/版式 → 结构化/去重 → 答案及评分规则独立核验 → 多语言 → 逐步图文/原声/动画/解答视频 → 人工抽样/自动验收 → 多渠道按权限发布 → 用户纠错回流。

每个环节统一累计候选数、通过数、原因码、GPU/LLM/存储成本和人工成本；**只在一个集中审核门禁决定可发布性**，不在后台多处重复且隐蔽地筛选。AI 生成解析和图解都要绑定原题版本及正确答案。版权未清晰的名校真题只保留合法引用/跳转或授权自用，不擅自商业转载。

## 5. 第二条产品线必须有真正的不同能力

**职业 SQL / 数据清洗实操**：标准数据集 → 题目和 rubric → 隔离、资源限额、无任意网络访问的执行环境 → 校验查询结果与边界案例 → 提交结果证据 → 具体错误、性能、数据质量反馈 → 改进后复测。不能靠 OCR 或一次 LLM 判词冒充真实动手能力。

随后扩展 Python、AI 工作流、分析报告、模拟面试；新增考试类型只注册领域评分适配器，不复制用户、考试会话、计费和报告系统。口语/作文需要带rubric和人工复核的不同适配器，量表须独立披露信效度。

## 6. 实际交付阶段（每个都必须独立核验）

| 阶段 | 真正交付 | 必须验收 |
| --- | --- | --- |
| P0 统一门户 | 7 域单一 Catalog、可访问门户、仅真业务给入口 | **已上线**：SHA `cc18ae4`，生产门户 HTTP 200；2 live / 5 planned |
| P1 统一交易级测评内核 | 多端会话/提交/证据/报告/权益适配；数学完整对账 | 原用户旧分数、原试卷数不变；断网重试与越权拒绝 |
| P2 非数学实操闭环 | SQL/数据清洗真实执行/评分/复测 | 真实用户成功完成一份非数学实操任务，独立读回完整证据 |
| P3 AI/内容工厂 | 一条稳定、合法、低成本的端到端内容流水线 | 来源到上架可追溯、错误可回滚、生成成本核算 |
| P4 支付与订阅 | 复用现有身份+真实订单+低价单卷/包月 | 沙箱/真实试购、到账、退款、权益回收均有回执 |
| P5 扩张 | 语言/大学/资格/兴趣与教师/企业端 | 每个新领域都至少可完成一次真实测评并算清单位贡献 |

**研发并行安排**：P1 统一底座、P2 独立真实试卷样本、P3 题源/版权/内容工厂三条可并行；P4 付费接线伴随 P1/P2 逐步验收；不能因为一个反馈页、个别边框、后台表单再次中断统一核心。模块先做实际可运行竖切，再复制模块规模，避免构建巨量空壳。

## 7. 仪表盘只看与客户价值有关的指标

- 真正可用的题目和考试数（按来源/权利和质量分层，而非 OCR 或爬虫候选量）。
- 找到内容 → 开始 → 完成 → 看解析 → 复测 → 进步 → 付费 → 退款/续订。
- 每次测评的模型费用、沙箱资源费用、内容审核费用、支付费用和实际贡献毛利。
- 纠错率、错误恢复率、端到端完成率、学生低样本误判率；按领域比较而非混算。

决策规则：优先修复堵塞完整客户旅程的障碍；新增页面、后台控件、营销素材等只能为已定义的端到端能力服务。不得把“有计划 / 有接口 / 有目录 / 通过 mock 测试”表述为“客户已经可用 / 已产生收入”。
