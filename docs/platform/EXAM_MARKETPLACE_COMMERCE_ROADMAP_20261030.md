## 一、战略定位与不可偏离的产品原则

**考试 = 一类可上架商品（SKU），考试系统 = 统一基础设施，诊断/复测/机构服务 = 客户长期价值。** SOCTHINK 同时面向 B2C 考生/家长和 B2B 老师/培训机构/招聘企业。品类越多不等于天然有流量；每个品类必须有自己的真实客户需求、可核算的内容/推理/支付/获客成本、合法题源及可持续复测价值。

唯一架构：

```text
微信小程序 / 手机 Web / PC Web / 教师机构台 / 企业端
       ↓ 搜索真实考试 / 体验 / 选购 SKU
Catalog + CommerceProduct (考试 / 口语次卡 / 实操 / 套餐 / 会员 / 机构席位)
       ↓ 身份和监护权限 + 服务端价格快照 + 独立订单号
统一 Orders / PaymentGateway
        ├─ wechat_native (PC) / wechat_jsapi (微信内 Web) / wechat_h5 (合规场景)
        ├─ wechat_virtual (微信小程序虚拟权益：须依据实际已开通能力)
        ├─ alipay_page (PC 网站)
        └─ alipay_wap (手机网页)
       ↓ 官方验签 + 查单 + 金额/币种/商户/应用/订单核对
唯一账本 billing_orders + billing_payment_events / 退款 / 日对账
       ↓ 统一 Entitlements / 配额 / 家庭授权 / 机构席位
Assessment Blueprint → Attempt → ScoreEvidence → Report → Retest
       ↓ 完考率 / 单次成本 / 毛贡献 / 退款 / 复购
```

- **单订单**：一个 SOCTHINK 商家订单绑定一个稳定 SKU 与一次服务端价格快照；选择不同渠道只是支付适配器，不建立平行订单、会员、学习画像。
- **商品不是题目**：商品可对应单张卷、三次口语模考、考试包、限额 AI 训练、订阅（非自动续费优先）、企业席位；同一内容/试卷只保留一份权威来源与授权记录。
- **仅可交付服务可卖**：商品没有合法内容、真实可开始的考试、验证好的评分/报告/复测、真实支付权限和退款服务时，状态只能保持 draft/preview/blocked，不能出现“立即付款”按钮。
- **付费服务独立计成本**：普通数学自动评分、实时语音、AI 图文视频、SQL 沙箱各核算使用量与成本，SKU 有预算与消耗额度；不承诺无限次数模型调用。
- **保留免费价值**：已有公开算术、公开样题、基础结果不突然上付费墙；免费体验可明确展示完整服务价值。
- **未成年由授权家长购买**：不能仅凭小程序 OpenID/昵称将支付家庭、学员、历史成绩自动合并，尊重真实监护证明。
- **统一可观测**：流量→体验→正式考试→完成→报告→复测→付款→退款→续费，分考试领域统计；跨领域不混算成绩，不把候选 OCR 数当可售卷数。

## 三、商品分类、销售方式与定义完成

| 商品形态 | 交付内容 | 服务端权益 | 推荐支付模型 |
| --- | --- | --- | --- |
| 单份模拟卷 | 一场指定赛制考试+解析+约定报告 | 单个 blueprint revision 使用权 | 一次性 |
| 口语模拟 | 一次/多次 AI 考官完整模拟及音频报告 | 口试次数、时长与每次成本上限 | 次卡/包 |
| SQL/Python 实操 | 实际沙箱执行、评分、证据、复测 | 沙箱次数、CPU/时长预算 | 按次/包 |

| 会员 | 用户已可用能力的有限额度组合 | 定期授权+限额，先不自动续扣 | 非自动续费 |

**价格不得写死成猜测市场价**。产品表要有币种和最小货币单位；活动/折扣/退款以不可变价格快照保持可追溯。微信虚拟支付如采用对应虚拟货币/报价机制，不假定与普通人民币金额单位相同，须使用独立的合法支付映射，最终账本对账要有人民币结算依据。

## 四、支付代码现状与必须采取的迁移

基于 main（2026-10-30）：
- `ops/db/001_billing_entitlements.sql` 已有 8 表，`billing_products` 仅支持 `tier in (plus, pro)` 和 month/year。此表**还不能直接表示单张试卷/口语次卡/SQL 实操/机构席位**。
- `src/lib/billing-ledger.ts` 已有事务订单/权益/退款/额度，但 `createBillingOrder` 固定 `provider='wechat_pay'`，`VerifiedPaymentReceipt` 也仅支持 `wechat_pay`。**不能直接接 Alipay 而把它伪装成微信订单**。
- 会员页面此前显示暂未开放购买；无官方微信/支付宝收款接口和生产级真实回执，运营上必须继续禁用收款。

改造遵守 **additive / reversible migration**：建立稳定商品 SKU 与交付表或规范化字段（区别订阅 vs 单次 vs 机构）、不可变报价快照、订单的 provider/channel 区分、官方渠道交易 ID 唯一约束、退款金额/多次部分退款与权益精确冲正；旧 `plus/pro` 记录必须完整保留。不能把已有表直接 DROP/RENAME 或修改真实历史行。先搭建影子对账与测试数据迁移，再选正式迁移。服务端才可生成价格、权益范围、订单号，客户端任何报 paid=true、虚拟商品金额、优惠等均不可信。

在新账本线上交易未验收前，本实施 PR 只建立跨品类商品 **draft 契约、文档和模拟测试**，不暴露下单 API、不注入商户私钥、不启用付款按钮。

## 五、支付宝申请/微信提供资料协同

### 立即启动支付宝申请（不依赖全部考试上线）

官方入口：
- 支付宝开放平台：https://open.alipay.com/ （网页/移动应用创建、开发者应用/产品权限）
- 支付宝商家平台：https://b.alipay.com/ （商户认证、产品签约、交易/账单）
- 支付宝开发者入口：https://developers.alipay.com/

推荐先申请与现有 `https://socthink.cn` 对应的**电脑网站支付（alipay.trade.page.pay）**，并视实际移动网页访问申请**手机网站支付（alipay.trade.wap.pay）**；不必为此重新创建支付宝小程序、线下当面付或 APP 支付。商户网站运营主体、营业执照/个体工商户资质、银行结算账户、应用资料与实际提供服务相匹配，并以当前开放平台控制台能申请的产品和审核条件为准。

操作前提：账号持有人亲自完成实名/营业执照与结算账户认证、经营类别选择、电子协议和最终提交；在审批前可提供应用名称、官网、考试服务说明、测试入口、用户协议、隐私政策、退款规则和客服渠道。创建网页应用后获得 **APPID**；按支付宝页面选择公钥或证书模式/ RSA2，服务端生成私钥并上传**公钥**；正式回调 `notify_url` 需在实际处理器/公网 HTTPS/验签通过后配置。开通审批 ≠ 测试支付 ≠ 生产收款；记录实际每一步状态与官方回执。

**绝不将身份证照片、银行账号、营业执照全量扫描件、私钥、AppSecret、APIv3 key、证书明文粘贴到 Chat、GitHub、PR、公开日志或发给非官方人员。** 商户材料直接由主人在支付宝/微信官方安全后台提交；工程只接收非敏感的完成状态、应用编号及加密部署通道。微信材料若旧密钥已外泄应先轮换，服务端 env/secret manager 保存，绝不在浏览器前端/小程序明文打包。

### 微信支付渠道准入

- **Web PC** Native，微信内 Web JSAPI、普通手机浏览器 H5：每个产品权限与 APPID/域名独立核验，不能把扫码 API 当所有场景通用。
- **微信小程序**数字会员/AI题解/模拟考试：此前 [PR #97](https://github.com/star8592/Kangaroo-Practice-Simulator/pull/97) 已认定需优先核实 **微信虚拟支付**（2026政策与实际后台准入）。普通小程序支付官方说明不等于小程序虚拟权益可用许可。请核实应用主体、经营类目、订单发货和退款、数字服务费率及 iOS/Android 官方限制；**不得通过引导跳网页购买绕过平台规范**。
- 统一订单账本但 **支付路由严格分流**，渠道订单/支付状态不混淆。生产启用前以官网当前规则和商户真实授权为准。

## 六、上线门禁（只留与真实交易有关的硬性条件）

1. 商户号/APPID/应用审核/各场景产品签约实际有效且结算主体正确。
2. 真实可用考试及合规商品交付内容已验收；免费入口一直可用。
3. 钱的证据：官方 webhook 验签+防重放、主动查单、订单/商户/金额/币种/产品匹配；**客户端成功提示不是到账证据**。
4. 账的证据：交易原子幂等、断网/重复提交/并发/超时/退款/部分退款/对账差异处理、家长授权和安全隔离、密钥轮换/备份恢复。
5. 真机/真实金额测试与受控发布：Web PC、移动浏览器、微信 Android/iOS 小程序分别验收合法场景。支付一键停收款，不影响免费考试及既有学习数据。
6. 成本与用户价值：每笔订单记录商品、渠道、用户授权、第三方手续费与交付资源成本；每种考试有完考和复购数据，不能用“上架量”伪装营收。

## 七、商业决策指标及优先次序

按 **用户搜索和点击 → 免费开始率 → 完考率 → 解析打开率 → 复测率 → 实付转化率 → 退款率 → 毛贡献（含 GPU/音频/沙箱/人工/支付手续费） → 复购/机构续费** 分品类统计。早期优先既有数学产品、雅思 AI 口试、SQL/数据实操三条典型 SKU 验证同一底座，随后按真实贡献扩张 KET/PET/TOEFL/PTE、大学考研、公考/法考、教师企业测评。
