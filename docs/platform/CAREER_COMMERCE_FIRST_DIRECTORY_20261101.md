# SOC THINK 职业中心：商业入口优先 + 270岗位分层导航（2026-11-01）

## 痛点与设计决定
用户明确指出旧版虽有行业研究、热度说明，却把真实教程/服务购买入口放到页面下方，字号过小，16个大领域也不足以让求职者找细分岗位。

本次不再给旧 hero 打补丁，而是完全改造首页信息层级：

1. **第一屏：两个最大销售入口**，不采用长篇口号作为视觉中心。卡片分别为“职业教程与复习资料”（数字商品）、“模拟考试与自动评分”（数字服务）。每卡大按钮直接进入对应商品区，且列出3个真实可用商品或服务的直接链接。PC并排，移动端在卡片之前另有同屏可见的“找复习资料/做模拟考试”快捷入口。关键字号16–19px，操作高度至少48–59px，移动端两个快捷入口必须在首屏。
2. **行业分类目录**：13个面向国内用户的行业大类，覆盖270个具体岗位名称、约30个细分方向，支持站内实时关键词搜索、行业切换、角色详情页。默认“行业总览”只显示13张行业卡和每行业4个岗位示例，避免展开270行而导致商业产品又被挤到底部；切换分类后展示此行业全部细分岗位。
3. **真实商品详细区**：3份完成验收的原创教程可阅读/下载；3套原有模拟考试可服务端评分、报告及复练；继续提升字号、触控尺寸。目录中只有内容验收通过的具体岗位类型显示该岗位直接相关的教程/考试，其他岗位明确“专项资料尚未上线”。
4. **岗位热度与研究数据**：不删除真实增速、出处和现有企业招聘证据；但退到商业入口和岗位分类之后。原有16个行业招聘样本卡及研究方式默认折叠，仅在用户需要时展开。前台不把采购招聘类别页面视为某公司当前正在招聘的岗位。
5. **SEO**：有对应真实内容的岗位详情可索引，仅有名称和分类、尚无专属教程/考试的薄内容详情页 `noindex,follow`，避免制造270个低质量SEO落地页。

## 分类依据及数据边界

架构参考《中华人民共和国职业分类大典（2022年版）》的多级职业分类原则；人社部门官方大典为八大类、1639职业，本网站采用**13个行业消费导航大类**，不是声称这些是官方八大类、不是逐条转录官方职业分类编码。

参考资料（人社部门/国家发改委转载）：https://www.ndrc.gov.cn/fggz/jyysr/jysrsbxf/202210/t20221031_1340470.html

`src/lib/career-role-taxonomy.ts` 是**用户导航目录**，包含13个大类、细分方向、270个岗位名。它不代表270个经核对的招聘岗位、也不等于270个已上架的训练商品，不展示假的招聘热度、企业认证或工资价格。真实招聘证据仍只有此前 `career-demand.ts` 的版本化36条非随机样本；市场热度仅限有一致统计口径和来源的具体职位。

## 产品映射

`src/app/career/roles/[id]/page.tsx` 中 `EXACT_PRODUCTS` 只允许下列三个**有完整交付内容**的训练轨道直达：
- 采购与寻源 → 供应商决策原创教程 + 采购模拟考试
- 电商与零售运营 → 运营 ROI 原创教程 + 商品运营模拟考试
- 工业质量与可靠性 → 工业 FMEA 原创教程 + 工业质量模拟考试

其他岗位有职位分类信息及同领域岗位导航，但不显示虚假的商品、考试报名或价格。随着真实内容建设，新增产品与映射必须经过内容来源和在线评分/下载测试。全站仍使用原微信单账号和 PostgreSQL 收费账本，没有增加第二套支付系统。

## 实际验收
- `npm run test:career-directory`: 13行业、270去重职位、细分类、搜索与筛选、已上架产品匹配及首页重要性测试。
- `npm run test:career-research`、`npm run test:platform`：原企业证据、职业题库、微信身份、账号隐私、阅读/数学/SQL平台测试完整回归，不删除旧系统测试。
- `npm run lint`、`npx tsc --noEmit`、`npm run build`。
- `tests/e2e/career-commerce-navigation.spec.ts`：电脑/Pixel7，验证两大主入口、移动端两个入口首屏可见、13类岗位卡与270导航计数、选择行业、查找质量工程师、进入岗位详情领取其内容、直接跳到已开放实操服务。
- `tests/e2e/career-market-and-storefront.spec.ts`：岗位增长数据、三个资料包、下载文件和在线考试服务实际可操作。
- `tests/e2e/career-practice.spec.ts`：原3套案例每套完成正确判分和空白重测，覆盖PC与手机。

## 发布边界
PR和本地UI测试不是公网。上线需要GitHub保护CI、主分支合并后GitHub push CI、正式服务器不可变发布及自动回退、公开 `/api/release` 对齐准确SHA、**真实公网**完成PC/手机商业入口和岗位导航E2E、三套商品/服务入口无障碍。不可在没有真实支付验收之前放出职业报告或资料付费链接。
