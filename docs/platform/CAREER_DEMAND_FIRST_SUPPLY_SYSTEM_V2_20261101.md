# ADR-Career-002：企业招聘需求驱动的职业产品供应工厂（2026-11-01）

> **正式产品决策，覆盖 2026-10-31 文档中以 SQL 作为首条业务主线的排序。** SQL、Python、面试等都是可能的交付组件，不是分类中心。实施状态：部分数据与需求目录代码已提交 PR，正式收费与规模化自动采集尚未上线。

## 0. 目标：不是「题库找用户」，而是「企业需求找内容」

```text
企业官方招聘岗位（可合法获取、原始证据、抓取时间）
  → 岗位身份/行业/地区/学历经验/校招社招
  → 岗位职责、必须能力、加分项、明确招聘流程
  → 多企业复用的技能/任务/胜任力图谱
  → 原创商品候选：资料、教程、笔试、面试、实操、项目
  → 真实内容与执行评分验收 → 有库存/交付/权益的SKU
  → 买家免费体验、真实支付、交付、考试、复测与投诉
  → 购买信号、复用率、JD变更、可持续收益 → 下一轮供应规划
```

**不预设岗位门类的重要性，不以研发、数据或 SQL 作为中心。** 技术研发、AI、数据、产品、运营、销售、市场、品牌、游戏、视觉、供应链、采购、物流、财经、风控、人力、法务、客服、商业管理都纳入候选视野。每类最终分配的内容生产资源由可核验的岗位证据与用户真实购买意愿共同决定。

### 关键区分

- 官方职业/岗位分类 **只证明企业存在这一职业方向**，不证明某个岗位目前正在招、不证明考试题型，也不证明必须技能。
- 具体 JD **证明该版本明确写出的任职要求和职责**；只有企业官方说明考试流程时，才可说企业使用某类测评。
- 我们根据任职要求自行开发原创模拟卷、案例、实验和教程。它们是 **SOCTHINK 独立训练产品**，不等于官方真题、官方认可或面试通过承诺。
- 如果没有具体职责证据，只列为待调研岗位，**不得自动生成虚假课程或销售页**。

## 1. 用户浏览路径与产品供给

消费者（B2C）按「我要应聘哪家企业/哪个岗位」或「我要提升哪项能力」进入，查看与岗位相关的**来源、更新时间和任职要求**。站内推导出能帮助备考或补能力的内容，优先免费样题，后续是完成真实验收的付费教程、考试、情景面试和隔离工作实验。一个具体技能可以服务多个岗位，但**不能让技能倒过来主导站点导航**。

B2B 企业可用同一题库/执行环境制作职位测评，但应独立授权、采用岗位相关且公平的评价标准，不搜集无必要的敏感身份数据，也不能向求职者透露企业真实保密题库。

平台顶层仍是 SOC THINK 的一个 `career` 域。招聘需求台账、内容生产与既有 Assessment Core / Catalog / Attempt / Grade / Report / Entitlement 和账本复用，不建第二套考试或支付服务。

## 2. 首轮可核对的岗位证据与覆盖边界

首轮已结构化 [`data/career/demand_signals_seed_20261101.json`](../../data/career/demand_signals_seed_20261101.json)：24 条非随机官方来源记录，横跨 5 个企业和 16 个岗位领域，其中 8 条是职位级说明，其余是岗位分类级证据。

公开源示例：
- [阿里巴巴 2027 校招](https://campus-talent.alibaba.com/campus/index)：研发、算法、芯片、产品、游戏、运营、商务拓展等岗位类别。
- [华为官网](https://career.huawei.com/cn)：研发、销售、服务、供应链、采购、财经。
- [美团 2027校招 FAQ](https://zhaopin.meituan.com/web/question/campus)：报名、测试、部分考试通知规则；具体岗位请看独立 JD。
- [美团商品运营应届岗](https://zhaopin.meituan.com/web/position/detail?highlightType=campus&jobUnionId=4694862636)：商品规划、价格、经营指标、ROI、库存等职责。
- [美团采购开发岗](https://zhaopin.meituan.com/web/position/detail?highlightType=social&jobUnionId=4781234064)：供应商筛选、价格、商品开发。
- [美团供应链计划实施](https://zhaopin.meituan.com/web/position/detail?jobUnionId=4439415825)：需求/库存计划、S&OP、流程、SQL等。
- [京东数据科学家](https://zhaopin.jd.com/web/job-info-detail?requementId=224411)：SQL、Python/R、实验、因果等。
- [腾讯2027海外校招公告](https://careers.tencent.com/m/zh-cn/faqdetail.html)：产品与设计等类型；**海外公告只是岗位分类参考，不能直接当国内招聘规则。**

**不能从这个非随机样本的条数推断招聘市场占比/岗位热度**。网页会过期；`observedAt` 是观察时间，`publishedAt` 未核准时必须留空。

## 3. 数据协议与自动需求映射

正式入口是受许可来源的版本化 `job_signals` 流，而不是维护多份企业专属页面。

输入规范：
- 企业与来源：`company_id, official_url, retrieval_time, published_at?, source_hash?, source_rights, evidence_level`；
- 岗位：`posting_id?, role_title, normalized_role_family, level, work_location, campus_or_social, valid_at?, status`；
- 能力：`skill_id, requirement_type(required/preferred/duties), evidence_ref, reviewer_status`；
- 招聘流程：`employer_confirmed_stage, process_source, cohort/edition`；**不能从 JD 自动推测为笔试**。

算法：
1. 跨URL规范化去重：企业+职位ID+发布版本，保留历史，不能因下架删掉既往证据。
2. 提取「必须」「加分」「工作职责」证据，连接统一技能词典，缺乏证据记 `unknown`。
3. 评估可制作性：是否可写原创题、是否能客观/可复核判分、单次执行成本、法律与公平性要求。
4. 每条技能可以匹配多种候选交付（讲义、选择/问答、代码/数据实验、面试Case、职业项目），**映射表是可更改的模板，不是售价和商品库存**。
5. 只有真实 JD 能力证据生成 `proposal`；无证据类别显示「继续调研」。
6. 商品转正必须拥有题/素材清单、受权证明、实际运行或准确判分回执、交付样例、权益和价格配置；`proposal` 一律不能收费。
7. 产生复用和销量数据后，资源配置按跨企业能力覆盖、用户真实需求、复测结果、单位贡献排序，**绝不使用抓到的JD条数作为市场总量**。

首个实现片段：
- `src/lib/career-demand.ts`：读版本化证据数据，验证来源和证据级别，跨公司/岗位领域汇总，搜索。
- `src/lib/career-product-mapper.ts`：仅根据职位级技能证据生成原创产品**候选**；无具体职位证据不生成候选。
- `src/app/career/page.tsx`：求职者按公司、岗位、能力筛选，只展示证据和规划内容，不给虚假购买链接。
- `scripts/test_career_demand.ts`：种子数据、覆盖广度、证据分级及产品候选不越权的检查。

## 4. 产品组织层级

第一层：**企业/岗位匹配**。第二层：**岗位需要的能力**。第三层：**用户可实际购买或免费使用的内容形态**。不是 `SQL → Python → Java` 的技术课程列表。

示例供给（全部须有职位证据和可运行内容才能售卖）：
- 商品运营岗位 → 商品规划、定价、库存、ROI 的模拟经营数据/专题教程/情景面试；
- 采购岗位 → 供应商评价、招采成本、合同谈判、质量与交期的 Case；
- 设计岗位 → 创意Brief、素材制作、作品集评审与可复核作品评价；
- AI应用工程岗位 → API/RAG/Agent系统实现与自动测试；
- 财务岗位 → 只有对应企业具体 JD 提供能力要求后，才推出财务分析/预算相关训练，不因官网存在「财经」栏目就认为企业已经考试这些内容。

## 5. 后续运营节奏（工程目标，不是现有自动化能力）

- 每次增量扫描输出 `new/changed/closed/unknown`，基于企业官方公开访问许可，最小化采集，禁止绕过验证码/登录/反爬与大规模再分发受保护的职位文案。
- 第一批先用 2026/2027 届招聘与近期社招；历史最多近三年做变化分析，旧要求不能当新一届考纲。
- 模拟题与实际岗位要求出现偏离时标记「待复核」，而不是偷偷改旧版考试和用户成绩。
- 公开 SEO 页必须有具体证据、实质内容和真实可操作入口，不批量生成「XX厂1000道真题」空页面。
- 比较市场时引入分母：允许采集范围、去重职位、更新频率、行业地域分布、用户意向，避免少量样本的频次偏差。
- 核心指标：有效JD、JD→技能映射的准确性、发布可用训练数、完考与复测、真实交易与交付、投诉与纠错、单次变动成本、每SKU毛贡献。

## 6. 验收级别

- **D0（已有开发分支）**：多职业需求样本、岗位搜索、证据级别、原创内容候选、无虚假支付入口；必须通过类型检查、单测、页面请求。
- **D1（待建）**：有权限增量岗位来源抓取、去重、来源追溯、能力词典验真、有效时效自动更新。
- **D2（待建）**：至少三个不同职业领域的真实可完成免费练习、真实判分/报告与改进建议。
- **D3（待建）**：复用既有支付与权益，将完成审计的商品实购、发放、消费、纠纷处理闭环接入；不以模拟支付冒充验收。
- **D4（待建）**：企业需求变化驱动内容版本与SKU更新，按销量/完考/成本复盘。

**结论**：网站供给由企业需求与真实客户反馈共同驱动；能力考试、模拟面试和教程是可复用的生产模块，不是先验的产品目录。
