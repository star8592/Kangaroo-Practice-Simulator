# 全球数学赛事管家：个人关注与赛事赛历（二期）

## 已实现（2026-10-09）

- 赛事主档与具体场次解耦：赛事关注属于 eventId 层的个人意向，不表示当届报名、考试资格或证书；具体的报名状态仍由既有 AcademicSession / Enrollment 负责。
- 统一关注 API GET/PATCH /api/competition-follow：仅有效学生身份可操作；匿名与临时游客会话拒绝持久化。服务器只接受已知赛事 ID 和布尔 following；幂等添加、撤销；存储于私有用户数据目录中的 world-competition-follows.json；每个用户只可读取与修改自己的列表。Web 用 cookie，小程序用 Bearer。
- Web 目录：统一地区与参考学段筛选、关注数、登录后关注/取消、进入「我的数学赛历」；错误反馈与重试。
- 小程序：共享赛事目录 API 的 following 字段；赛事管家使用相同参考学段/地区筛选和关注操作；顶部汇总已关注赛事、最多三项下一步任务并可进入对应清单；临时游客保存前要求正式微信身份。
- 个人赛历：保留现有可信具体考试场次及节点；新增关注赛事列表、清单完成进度、每项赛事下一步行动和最多三项当前备赛建议。未知当届日期绝不编造日历节点和倒计时。
- 参考学段字段只表示历史或系列受众；未知范围的赛事对所有学段保持可见，不能据此认定本届赛区报名资格。

## 验收与上线门禁

- 隔离数据目录的 API 契约：不同学生、匿名游客、非法赛事、非法状态、非法 Content-Type、幂等与个人赛历。
- Web 桌面/移动端：实际学生登录、关注、查看个人赛历、从赛历返回、取消关注，匿名可浏览。
- Web 和小程序的 following 状态从同一数据源读取。
- 不跳过完整公开质量门禁、微信编译、正式 CI、生产 SHA 和公网 E2E。
- 小程序正式上线另需微信开发工具与安卓实机同 SHA QA 回执及审核/发布证据。

## 后续改进

- 建立按官方来源核验的届次、赛区、报名渠道和有效期，不把历史活动泛化至任意地区。
- 学生确认年级与地区；家长通过明确家庭关系管理关注。
- 只有可信日期且学生关注/报名时才推送真实提醒。
- 现有私有 JSON 存储适用于小规模 MVP；多实例部署时应迁移事务数据库，并对 userId/eventId 加唯一约束，避免跨进程并发覆盖。
