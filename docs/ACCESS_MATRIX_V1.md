# 数学竞赛训练中心：统一账号、权限与付费权益方案 v1

最后更新：2026-10-08。适用产品：socthink.cn Web + 微信小程序。
**当前状态：方案与授权引擎首期实施；未对既有免费服务启动收费，也未接通正式付费权益。**

## 1. 核心原则
1. 游客能立即做题并看基础成绩。已公开样题（尤其 `au-amc-pre-a-sample-2`）不能被登录/收费墙阻拦。
2. 注册用于保存学习档案，不以邮箱/电话作为开始学习的强制条件。
3. 收费的是增量价值：个性化诊断、长期分析、按薄弱点组卷、可交互 AI 题解、家庭赛程管家，而非现有基础算术、基础题解与原始成绩。
4. 家长付款、学生学习；会员权益从家长/家庭向已绑定的学生派生，孩子之间的成绩绝不混用。
5. 内容来源合规/题目质量核查与用户是否付费独立；付费不豁免下架、不完整、不可分发试卷。
6. 授权由后端判定；前端只显示 UI。账号角色和套餐完全独立。

## 2. 账号与计费主体
- `anonymous`：无会话浏览者，仅可访问公开的赛事目录、介绍。
- `guest`：服务器签名的临时游客会话（现用 guest_ 前缀）。允许公开样题、基础计算、基础结果，默认无永久历史。
- `student`：站内学生账号或已经服务端验证的微信小程序身份。拥有独立学习记录；跨设备同步需明确绑定同一学生实体。
- `parent`：邮箱/微信验证的家长身份，可持有订单，管理和合法绑定学生。
- `admin`：运营角色，仅用于受控管理后台，不自动拥有其他人的隐私或订阅权益。
- `free/plus/pro`：不是角色，而是可变套餐。订阅过期自动降为 free，历史数据不删除。

小程序的 OpenID 随 AppID 变化，关联其他登录渠道必须完成可验证的账号合并流程。微信初次登录不得错误视为已和站内学生绑定。

## 4. 商品与价格
- 商品 SKU 分开 `plus_month`、`plus_year`、`pro_month`、`pro_year`、按次诊断包、席位扩容包；价格/优惠/计费币种取服务端配置，不把前端金额作为实付依据。
- 正式定价在支付方式和市场试验之后确定，不能在未履约前收钱。
- 配额由 `capability+owner+period` 和幂等使用记录决定；失败不扣次数。不同会员等级提供不同额度，但未售卖的额度不应写死为“无限”。
- 到期后基础历史成绩仍可看；高级重新分析/生成暂停。账单、发票、退款、注销和数据删除都不能置于付费墙后。

## 5. 系统架构
建议统一 API `GET /api/access/me`，Web 依 Cookie、小程序依 Bearer Token，经服务器身份校验返回当前套餐和各个 capability 的可用性。实际执行业务请求时必须调用同一 `canAccess()`，不可只靠隐藏入口。
判断顺序：身份 → 家庭/数据所属 → 内容来源许可及质检 → 有效权益/到期 → 配额/并发 → 许可或结构化拒绝。
错误语义：未认证为 401；无权益为 403（返回 requiredPlan 与 upgradeUrl）；资源不属于本人或不该泄露存在性为 404；限频为 429；失败应显示可读错误而非空白。
- `policyVersion` 为配置审计字段。权限策略不能让已开始考试的用户突然无法交卷。
- 每次获取“试卷正文、题解、报告、PDF、开始考试、成绩提交”的后端操作必须独立鉴权。
- 在 feature-flag 开启付费约束前，所有历史公开卷保持免费；新高级 API 从首次上线就走强制授权。

## 6. 权威数据与跨端一致性
建议事务型存储：
`products`、`orders`、`payments`、`entitlement_grants`、
`family_memberships`、`usage_buckets`、`usage_events`、`audit_logs`。
`entitlement_grants` 至少存 `owner_id, tier, source_order_id, start_at, expires_at, revoked_at`；
`usage_events` 有唯一幂等键。授权不能读取未签名、未验证、来源不明的订单状态。父母可同时管多个孩子，但业务 API 用单个学生 subject 限定数据。

## 7. 微信支付、退款与商户安全
**2026-10-10 合规勘误：见 `docs/engineering/PAYMENT_DUAL_CHANNEL_ADR_20261010.md`。** 原有“小程序普通 JSAPI/`wx.requestPayment` 购买会员”流程已不再适用于小程序虚拟商品交易。应按渠道拆分：
- Web PC：普通微信 Native 支付（商户已开通权限后）；微信内网页 JSAPI/H5 需分别核实产品及 AppID/域名权限；
- 小程序会员、AI 题解和数字题库：2026 微信规则下应接入 `wx.requestVirtualPayment` 的专用虚拟支付服务端流程，先核实商户后台的虚拟支付准入与商品配置；
- 两端服务端按各自官方签名/查单/发货机制核实成功，标准化为可信交易事件后，才允许进入统一事务权益账本、幂等发放、退款冲正与日对账；不允许小程序跳转网站付款规避虚拟支付规则。
微信收银台“支付成功”客户端回调不等于正式授权，必须以微信官方交易状态确认为准。
退款/撤销需冲正权益和配额，不能追溯删除儿童历史成绩。回调重复投递、订单超时、异常支付、金额篡改、退款、多次请求都要验收。
订单与孩子身份的绑定由家长在受保护流程里授权。
证书、APIv3 密钥、AppSecret 永不写入 Git/日志。小程序虚拟内容的实际售卖、支付渠道及界面须按上线时平台规则审核；未审核前不得直接支付上线。

## 8. 客户旅程
**游客** 点赛事卡 → 直接进入公开样题 → 完整做题 → 看到基础成绩 → 提醒注册即可长期保存，允许稍后再说。
**注册学生** 看全部免费内容/错题/成绩/基础报告 → 进入高级能力时解释具体收益及升级条件，不遮挡原功能。
**家长** 微信/邮箱登录 → 创建/绑定学生 → 购买并查看订单、权益、期限、用量 → 派发权益到合法关联学生。
**付费家庭** 跨 Web/小程序使用同一个服务端 entitlement，不重复收费；席位不足明确解释。
**异常** 网络断开、权益检查失败：公开功能仍可使用；付费生成失败友好重试且不扣额；没有无限 spinner 或空白屏。

## 9. 渐进发布和验收准则
P0 修复已报告样题空白/加载异常，并验证 25 题完整图文和游客会话。
P1 实现中央策略纯函数、身份分类、矩阵自动测试；建立 Web/小程序只读权益接口，不收费。
P2 建立被核验的支付权益数据源和家长-孩子绑定边界；沙盒模拟到期/退款/复购/配额。
P3 给**新增高级功能**同时加入服务端拒绝规则与客户端权益解释，旧功能继续免费；增加权限规则监控。
P4 微信支付正式验签、查单、退款/对账、异常恢复端到端通过，按 1% → 10% → 100% 灰度启用。
P5 审核所有下载、报告、题解、试卷、AI 用量、微信 Bearer/站内 Cookie 路径；持续自动回归。

验收场景包括：游客、免费、有效会员、已过期会员、未验证/重复支付；
父母查看自己和别人孩子报告；做题时订阅到期；高并发计费；
小程序/Web 同一账户一致；题库仍满足原来源许可；
至少确认 `/exam/au-amc-pre-a-sample-2` 免费进入且 25 题可见。
未完成后端账本、支付确认、灰度与回归，不标记“付费系统已上线”。

## 11. 微信小程序无感身份与 Web 一体化补充（2026-10-08，待实施）

本节**补充而不替换**上述第 1–10 节权限矩阵；《PRODUCT_INFORMATION_ARCHITECTURE_V2.md》为页面、交互、流程的执行文档。身份（谁）、角色（家长/学生）、权益（free/plus/pro）、数据主体（某个学生）、内容可分发性是五个独立维度。不能用“微信已登录”替代会员判断，也不能把“微信小程序用户”自动推断为已验证家长。

### 11.1 首次进入与再次进入
- 小程序默认首页，不以“注册/登录”页作为启动页，不用先登录才能点“开始计算”。
- 后台优先复用有效业务会话；无会话时异步调用 `wx.login()`，后端使用**该小程序自身的 AppID/AppSecret** 校验一次性 code，按 `provider + appid + openid` 查找/创建最小身份，再发行本系统短期会话。敏感密钥和 session_key 仅存在服务端。
- 首次成功识别的小程序用户默认 **free**。允许匿名显示公共页面；资料完善不是启动门槛。不得静默获取昵称、头像、手机号、通讯录或未经声明的其他个人信息。
- 登录超时/微信接口异常/服务器不可用时，公开内容和基础训练应有明确降级路径（游客临时会话或设备暂存，视端能力）；绝不因身份接口失败造成首页/题目空白、无止境加载、反复弹登录。
- 会话过期采用单飞刷新/单次重试；旧会话可用时不中断正在进行的训练或考试。失败先保留本地作答草稿；不要在不明用户身份下将其写入别人的账户。
- **重要**：不等于自动成为“已绑定的站内学生/家长”，也不等于已取得家长监护授权、手机号或付款权益。

### 11.2 Web 与小程序统一账户
- 采用内部统一 `account_id`/学生 `student_id`，渠道身份另建映射：`auth_identities(provider, appid, openid/subject, account_id, verified_at)`；有 UnionID 且达到可信关联条件时仅作候选匹配，**绝不只凭相似昵称或客户端申报合并**。
- Web 维持公开首页、邮箱/账号及微信扫码等登录路径；小程序使用微信自动识别为主，原学生用户名/PIN 作为“已有账户绑定/切换”的次入口，而非首屏主流程。
- 已有网站学习记录只能经**双方身份都已验证**的合并流程接入小程序，冲突时显式确认；保留作答、错题、成绩、购买权益来源审计，禁止覆盖、串号和跨学生成绩混合。
- 家长可合法创建/绑定学生，`family_memberships` 决定哪个学生可以继承家长付费权益；一位家长可切换多个孩子，学生数据各自隔离。微信静默身份不自动获得“家长”角色。
- Web Cookie 与小程序 Bearer Token 认证通道不同，但调用同一 `/api/access/me` 权限快照、同一服务端 `canAccess()` 与可信账本；不允许前端独立维护 VIP 布尔值。

### 11.3 渐进式登录/授权/购买时机
| 用户操作 | 应有体验 | 禁止行为 |
|---|---|---|
| 打开小程序、浏览首页/赛事 | 直接展示、后台异步识别 | 强制登录页挡住首页 |
| 点公开样题/基础计算 | 立即练习，显示基础判分与解析 | 交卷后才告知付费可看对错 |
| 需要跨设备长期保存 | 告知数据保存价值，再核验/绑定同一学生 | 匿名临时记录偷偷覆盖已有档案 |
| 查询个人历史/家庭赛程 | 已绑定则直接访问；未绑定仅在此节点轻量引导 | 全站反复弹注册窗 |
| 进入高级诊断/AI 题解 | 展示价值、权益、余额/配额、升级方式 | 假装已付费或跳过后端授权 |
| 家长开通或分配权益 | 家长身份校验、学生关联、支付核验与订单恢复 | 微信登录身份直接当付款人，前端支付回调直接发权益 |
| 信息/手机号/隐私接口 | 只在具体功能必要时明确请求并遵循适用隐私规则 | 自动抓微信昵称头像手机号、拒绝后封死公共功能 |

### 11.4 发布门禁与验收
- 本次补充属于**架构文档与实现计划**，不代表现网已完成，正式收费仍依赖原 P2–P5 的可信账本、平台合规审查、对账及端到端验收。
- 独立覆盖：全新微信用户、已登录回访、微信 code 失效、断网、微信服务器失败、Web 历史账号绑定、家长两个孩子、会员到期、重复支付、交卷中刷新会话。
- 公开样题 `/exam/au-amc-pre-a-sample-2` 必须持续以游客身份可进入且 25 题显示完整；现有免费计算、标准题解、标准成绩不得意外加墙。
- 小程序与 Web 测试用**同一个后端身份、家庭关系、权限策略版本**核对能力可用性；拒绝越权或无权益 API 的测试必须覆盖直接请求而不是仅验证按钮隐藏。
- 功能发布以“灰度 + 可回滚 + 数据不迁错 + 实机验收”作为完成条件，文档/代码/构建/线上四种状态分开汇报。

## 12. P3 公开权益目录与页面（2026-10-08）
