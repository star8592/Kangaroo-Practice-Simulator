# 数学卡册与荣誉体验 V1.0 开发方案

Last updated: 2026-10-04

## 0. Scope lock

本方案只属于 `star8592/Kangaroo-Practice-Simulator`（数学竞赛/训练项目）。\n\n本功能同时受 `docs/features/THIN_GAME_LAYER_V1_1.md` 约束：游戏反馈必须服务于数学主线，不能形成第二套主流程。
本轮目标是给真实小学生/中学生测试一套“看得懂、马上有感觉、愿意继续”的卡牌化奖励体验；不把儿童前台做成成人化的 Achievement/Profile 系统。

## 1. Product decision

儿童前台的主语言不是 Achievement、Identity、Trophy Case、Percentile 等成人产品术语，而是：

- 我的卡册
- 新卡片
- 稀有 / 超稀有 / 传说 / 神话
- 升级
- 我的战绩
- 晒一晒

后台仍可保留 Achievement、Verification、Level 等工程概念，但不要求儿童理解。

核心循环：

完成挑战 → 奖励揭晓 → 卡牌出现 → 翻牌 → 收进卡册 → 展示/分享 → 挑战下一关。

## 2. Card-first model

V1 将“卡牌”作为视觉主角，勋章降级为卡牌上的小元素。

卡牌类型：

1. 成就卡：由真实训练行为、连续训练、个人纪录等触发。
2. 竞赛卡：由完成真实竞赛试卷/模拟并产生有效成绩触发。
3. 人物/数学世界卡：第二阶段扩展，用于数学家、概念、主题收藏。

V1 只上线前两类的基础体验，不做对战、交易、随机抽卡、氪金抽卡。

## 3. Emotional design

奖励不是一个静态提示，而是一个“事件”。

不同成就具有不同情绪强度：

- 普通完成：轻反馈 + 星星
- 新纪录：明显庆祝
- 新卡：卡背出现 → 翻牌 → 稀有度揭晓
- 升级：Level Up
- 重大竞赛成绩：完整领奖仪式 + 证书/荣誉卡

V1 首先把“新卡揭晓”做到有趣，而不是一次性做完整游戏。

## 4. Card visual language

卡牌应像孩子想收藏的实体卡，而不是一个 32px 徽章：

- 手机端中心大卡
- 卡面主体清晰
- 稀有度一眼可见
- 微光/粒子/浮动效果优先用 CSS/轻量动画
- 点击翻面
- 背面显示获得条件、成绩、日期等简单信息
- 不用复杂数据图表

稀有度语言：

Common / 普通
Rare / 稀有
Epic / 超稀有
Legendary / 传说
Mythic / 神话

V1 的稀有度只用于体验验证，不宣称“全站真实稀有比例”。以后接入真实获得人数后再升级为真实稀有度。

## 5. Child-friendly copy

示例：

- “哇！你拿到新卡啦！”
- “这张卡加入卡册！”
- “再挑战一次，就可能升级！”
- “新纪录！”
- “传说卡！”
- “这张卡要不要晒一下？”

避免：

- 数学身份
- 复杂百分位解释
- 用户资产
- 荣誉档案
- 成就引擎
- 验证等级

## 6. Card book

儿童端提供“我的卡册”入口/区域。

展示：

- 已拥有卡
- 未解锁位置 / 下一张卡目标
- 最近获得
- 最喜欢的卡（第二阶段）
- 分类收藏（第二阶段）

V1 已迁移为账号级真实卡册：系统根据当前学生账号的真实考试记录自动生成并同步竞赛卡，不再依赖浏览器 localStorage，也不要求学生手动“存卡”。同一套正式试卷只保留一张卡；重做后如果成绩提高，这张卡按最佳战绩升级，避免重复卡刷屏。

## 7. Competition integration

竞赛试卷完成后，从现有真实结果数据生成第一张竞赛卡。

卡牌必须绑定：

- examId
- competitionId / formatId（如果存在）
- year（如果存在）
- score / maxScore
- completedAt

卡牌不能伪装为主办方官方奖牌。

历史赛场模拟的任何“奖项”必须保持：
“按该年度公开数据模拟/估算，不是赛事主办方颁发的官方奖项”。

## 8. Share

V1 可以先提供“分享/复制分享文案”的入口；
第二步再做高质量图片 Share Card 和公开荣誉页。

分享内容必须强调真实成绩，不制造官方奖项，不公开邮箱、家庭信息等私密资料。

## 9. Safety / anti-abuse

不做：

- 付费购买核心荣誉
- 付费随机抽卡
- 卡牌交易
- 赌博式随机机制
- 用虚假全站排名诱导孩子
- 将模拟结果写成官方获奖

鼓励：

- 真实成绩
- 个人纪录
- 真实进步
- 坚持
- 挑战

## 10. V1 implementation boundary

第一版只验证一个问题：

> “学生做完一次数学竞赛训练后，看到一张漂亮、会动、可以翻面的卡牌，会不会明显比普通结果页更兴奋，并愿意继续挑战？”

V1 deliverables:

1. Result 页面新卡揭晓动画。
2. 大卡正反面。
3. 稀有度视觉。
4. 账号级真实卡册，完成正式挑战后自动收卡。
5. 最近获得卡片展示。
6. “下一张卡”目标：按当前最佳战绩提示下一稀有度门槛；达到神话后引导挑战新的正式试卷。\n7. 再挑战 CTA。
8. 基础分享入口/分享文案。
9. 成就卡：首次正式挑战解锁“初次出征”，首次满分解锁“满分时刻”。\n10. 新卡提示：最近一次解锁的卡显示“新”，并在卡册顶部显示竞赛卡/成就卡/神话卡统计。\n11. 不影响现有成绩、诊断、复盘链路。

## 11. Feedback experiment

用真实学生测试三组体验：

A：现有成绩页
B：成绩页 + 静态卡牌
C：成绩页 + 动态翻卡 + 收藏

主要观察：

- 学生是否主动点击卡牌
- 是否主动打开“我的卡册”
- 是否询问“下一张怎么拿”
- 是否愿意再挑战
- 是否愿意分享
- 哪种卡面最喜欢
- 稀有度是否被理解
- 是否觉得“像游戏”而不是“像作业”

核心不是单纯点击率，而是：
“学生是否自发地想继续拿下一张卡”。

## 12. Post-V1

只有在真实学生反馈证明卡牌有效后，才继续：

- 卡牌升级
- 卡牌组合
- 隐藏卡
- 赛季限定卡
- 角色/头像框
- 数学家人物卡
- 数学能力主题卡
- 卡册社交展示
- 更丰富的服务端账号级收藏能力（收藏夹、置顶、最喜欢、分类等）
- 公共荣誉页

## 13. North-star product principle

后台可以复杂；孩子看到的必须简单。

最终儿童体验：

做题 → 得奖励 → 开卡 → 收起来 → 晒出来 → 再挑战。
