# R179 — SOC THINK 英语角色入口与架构收敛合同

2026-11-16。以主站 socthink.cn/english 为单一英语入口。
老师进入 /english/teacher，学生进入 /english/student；作业专属链接可直接进入，
不应强迫用户绕行二级门户。

## 核心架构规则

1. SOC THINK 主站负责微信 OAuth；四套英语教学引擎不再分别创建微信登录。
   跨应用关联必须使用已验证的 UnionID 或经验证的当前身份会话，
   绝不凭学生姓名、教师姓名或家长昵称自动合并账号。
2. 主站 WeChat session 证明“微信已登录”，**不证明教师或学生的业务角色**。
   当前主站 ParentUser 还使用受保护的 JSON 存储，role 为 parent，
   尚不是 PostgreSQL18 中完整的教师/学生统一账户。不可谎报已统一。
3. 发音与词语星球保留原教师后台和产品服务端的任课权限核验。
   词语星球仍需要首次原账号验证和微信关联；已有课程、作业、
   学习事件与复习历史不迁移、不丢失。
4. 阅读与 AelOS 尚无经验收的统一班级作业接口，仅作为教师内容浏览入口。
   页面不得伪造“所有班级已汇总”或跨产品成绩平均分。
5. 后续在单一 PostgreSQL18 实例按 schema/database 实现统一主体、角色、
   组织与班级映射；教学引擎继续独立管理评分、音频、FSRS、
   课程内容及学习明细。跨产品报告只能读取真实可信的事件证据，
   数据合同见 schemas/english-learning-event.v1.schema.json。
6. 所有主站英语产品元信息以 src/lib/english-products.ts 为唯一注册表，
   角色入口仅在 src/lib/english-role-hubs.ts 追加角色路由适配，
   不再维护重复的产品清单。
7. 四个应用继续独立源码、独立构建与回退，统一经由
   /english/{product}/app/ 公开。现行共享静态目录内互相复制资源的
   发布方式只是过渡，目标是各自原子发布，彼此不覆盖。
8. 使用同一身份、同一个教师工作台的目标是减少老师重复劳动，
   不是额外增加审批层级；平台不得在没有跨产品授权时自行创建角色、
   付费权益、班级或学生联系关系。

## 分阶段验收

### M0 — 本轮统一角色入口
- [x] 老师与学生各有一个角色入口，四套英语引擎仍独立
- [x] 原英语首页六个教学直达入口保留
- [x] 阅读/AelOS 的教师入口明确为内容浏览，非班级管理
- [x] 教师 OAuth 核实身份、学生 OAuth 静默，保留原回跳地址
- [x] 桌面与手机浏览器、现有发音/单词登录流程完成隔离测试
- [ ] GitHub 合并、生产原子发布及公网核验

### M1 — 真人微信绑定
- [ ] 老师同一微信首次验证原词语星球教师账号，后续免旧密码访问原班级
- [ ] 学生首次绑定原学生账号，记录与成绩保持完整
- [ ] 退出、切号、解绑、教师撤权、监护授权失效的联邦拒绝均通过
- [ ] 真实跨 AppID UnionID 账号一致性核验，不暗中合并历史用户

### M2 — 平台身份与权限内核
- [ ] 完成现有主站 JSON 用户与各应用 PG18 身份库的迁移评估及回退方案
- [ ] PG18 统一主体/角色/机构授权，独立产品数据保留
- [ ] 各产品通过版本化身份和权限合同消费统一身份，不再复制 OAuth

### M3 — 真正的统一教师后台
- [ ] 真实跨产品班级 ID 映射、任课授权与双向核验
- [ ] 作业 API 幂等派发、真实回执、AI 批改与学生任务聚合
- [ ] 不同产品的成绩按来源与评分量表分栏展示，未经证据不合算总成绩
- [ ] 单手机建班、布置作业、收成绩的端到端体验验收

### M4 — 独立发布与统一权益
- [ ] 每个引擎拥有独立原子发布、回滚和主站健康监控
- [ ] 真实订单驱动跨产品权益，不能仅凭登录获得收费功能

## 发布边界

R179 只新增主站角色页面与导航入口、微信登录上下文、相关验收。
不修改生产数据库、不替换任何英语教学引擎、不声明 M1–M4 已实现。
正式发布沿用 GitHub main、CI、候选构建、库存守卫、原子切换和回退。
