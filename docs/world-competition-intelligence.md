# 全球数学赛事管家：核验与提醒引擎（阶段三）

## 目标与真实能力

从单纯赛事关注提升为基于证据的站内提醒。参赛地不是赛事主办方总部所在地。学生明确选择“拟参赛地区”，才允许匹配该地区的具体场次。

目前提供：经过来源复核的届次信息结构、适用地区和年级过滤、有效期/去重/紧迫度排序，以及 Web / 微信小程序的站内查询与赛区选择。**不等于已实现自动抓取、微信订阅消息推送、短信或邮件发送**；不得以“自动提醒已运行”宣传。

### 当前已核实日期

数据源 data/competition-intelligence/verified-editions.json 首批仅纳入 MAA 官网 https://maa.org/amcreg/ 核验的 2026 美国 AMC10/12 届次：10月15日和28日是**美国考点管理人登记日期**（不是学生个人报名日期），考试日为11月5日和13日。官网内容经本次助手复核，尚无双人审核；中国赛区不适用，不直接套用。现有学校导入源仍标记 raw。正式数据应通过代码审核 PR 加入；只有当届官方主办方或正式区域运营方、有效 HTTPS 来源、审核人、审核日期、适用赛区、有效期（不得超过审核后 180 天）、赛事 ID、届次及至少一个具体节点完整填写，才允许进入候选发布。在线验证器验证的是元数据格式与过滤规则，并不能代替人工确认实际来源真实、权威和一致。

同样修正了既有 AcademicEvent / 学生首页注意力摘要：学校原始照片等 raw 来源不可触发紧迫日期和考试倒计时；已登记但未核实节点的个人赛历会明确“当届场次日期待核验”。

## 数据与算法

- 主档 worldCompetitionId → edition id / sessionId / season → region → milestone kind+date。
- 来源 sourceAuthority 只能 organizer 或 regional-operator；url 必须 https；verifiedBy 非空；verifiedAt / validThrough 必须有效且未过期。
- 同时满足：学生真实登录（排除 guest_），已关注，明确拟参赛地区，与来源赛区一致，当前在审核有效期内，日期在 0–30 天内，学段不明确时不硬排除；等级不足时过滤。
- registration-deadline 必须注明受众。competition-manager 级别截止仅提供 P3 参考信息，明确“非学生个人报名截止”，绝不提升为学生本人 P0 截止提醒；考试/设备等动作仅对已登记的具体 session 展示。
- 优先级：≤3 天 P0，≤7 天 P1，≤14 天 P2，≤30 天 P3；去重，最多展示前三项。过期来源、错误赛区、原始导入、无关注均产生 **0 条正式日期提醒**。
- UI 支持设置/清空参赛地区，私有数据保存在 world-competition-regions.json。与用户身份关联，不能传 userId 越权查询。返回 Cache-Control private, no-store。
- Web 页面 /student/calendar 内展示“我的赛事情报”；小程序 events 内展示“赛事情报与截止提醒”。暂为进入界面后的站内查询，不启用实际外发通道。

## 测试与发布

- scripts/test_competition_intelligence.ts：纯算法模拟有效/无效来源，学生隔离、游客 401、区域偏好、可信性拦截、未登记考试不提醒、假日期不加入生产、旧学校 raw 日期不再进入学生注意力。
- tests/e2e/guest-navigation.spec.ts：桌面/手机实测登录、选择/清空区域、重新加载持久化。
- tests/e2e/china-competition-directory.spec.ts：匿名 API 权限。
- 完整 npm run verify:public、微信小程序 typecheck/build 和公开 Web 浏览器 E2E 均必须通过；CI、合并主线和生产回执 SHA 对齐后才能视作发布。
- 任何实时消息通知与全自动官方信息采集属于下一阶段，需要运营来源核验、消息发送权限、用户通知同意与送达/重试/退订机制；不得跳过这些门禁。

## 后续工作

1. 建立多国/赛区官方源白名单和来源监控（抓取新信息进入 review queue，不直接生成已核验日期）。
2. 运营核验流程：证据快照、字段级复核、版本与撤销、双人审核、来源可信度评估、变更审计。
3. 按用户同意开通微信订阅消息或邮件提醒；含降噪去重、首次提醒与改期提醒、撤回及失败重试。
4. JSON 数据存储如扩展到多实例，应迁移至具事务唯一约束的数据库。
