# AccentLab · Next.js 原生发音 V3 体验对照 R2（2026-11-17）

状态：**候选 UI 已开发并通过本地双端/模拟麦克风自动验收；尚未替代旧 Vue V3 的全部功能。** 本文件不构成正式口语评分精度证明。

## 真实业务边界

- Next.js 原生候选：`/english/pronunciation/next-lab`。旧 Vue 正式版：`/english/pronunciation/app/practice-library`。两者共用**同一套 Rust API**：`/english/pronunciation/api/follow-along/items`、`/follow-along/items/:id/score`、`/follow-along/items/:id/score-word/:word`。
- 任何标准音频和任务句子均来自已有 Rust 目录和主站同域静态 MP3，绝不通过新前端内置私有题库、模拟评分后端或新建一套账号/计费。官方地区试卷的认证和成绩**不在此次改造范围内**。
- 生产参考音轨是已有 Kokoro AI 合成示范，不是出版社真人录音，也不是官方考试等值评分。儿童、口音差异仍可能误判。单词设备 TTS 仅作局部试听，不作服务器参考音源。

## UI 与数据隐私

- 手机首屏始终只有一句、示范音、调速与主录音按钮。双轨波形与优先单词纠音仅在有真实录音或已返回评分后出现，并且默认折叠。
- 主录音最长 45 秒，Blob 大于 6MiB 则拒绝本地分析/上传；单词最长 4.2 秒。每次录音前需用户点击并通过浏览器麦克风授权。
- 波形解码完全在当前浏览器进行；用户切换句子会清除 React 内存中的前次录音。单词录音 URL 使用 ObjectURL 并在切换/卸载时 revoke；取消未完成请求时 abort。
- 整句和单词请求只上传到已有同源自托管 Rust 实验评分器；不得额外发送音频到前端遥测或第三方 API，必须依据服务端真实回应显示 0–100 分数。
- 录音评分失败时允许查看已录本地声音，但不显示任何替代/预置分数。

## 自动化验收

- `npm run lint`、`tsc --noEmit`、`npm run test:site-architecture`、`npm run build` 均通过。
- `tests/e2e/native-pronunciation-v3-parity.spec.ts`：2 条用例 × 桌面/手机 Chrome = **4/4 PASS**；模拟麦克风录音转 Blob 后使用浏览器 AudioContext 实际解码 WAV/Opus，校验真实采样叠合、时间偏移重置、单词独立上传和评分的 HTTP 503 失败通道。
- 原有 `tests/e2e/native-pronunciation-trial.spec.ts` 仍须在 PR 的 GitHub 浏览器矩阵中检查，以避免 R1 回归。
- 测试中评分响应和参考 WAV 为受控测试夹具，**不是生产评分验证**；生产音源/麦克风/手机权限必须在发布后做真实浏览器联调。

## 发布回退及旧版清理

本批仅修改主站 Next.js 内的候选 UI，无 Nginx 静态路由变更、无生产数据库写操作、无 Rust API 改动。仅当 PR CI 绿色、与最新 `main` 无冲突，才进入既有自动回退发布流程。旧 Vue 发音工作台保留为可用对照；老师作业/历史记录的真实数据迁移验收前**禁止删除任何旧前端、数据库或教学语料**。
