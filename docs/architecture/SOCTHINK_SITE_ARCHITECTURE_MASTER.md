# SOC THINK 全站信息架构总纲（Master Information Architecture）

版本：v1.0 · 2026-11-03 · 维护对象：SOC THINK Web（https://socthink.cn）及其共享业务契约

**状态：设计基线，实施以 GitHub PR 通过并获得生产精确 SHA 回执为准。** 这是整个网站的**唯一长期信息架构主文档**。首页 V3、历次导航改版、个别产品策划以及截图都不是另一个权威版本。新增业务先判定归属，再写代码；不要因为某个页面有考试、资料或支付按钮就另造一级栏目。

## 1. 定位、用户与信息架构目标

SOC THINK 是一个聚合真实考试训练、经核验的资料、职业准备、实际可运行的技能学习、研究性测评和数字交付的中国市场优先平台。国内 K12 校内考试重点是武汉／湖北、江苏、浙江、北京、上海、广东；资源建设优先最近三年，依据**考试年份**与**真实来源**判断，不把抓取时间当作考试时间。海外竞赛是数学竞赛业务的一部分，不能反过来定义全站。

用户来站的主要任务：找考试 → 找真卷或样卷 → 开始练习；找岗位 → 了解标准 → 完成笔试/面试训练；学技能 → 找教程或书 → 运行实验；选择测评 → 查看方法边界 → 答题与阅读报告；找数字产品 → 核对文件、价格、交付资格 → 已付款后下载。**每条任务应有清晰直接入口，而不是被冗长介绍淹没。**

本架构优先优化：① 归属正确和好找；② 真实可用；③ 自助成交与交付；④ 搜索引擎与大模型可理解；⑤ 数据与代码单一权威、维护成本低。

## 2. 层级与全局页面树（当前稳定边界）

**L0 全站入口：** 首页 /、全站公开搜索 /search。搜索是发现工具而非业务一级栏目，搜索结果页不做索引入口。

**L1 六大独立业务**（桌面顶栏、移动导航共享同一数据源，顺序稳定）：

| 一级业务 | 唯一业务入口 | 二级功能与样例 | 明确不属于该栏目的内容 |
| --- | --- | --- | --- |
| 全部考试 | /assessments | K12 校内与升学；数学竞赛；语言考试；大学考研；资格公考；计算 /arithmetic；竞赛模拟 /competitions；错题 /review；考试日程 /exam-planner；数学赛事信息 /events | 招聘岗位笔试、代码实操、人格/心理研究 |
| 真题资料 | /resources | 可用试卷按地区、学校/考试、学科、年级、年份、来源及授权状态检索；可用时进入正式模拟/练习 | 付费商城的未经授权真题；把练习资料误写为官方真题 |
| 职业岗位 | /career | 招聘需求与企业证据、完整岗位模拟笔试 /career/exams/…、模拟面试 /career/interviews、岗位原创资料 /career/guides/… | 心理诊断、伪造企业官方试卷、通用编程实验 |
| 技能实训 | /skill-labs | Agent、SQL、JavaScript、WebGPU/Three.js、软件工程实操；技术书库 /skill-labs/books/… | 把技术书库做成平行一级业务；把编码任务塞进人格测评 |
| 测评中心 | /assessment-center | 逻辑能力、招聘通用能力训练、人格自我描述、RIASEC 职业兴趣、职业价值观；方法与来源 /assessment-center/methodology、报告样例 | 国家资格考试、雇主原题、未经本土常模验证的诊断结论 |
| 数字商城 | /shop | 实际在架商品、PDF 真实样张、服务器核对的付款与下载 /shop/[productId] | 无真实文件或支付授权的虚构商品；复制已有支付账本 |

**L2**：考试类型、岗位/课程/测评分类、资料筛选、数字商品列表或专题着陆页。

**L3**：具体试卷、课程、书籍、岗位模拟、测评工具、文件商品详情。一个详情页只有**一个主归属业务**，可以有多条相关推荐，但相关推荐不改变主归属。

**L4**：开始练习、交卷与评分、报告、登录、付款、授权下载、复测。这些是**动作/状态**，不再作为全站平行的一级业务。账号与权益（/account、/membership、/login）是跨业务设施，通过账户入口、流程 CTA 和页脚访问。

公众的“考试目录”**只有五类**：校内升学、数学竞赛、语言考试、大学考研、资格公考。注意：底层 Assessment Core 的七个领域仍完整保留，用于评分格式/接口契约；**接口领域的数量不等于可见考试目录数量**。不要为改导航篡改测评底层分类与历史答卷。

## 3. 不重叠的业务所有权与关联规则

一个功能只允许有一个主所有者（owner）。判断顺序：① 用户是来完成什么任务？② 交付物是什么？③ 谁负责持续更新原始数据？④ 成交/评分在哪里闭环？

- 在线计算不是新业务：属于 K12/考试的训练动作。
- 数学竞赛模拟属于考试；赛事跟踪与日程是同一考试业务的服务工具；国内仅提供来源信息的赛事不得伪装成可考的模拟卷。
- 岗位笔试虽然也是“考试形式”，但其核心对象是岗位与雇主需求，因此主归属职业岗位；代码运行型技能实操属于技能实训。
- 技术书籍是学习技能的阅读层：书籍→课程→实训→岗位案例或模拟笔试，可横向互链，但书籍不占一级菜单。
- 逻辑训练可与求职关联，心理/人格研究只能按其证据与适用边界展示；未验证常模不得做诊断或虚构百分位。
- 数字商城只是交易与交付目的地；商品可以来自任何合法授权的业务，但是课程、岗位和试卷的**内容源**不搬进商城复制维护。

**横向关联不等于层级归属。** 推荐：技术书→相应实验，实验→原书与岗位；岗位笔试→复习资料和技能实验；试卷→对应考试规则和错题；测评→方法证据与报告示例；商城商品→真实源资料说明与我的订单。主面包屑指向唯一 owner；“猜你喜欢”“配套资料”可以跨业务，不应改变 canonical。

## 4. 页面布局、主导航与首页信息优先级

顶部和手机首层只显示上述六个业务链接。语言选择、账号状态作为独立控件；不要加入“在线练习”“考试管理”“技术书库”“我的错题”等重复一级菜单；也不要在全站顶部复制考试分类导航。移动端展开后可以有“个人服务”，但不再维护另一套分类数据。

首页阅读顺序：清晰单句定位 → 全站搜索 → 三个最常用真实动作 → 依据可靠来源日期的最近更新 → 四个主要服务发现卡（职业、技能、测评、商城；考试与资料已经在首屏动作及导航体现）→ 优秀课程和书籍/岗位交叉推荐 → 下方五类考试索引。首页不是业务源数据库，也不必展示每个规划方向；不要伪造公开发布日期、会员数、成交数、题量或购买状态。

每屏优先呈现：用户要做什么、有什么实物/题量/时长/来源、是否真的可用、下一步 CTA。辅助方法、品牌声明与技术细节可折叠或进入独立说明页。字体与关键 CTA 比装饰性口号更重要；手机避免横向滚动。一个页面一个主标题、一个主操作焦点；辅助链接不能与付款/开始考试竞争视觉注意力。

页脚按考试、职业与技能、专业测评、商城与账户/政策分组；**页脚是补充发现，不能反过来定义顶层业务**。常见故障：标题写“全部”，却只进入某一个子栏目；分类下堆放不相关链接；同一个详情页两套下载或付款路径——全部视为架构缺陷。

## 5. 单一事实源：代码、数据、搜索与商业状态

- **src/lib/site-architecture.ts**：六大业务的唯一导航定义，以及 URL 前缀之外的旧功能归属；被公共页头和首页业务卡共同引用。它**不是**第二个内容 CMS 或权限系统。
- **src/lib/exam-directory.ts**：仅公开考试分类与已开放 topic；**src/lib/assessment-platform.ts** 仍管理更广泛的底层测评契约，不直接当作网站导航。
- **src/lib/site-discovery.ts**：从已经存在的技术书、岗位试卷/教程、研究量表和课程目录只读组合可检索条目；运行时试卷和商城各自读取其真实授权/在架权威来源；不重新建立第二题库。
- **真实订单、登录和交付**：复用现有统一微信账号、支付账本、商品权利校验与下载鉴权；不存在“为了导航好看”复制新的收费路径。
- **页面发布时间**：明确区分 examYear、sourcePublishedAt、verifiedAt、firstPublicAt、updatedAt；缺少可靠时间时不进“最新上架”榜。书库目录发布日期不等于原著出版年份。
- **发布状态**：planned 仅是方向；free-preview 是可用但有边界；official/verified 是有来源核验；payable 还必须有库存文件、权利与当前有效的支付开关。禁止将已有路由误判为完成收费验收。

新增商品或内容时，先补真实源 registry 和授权证据，再由现有页面/全站搜索/相关推荐发现；不能靠人工每次复制多套导航和长篇宣传。

## 6. URL、面包屑、SEO/GEO 与历史兼容

L1 路径一旦上线，尽量长期固定。子层路由仍可能保留历史短路径，例如 /arithmetic、/events、/review、/exam-planner；**真实归属由 architecture 的 owner 规则定义，不要求为了路径外观大规模迁移**。所有可访问的旧书签继续有效。此前的 /assessments#domain-career 与 #domain-interest 在客户端明确导向 /career 和 /assessment-center；将来如需要服务器 301，必须先观察真实流量与 SEO 影响。

每个公开详情页只设一个 canonical；搜索查询页 noindex；结构化数据应与页面真实业务类型、来源、时间和售价一致。Sitemap 不得包含登录、后台、订单私密数据、未审核或无权利内容。需验证公开 200、内链、软 404、robots 与 Sitemap 一致性。跨业务推荐写清“相关课程/相关书籍/配套岗位资料”而不是把所有内容强行塞到同一分类。

**六个一级入口与实际交易/成绩边界分离：** SEO 信息架构可以改变展示层，但不能通过 URL 或导航绕过授权、付款确认或成绩隐私。

## 7. 工程边界与上线验收

保持模块化单体、低耦合、清晰数据流：公共导航配置、业务数据 registry、考试执行、测评评分、商品支付、交付下载、SEO 发现是不同职责；通过明确链接/只读投影连接，不通过“重复建一个通用中心”连接。

每次分类改动只需最小的**现有**验证：导航契约单测（六大分类/主 owner）、现有平台合同与支付边界测试、桌面/手机真实浏览器关键路径测试，然后按照当前自动发布/失败回滚流程部署。不要叠加互相阻拦的发布门禁，不要更改无关组件。生产成功必须有同 SHA 回执及公网 URL 点击检查，PR 合并不等于生产完成。

关键用户路径（必须能走通）：

1. 首页 → 全部考试 → K12 计算 / 数学竞赛 → 作答 → 复盘；首页 → 真题资料 → 筛选 → 训练/详情。
2. 首页 → 全部考试 → 考试日程 → 数学赛事管家；原 /events 与 /exam-planner 直接链接继续有效。
3. 首页 → 职业岗位 → 完整笔试/模拟面试 → 岗位教程 → 相关技能实训。
4. 首页 → 技能实训 → 技术书库 → 官方来源/课程 → 可运行实验。
5. 首页 → 测评中心 → 方法来源 → 问卷/报告示例；未验证心理常模明确披露。
6. 首页 → 数字商城 → 文件真实样张/售价 → 登录 → 仅在支付可用时付款 → 订单授权下载。

## 8. 迭代与稳定性策略

不把“长期稳定”误解成禁止升级。采用：**观察真实用户路径 → 找错层级和断链 → 找统一 owner 的根因 → 小范围改代码与主文档 → 用可重复测试和公网回执确认 → 删除旧重复实现**。不同页面各自复刻菜单、临时 patch 或叠加兼容层都不是目标。

以下情况**才考虑新增一级业务**：拥有区别于六大业务的独立用户目标、可持续独立交付与真实供给、独立业务主责，且不能以二级子栏目承载。技术新潮、功能新增、商品更多、训练模式不同，均不是增设一级菜单的充分理由。任何 L1 变动必须同步修改本总纲、共享业务导航注册表、页脚/首页呈现及原有回归测试；一般新增内容只调整对应 L2/L3 和相关推荐。

后续持续核验清单：孤儿页与重复旧路由、面包屑主归属、K12 年份/来源、商城公开发布时间、全站搜索召回、各业务的“访问→作答/购买→交付”真实漏斗。按证据和成交价值优先处理，不凭主观感觉反复大规模换结构。
