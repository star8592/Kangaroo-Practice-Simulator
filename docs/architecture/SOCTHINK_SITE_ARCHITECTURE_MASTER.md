# SOC THINK 全站信息架构总纲（目标版 v2.0）

版本：v2.0 · 2026-11-03  
性质：**转型目标架构；本分支仅记录设计决策，尚未替换生产导航、迁移数据或发布。**  
唯一长期主文档：本路径。原六业务版 v1.2 保留在 Git 历史中，待代码切换后不再作为当前业务约束。按实际合并/生产回执判断生效状态，不能以文档状态冒充上线。

## 1. 新定位与最优先客户

**SOC THINK：面向中国大学生、应届毕业生和社会招聘求职者的职业能力学习、实训、测评与面试准备平台。**

核心用户只有两组：
- **校招学生**：选方向、理解岗位、补技能、做完整项目、正式模拟笔试与面试，准备真实求职。
- **社招求职者**：评估已有经验、补岗位差距、转岗/跳槽、完成更深的实操和情境面试。

共同底层是「岗位 → 技能要求 → 可信知识来源 → 课程 → 可运行项目 → 笔试/面试 → 能力报告 → 复习」。面向用户可以区分校招/社招难度，但**不得复制两套知识库、题库和支付系统**。不宣传包就业、官方认证或缺乏依据的行业通过率。

**战略收缩的意思是收缩客户对象与入口，不限制技术/学科来源。** AI、软件、数据、商业分析、运营、工业、职业英语等均可按岗位需求进入；不是每个学科都要建一级栏目。

## 2. 三个产品边界：主站、数学、英语

| 产品边界 | 用户 / 目的 | 本期处理原则 |
|---|---|---|
| SOC THINK 主站（socthink.cn） | 校招/社招求职、职业技能、笔面试 | 重新设计信息架构；迁移已有可用职业模块；不再围绕数学竞赛组织主页 |
| K12 数学教学和竞赛（建议 math.socthink.cn，最终 DNS/部署核实后决定） | 当前以用户自己的课堂、少量学生为主 | 从主站抽离为独立应用/运行边界；保留实用的题库、赛制、作答、错题、教师查看；不继续把它当大型 K12 商业平台开发 |
| 英语独立产品（English Leap 等） | 独立的英语学习和课堂服务；部分与就业、留学重叠 | 保留独立产品；主站只连接**已真实交付**的职场英语、校招外企面试、CET/IELTS/TOEFL 等相关服务；不得以规划内容充数 |

数学可先通过受限独立入口和原有教学数据稳定使用，再拆物理应用；不引入额外的多租户、家校/监护层级、复杂支付。**不是立即删除或覆盖原有学生数据。** 数据迁移前导出验证，迁移后双向核对；主站不访问数学学生私有数据。

英语的职业化模块尚未完成，不能把它写成已经上线的商品。通用英语教学的产品身份不由 SOC THINK 主站决定。

## 3. 用户导向的导航（不是六种经营业务）

**目标顶级导航只允许以下三类已交付的核心任务**：
1. **岗位方向** `/career`：岗位画像、技能要求和证据、校招/社招入口、岗位学习路线。
2. **学习与实训** `/learn`：免费导学、技术文档、可执行实验、项目交付；书库及 GitHub 开源资源作为子层，不再独立占一级。
3. **模拟笔试与面试** `/practice`：岗位标准完整卷、情境面试、答题结果与复盘；正式考试必须有明确题量、时长、方法、来源、报告示例。

**英语**不是先摆一个空顶级入口：待有真正可运行的职业英语产品后，可在岗位路线、学习路径和相关服务中展示「英语能力」入口；是否上升为一级导航由真实访问/转化决定。商品购买/下载、个人账号、搜索、能力档案、方法与版权说明为横切功能，**不额外设「商城」「测评中心」「真题资料」顶级栏目**。商城服务仍可由所属课程/岗位购买入口进入。

首页的主要动作：**选择目标岗位 / 开始训练 / 进行模拟面试**。校招和社招可作为同一页面的目标筛选，不要额外复制两个门户。每屏只显示用户需要的事实：适用对象、要做什么、时长、可用状态、来源、费用和下一步。

现有 `/career`、`/skill-labs`、`/career/exams/[id]`、`/career/interviews/[id]` 等路径不因 UI 改版就无条件删除。新 URL 与旧地址建立一一映射、唯一 canonical、必要的 308/301 跳转；新/旧数据注册表仅有一个写入权威。**技术实现允许过渡期兼容，但不能让两套业务实现永久并行。**

## 4. 学习服务的最小闭环与可衡量产品

核心对象：`Role`（岗位）→ `Skill`（技能）→ `SourceRecord`（证据）→ `LearningUnit`（课程单元）→ `Lab`（项目与实验）→ `Assessment`（模拟）→ `Result`（私有报告）。关系表引用 ID、版本与权威数据，**不要复制 README/题库/商品/训练结果**。

岗位详情必须给出：
- 目标群体：校招/社招、经验档位、应具备的技能；引用招聘证据但不冒充官方要求。
- 免费学习入口：原创中文导学、原始资料链接、可试运行的示范练习。
- 实操入口：明确环境、输入输出、可运行要求、自动检查与独立评分证据。
- 正式笔试：符合对应岗位的完整题量与时长，不提供没有意义的 6 题伪正式版本。
- AI 模拟面试：提问与追问有岗位相关性，保留评价依据、报告与可复练建议，且不宣称与实际雇主面试一致。
- 明确状态：`planned` 只在内部；`free` 和 `paid` 必须分别有真正可用的后端能力、商品和交付验证。

**一切付费围绕交付价值，而不是给免费开源资料换个包装收费。** 免费导学用于 SEO/GEO 和用户信任；收费可以是完整实训、项目批改、正式笔试报告、AI 面试与复练。每一服务需测真实成本、使用效果、购买转化，不依据 Star 或热帖声量推断质量。

## 5. GitHub / X 知识生产链

X 是发现与趋势信号；GitHub 是代码、Issue、实验和版本证据；官方文档/论文是规则和方法来源；招聘信息证明岗位需求。**来源证据与原创教学必须分层**：
1. 发现线索：原帖/视频/评论的原始链接、发布时间、作者、引用关系，标注尚未核实的断言。
2. 上游核验：仓库 commit SHA、更新日期、许可证与第三方素材权利、运行条件；识别停更/替代项目。
3. 技术复核：仅在隔离环境运行，不直接执行不可信仓库代码到生产；记录可复现输入、输出和失败。
4. 教学开发：中文独立讲解、预备知识、分步实验、原创题、解析与岗位能力映射。
5. 商业发布：以版权、可运行性、考试/报告品质和真实支付交付为依据，逐件上线。
6. 持续更新：源代码版本或规则发生变化时，只重新审核受影响的技能和课程，不使采集失败阻塞主站。

依来源授权处理 X API、公开视频、图片、数据集、GitHub 代码；禁止把公开可访问误判成任意转载/付费再分发授权。禁止将星标/转发量当作就业结果或专业质量证明。

## 6. 现有路由迁移：先分类，后抽取，最后删旧路

**以 2026-11-03 已审核的 75 个 Next.js 页面模板 + 1 个静态历史入口为基线**，详见 `SOCTHINK_PAGE_ROUTE_AUDIT.md`（v1.2 路由基线；迁移时同步更新而非另造平行表）。

| 当前板块 / URL 族 | 目标 owner / 处理 |
|---|---|
| `/career/**` | 主站岗位，按角色和校招/社招档位保留、加深内容 |
| `/skill-labs/**` | 主站学习实训，旧 URL 稳定映射至 `/learn/**`；仅已可运行的内容进入主推 |
| `/assessment-center/**` | 与求职有关的逻辑/职业能力测评整合进岗位训练；其他自我描述测评按方法边界决定是否公开，不再一级独立 |
| `/shop/**`、`/account/**`、支付及权益 API | 主站共用交易与账号能力，不建第二套订单或登录，不把商城作为一级主入口 |
| `/arithmetic/**`、`/math-practice/**`、`/competitions/**`、`/events`、数学赛制与学生报告 | 抽至数学独立应用；旧链接按业务和实际身份规则重定向；私有页面不得公开跳转泄露参数或成绩 |
| `/assessments`、`/resources` 中的 K12/竞赛内容 | 迁至数学产品；主站仅保留确属职业/高等学习的知识内容，去掉旧六栏目位置 |
| 英语相关规划和早期入口 | 仅确认真正存在的服务后建立职场英语、大学英语/留学英语的主站关联，原独立英语产品不迁入主站 |

**绝不能对共享 `/exam/[examId]`、`/result`、`/report/[attemptId]` 做无差别跳转**；先识别真实实体 owner、权限和历史记录。每条迁移有旧地址、新地址、页面 owner、规范 URL、索引状态和用户路径；未关联的页面列为待删除/归档，不保留永恒兼容分支。

## 7. 技术原则与迁移顺序

- 主站首期继续使用现有 Next.js/React 和账户/支付后端，按岗位、学习、模拟的模块化边界重构；不因转型就同时引入第二框架、消息队列或微服务。
- 数学独立应用与主站物理服务边界可以分阶段分离，但长期不再在主站路由/导航/依赖图混装数学和职业逻辑；共享公共函数只允许小而稳定的显式接口，不共享可写业务数据。
- 先确认数据权威（题库、历史答卷、账号、支付、资料权利）再移动路由；将不可信采集系统和生产账户/订单/考试隔离。
- 清理旧链接、旧二级菜单、重复 registry 和不再使用的组件，宁可一次规划迁移完成后删旧实现，也不要在六业务导航上长期叠加补丁。
- 最小发布合同仅保证构建可启动、账号权益/试卷/支付正确、失败可自动回退；内容采集、灾备演练不阻塞普通页面发布。必须有真实公网 SHA 回执才能声明上线。

**阶段 A（结构与证据）**：盘点 76 个现有入口和所有实际动态实例；形成唯一迁移映射；锁定数学服务的私有数据边界；设计三项主站导航和标准岗位详情。

**阶段 B（可运行闭环）**：优先建立 AI Agent、SQL/数据分析、商业运营三条*真实可交付*岗位路线。正式模拟笔试和面试必须验收实际结果，不能以路由 HTTP 200 冒充已完成。

**阶段 C（切换与减法）**：同一提交/受控发布序列修改导航源 `src/lib/site-architecture.ts`、考试目录、路由归属、逐页审计与测试；数学独立入口可用后再撤主站入口；验证老链接、首页、移动端、模拟笔试/面试、权益、SEO，自动回退保留。

**分支上的设计文档不代表迁移完成**；只有代码、数据、浏览器和生产回执同样过关，才更新本文件为「已实施」。

## 8. 设计约束

1. **用户先于既有资产**：业务未形成真实客户负担，不因为过去写了代码就继续经营不适合目标客户的品类。
2. **一页一个目标和 owner**：主要任务、导航、breadcrumb、URL、CTA、数据所有权保持一致，避免孤儿页。
3. **来源可追溯**：公开资料/教材/代码/题目/模拟面试的来源、版本、生成方式与方法边界真实且明确。
4. **可用先于宣传**：没有真实实验、正式题量、题解、评价和支付交付，就不能宣传成已上线产品。
5. **能删则删，不叠门禁**：把旧设计从根因上替换，保护实际客户数据，保持最小必要验收与自动回滚。
6. **以付费价值检验战略**：看从岗位导学到实训、真实评测、面试和付费的完成率，而不是累计栏目数、仓库 Star 数和转载量。
