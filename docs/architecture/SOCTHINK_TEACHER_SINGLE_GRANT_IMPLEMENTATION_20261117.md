# 2026-11-17 · 微信教师授课授权单一权威

线上事实：主站 platform.role_grants 存在一条 active 的
english.pronunciation 教师角色；旧 accent.teacher_access_requests 表中对应微信
账号没有记录、无班级，因而原有课堂 `approved()` 返回 403。

## 修复
- 主站已绑定微信且平台 `english.pronunciation` 产品级 teacher/module-admin
  授权有效，即可调用课堂 `/teacher/onboard` 创建自己的首个班级；
  无须再次向 AccentLab 申请教师身份。
- 原课堂已经批准的历史老师仍可授课，不做破坏性迁移或删除。
- 站点所有者继续通过经验证微信凭据确认；任何用户/管理员不得访问其他教师
  的班级、成员或成绩。`teacher()` 仍逐班验证 lead_teacher_id 和 membership。
- 后端获取当前平台授权，不采用浏览器的自报角色、昵称或本地缓存；
  平台角色服务出错时，新授权路径返回 503 而不放行。
- `/teacher/access`、统一用户目录中的课堂教师状态与实际授课权限一致；
  历史独立课堂审批记录仍保留，避免老教师数据断裂。
- 管理员界面不再提示一名教师必须经两个后台重复开通。
- 撤销平台角色将立即阻止没有历史独立授权的老师继续管理班级；授课数据保留。
  如果历史独立授权存在，撤销那条旧权限仍需在原课堂审核中操作。

## 验收
- `scripts/test_teacher_unified_access_20261117.ts`：
  主站有效教师/模块管理员、拒绝其他模块权限、无权限403、认证查询失败503、
  站点所有者路径、历史课堂兼容等 10 项断言。
- 仍需证明目标老师的微信 Cookie 本人真实读回、实际建班和作业发布；不模拟
  或生成真实老师的微信身份凭据。
