# ADR-2026-10-31: SOCTHINK 全考试门户视觉重构与 Rust 后端演进

状态：**Proposed / implementation branch**。主站生产模式当前仍为 Next.js，本文不代表 Rust 服务已部署或完成全站重构。

## 结论
- **保留 Next.js 16 / React 19 / TypeScript 作为前端，重做设计系统、导航和页面模板**。无需为了引入 Vue 再重写全部现有考试、支付和微信登录组件。前端不新增第二套 Nuxt 应用。
- 未来核心业务后端迁移至 **Rust（Axum + Tokio + Tower）模块化单体**，PostgreSQL 作为一致性数据库，题目图像/音频/PDF 走授权对象资产服务。性能提升以 profiling、p95、资源占用和压测为证据，不把“Rust 比 Node 快”当成无条件数字。
- Next.js 负责 SSR/SEO、路由、表单及交互；**不长期保有第二套交易、评分、权限账本**。迁移单个模块时使用接口契约、双向对账、灰度读回、回滚，确认后删除旧 TS 业务逻辑。
- 不引入 Redis/Kafka/微服务作为默认依赖。题库检索优先 PostgreSQL 索引、全文/前缀/同义词，再用真实性能数据判断专用检索引擎；任务优先 DB outbox + worker。
- 微信小程序保留独立呈现层，复用 Rust API、身份/订单/权限/考试语义；不把 Next 页面打包嵌入小程序。

## 为什么不是现在切 Vue / Nuxt
项目现有 Next.js App Router、React 界面、数十个实际 API、真实试卷/学习记录、微信支付和小程序合同已有生产能力。Nuxt 4 也支持 SSR/混合渲染，但大迁移不自动改善成本、SEO 或转化率，反而带来第二套组件和授权/成绩回归风险。**不反对 Vue**，仅不作为现在的首选重写项目。

官网依据：
- Next App Router: https://nextjs.org/docs/app
- Nuxt 4 rendering: https://nuxt.com/docs/4.x/guide/concepts/rendering
- axum / tower: https://docs.rs/axum/latest/axum/
- Nuxt UI library (若未来另建独立前端): https://ui.nuxt.com/

## 信息架构：先考试后资料、可随时使用
```
首页 / 一站式考试与资料检索
├── 考试大全 / 7大领域 / 53方向（唯一 EXAM_DIRECTORY）
│   └── 考试方向页：概述、年份/地区/级别/题型、已验证内容与可用动作
├── 资料中心：真实资料与试卷；索引、来源、样本、授权、题数
├── 在线练习/考试：开始、答题、提交、复盘、成绩
├── 考试与赛事管家：官方时间线与提醒
├── 我的学习：一个微信身份、订单权益、训练与报告
└── 机构工具：另行授权的机构入口，不强制个人创建家庭树
```
**内容对象同一底座**：`Assessment` / `Exam` / `Paper` / `Question` / `AnswerVersion` / `SourceProvenance` / `Rights` / `Entitlement` / `Attempt` / `Report`。
导航方向不是付费 SKU；任何未验收项目显示“内容准备中”，不伪造开考/下载/收费按钮。

## 视觉规范：SOCTHINK / Knowledge Blue
原则：像全国级专业资料与考试门户，而不是只有数学的小竞赛站。
- 主色 `#1454A8`（专业蓝）、深底 `#10284B`、辅助 `#2F6FE4`；底色 `#F5F7FB`，白卡 `#FFFFFF`。
- 文本 `#14253D`、次要信息 `#5D6C82`、边线 `#DEE5F0`。
- 唯一强调 `#F09A4A` 用于需要凸显的行动，不用于所有标签；成功 `#11765B`，待开放中性灰。
- 字体使用本地系统字体（优先 PingFang SC / Microsoft YaHei / system-ui），不分发字体文件。汉字正文字号 14–16px，列表标题 16–20px。
- 宽屏最大 `1440px`；12列网格，导航+筛选+内容；中屏两列，手机单列。44px 最小点击目标；375px 页面无横向滚动。
- 首页首屏：品牌主张 + 大搜索 + 常用考试分类；**直接展示真正能点的服务**，不是巨大空宣传图。
- 考试分类：左侧七大类/移动端横向分类切换，右侧层级标题+各类考试，明确 live/planned 和权利状态。
- 资料列表：紧凑列表优先，年份/年级/类型筛选；不强制每份资料使用营销卡片，不展示伪造价格/浏览量。
- 考试作答：独立专注布局，保留题目与公式输入、语音、计时、恢复和评分，不因公共门户换肤而破坏考场操作。
- 账号/支付：一个微信身份，购买必须经过官方支付确认；不以有按钮等于已成交。

## 标准化 UI 组件选择
- 公共排版/信息架构由平台统一 token 和布局组件控制；**复杂交互控件优先采用 shadcn/ui + Tailwind CSS v4 + 无障碍组件原语**（弹层、组合框、下拉菜单、日期等），减少自造复杂控件。项目目前尚未安装这些依赖，不把拟采用当成已接入。
- 官方方案： https://ui.shadcn.com/docs/installation/next 、https://tailwindcss.com/docs/installation/framework-guides/nextjs 。引入时先通过最小真实控件验证 CSS 优先级、包体积和 WebKit，再替换旧控件，避免把完整现有 98KB 全局样式盲目转换。
- 若坚持 Vue，则最佳对应栈是 `Nuxt 4 + Nuxt UI / shadcn-vue`，不是仅仅“装 Vue 模板”。但在本产品中不做双栈生产运行。
- 成本重点：公开考试与资料页尽量 SSG/缓存/CDN；仅必要的私人/实时视图运行 Next SSR，所有权威业务 API 迁 Rust。**Next SSR 仍需要 JavaScript 服务端运行时**，所以“业务后端全 Rust”不等于“服务器里绝无 Node 进程”；若未来明确追求零 Node 常驻，必须单独验证静态输出 + Rust API 的 SEO、登录、权限与成本取舍。

## 全站模板 / 底层共用契约
1. PortalHome（全站大搜索+7领域+真实可用入口）
2. Directory（目录/省份/年级/考试分层，可搜索）
3. ResourceList（筛选、列表、分页、可用资格）
4. ResourceDetail（来源、年份、版本、样例、格式、试卷/下载权限）
5. ExamWorkspace（题目/工具/交卷/恢复/复盘）
6. Commerce & Account（权益/支付状态/订单/下载/法定售后人工处理）
7. Institution Workspace（授权机构组卷、班级/数据报告）
以上组件在统一 token、宽度、排版、颜色、交互状态和响应式规则下迭代，不维护两套正式风格。

## Rust 迁移顺序（按边界、回归风险、收益，而非“全文翻译”）
- R0：测量现有端到端延迟、每个 API 成本、DB 查询、热路径；冻结 OpenAPI/JSON schema、幂等与错误码。
- R1：先迁无状态资源查询/分类聚合、资料元数据检索到 Rust，契约一致，并保留 Next 渲染。
- R2：考试试卷编排/评分在 Rust 实现，通过同一真实答卷 fixture、重放与评分一致性测试后切换。
- R3：订单权益、支付回调、法定资金状态对账（不增设常规退款接口）；这是一致性高风险模块，必须资金级验收、去重、签名验证、失败回滚。单一主账本，不双写两个权威库。
- R4：登录、会话、权限统一到 Rust，Web、小程序同时接入，撤出旧 Next TS 权限判定。
- R5：删除已替代的 Node 服务端业务代码及重复维护的 DB/作业；保留 Next SSR 层，不因此要求全部代码都叫 Rust。

## 成本与性能标准
- 上线页：LCP p75 移动端≤2.5s（真实数据）、CLS≤0.1、INP≤200ms，搜索按输入/响应 p95 目标≤300ms（API服务端，不含网络）。
- 机房成本报告 = 应用实例 + DB + 存储/CDN + AI 调用 + 带宽 + 支付手续费 + 内容授权；按每千次有效会话和每笔订单计算。
- 不因“百万题库”假设提前拆微服务；通过静态生成/缓存公开内容、分页查询、对象存储与 CDN 扩展。
- 自动测试：手机375/430px、平板768/1024px、桌面1440px；Safari/WebKit、Chrome；导航/检索/练习/支付每一步真实点击；必须有生产SHA读回。
- 保留生产自动回滚，按同一 SHA 一条主发布路径；不用未有证据的新门禁拖慢研发。

## 分期
本分支首先实现**可运行的公共门户视觉新模板和设计 token**，保持正式线上不动。通过独立编译、审计和桌面/手机验收、再经对照现有用户路径后合入。后续资源详情、考试工作台、支付/机构页面同体系逐页迁移；迁移完成直接删除旧模板，不保留两个正式界面。
