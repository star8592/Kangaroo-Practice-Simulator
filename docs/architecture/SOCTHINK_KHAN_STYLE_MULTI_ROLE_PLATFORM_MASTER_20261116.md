# SOC THINK 全站「可汗学院式」多学科、To C / To B 架构总纲（2026-11-16）

**状态：全站重构方案，非生产上线回执。** 未来架构以本稿为跨项目高优先级依据；过去只从职业馆或英语馆出发的设计仅供历史对照，不据此清空已有数据、覆盖已验收界面。借鉴 Khan Academy 的多学科内容体系、学习者/教师/学校分工、AI 教学与学习进度闭环；不复制其品牌、受限制素材、源代码或非营利定价制度。

## 1. 核心架构：学科与客户是两个独立维度

**学科/产品轴**：数学与国际竞赛、英语与语言、校内学科（语文/科学/物理等）、考试升学、职业技能/岗位实训、能力测评。某一产品可提供阅读、练习、考试、模拟、发音评分等多种活动；不为每科另写账号/班级/计费。

**用户与客户轴**：To C 个人学习者（儿童、家长、成人、求职者）；To B 独立教师/培训师；To B 学校、培训机构；To B 企业培训/HR；平台管理员。身份、授权角色、组织归属、付费主体和学习者不能混为一谈。

四个用户工作空间：
1. **个人学习中心**：找课、练习、考试、历史成绩、学习报告及自己获授权的作业。无教师也可独立学习。
2. **统一教师工作台**：跨数学、英语、校内学科、职业实训等产品选资源、建班、发布作业、收成绩、AI 汇总；不再为每科开发教师申请和单独工作台。
3. **学校/机构/企业管理中心**：管理本组织教师/培训师、班级或培训批次、服务席位、组织购买、授权范围内的汇总学情；企业培训与普通学校在 UI 用词不同，但底层组织、成员、任务和权益尽量复用。
4. **平台管理后台**：所有模块的权限授权、统一订单/权益/退款、资源审核、产品开通、运维。管理员可直接打开教师/学生界面及隔离模拟预览，无须提交教师申请；访问真实未成年人数据须独立校验具体上下文与操作审计。

**交互与商业分离，能力和账户共享。** To C 和 To B 营销、首屏、主要操作与产品权益定价完全不同；共享 SOC THINK 微信登录、服务端身份和角色、唯一计费账本、学习资源索引、课程任务与学情对接协议。不能把两个门户误实现为两套后台与数据库。

## 2. 可汗学院具体值得参考的地方

- 全学科目录：数学、语言、科学、编程、考试准备同处一个可搜索体系，而不是若干应用之间的登录跳转网。
- 同一学习活动两种入口：个人自主选择 vs 教师对班级/个人布置任务，仍用同一实训/练习引擎；只是学情归属不同。
- 教师使用同一内容库和班级作业汇总，不需要逐个批改；机构在授权范围内看汇总与教师/组织管理。
- AI 学生辅导与教师减负是不同工作流，评分证据与生成式教学建议分开保存。
- 不照搬美国学区采购、非营利免费定价及 Khanmigo 年龄/服务政策；SOC THINK 采用中国市场可交付、可验证的商业权益。

## 3. 实际主站盘点与目前的主要错位

2026-11-16 检查公开首页及源码 `src/components/SocthinkPortal.tsx`：六卡分别指向：
- 数学 `/math`：主要是国际竞赛、试卷、口算、报告及赛事管家，保留赛制和年级/国家差异。
- 英语 `/english`：AccentLab 发音、词语星球、AelOS 阅读及少儿绘本；EnglishLeap 旧阅读仅保留历史记录导出，不再新增同类阅读收费产品。
- 校内学科 `/resources`：目前实际是国际数学竞赛试卷检索（419 条可用练习卷目录），与「语文/科学/物理等校内课程」的承诺不一致，且沿用职业导航；不能继续把它当校内学科首页。
- 职业技能 `/learn`：真实存在 AI Agent、SQL、JavaScript 等实训；它是**职业专项馆**，不是综合学习中心。
- 能力测评 `/assessment-center`：九套训练/研究性测评，明示未建本土常模，不能被作为招聘淘汰或诊断工具。
- 考试升学 `/assessments`：跨中小学、竞赛、语言、考研及职业资格的目录，其中大量仅规划，不能把目录量当成可售服务量。

已有跨应用管理骨架：`src/app/workspace/page.tsx` 通过 `myAuthorizedModules()` 按授权显示模块；`src/app/english/page.tsx` 已将老师引向 `/workspace`。**优先复用这一入口与权限基础**，但生产 `/workspace` 页面需另做实际浏览器核验，防旧版本/路由冲突。

主站 `/api/auth/parent/me` 已有真实登录会话和服务端 `siteAdmin`；不能再要求管理员申请教师身份。AccentLab PR #73（Draft）是英语端第一阶段身份导航修复，不代表全站方案已完成。

| 需求 | 目标入口 | 对现有页面的处理 |
|---|---|---|

## 5. 统一平台最薄的领域契约

- `Account`：SOC THINK 唯一认证身份；微信标识与稳定主站 Account ID 分离。
- `RoleGrant`：人 + 授权角色 + 作用域（platform / organization / teaching workspace）+ 状态；角色不是付费套餐。历史身份字段 `role=parent` 不能作为完整平台授权依据。
- `Organization` / `Membership` / `Group`：学校、机构、企业及其教师、班级或培训 cohort；一个用户可跨多个获授权组织。
- `ResourceRef`：product_id、resource_id、version、type、subject、适用年级/水平、许可和可用状态、原生启动路径；资源权威仍由原始业务负责。
- `Assignment`：教师/组/资源版本/题目/截止日期/分享链接；分享 token 不自动授予学生身份。
- `Attempt` / `Assessment`：真实学员提交、模型/题卷版本、每次原始成绩/语音和结果状态；自主学习与教师作业归属清晰分离，不覆盖多次尝试。
- `ProgressProjection`：各角色从经授权的业务记录得到可读视图；学校和企业只查看本组织合法授权数据，不能读取员工个人未授权测评。
- `Entitlement` / `UsageMeter`：唯一支付账本与服务端权益、消耗、退款/撤权。订单购买者与学生/机构席位持有者可以不同，但一笔订单不能在各子产品重复记账。

**技术路径**：继续采用现有主站 Next.js + 已部署的业务服务；PostgreSQL 18 统一集群/实例、按模块 schema/角色或业务数据库隔离，业务可继续维护独立代码库；只引入必要的对接 API/只读学习报告，不开发第二通用 CMS、消息队列、大型新网关。现有英语发音、数学竞赛、职业代码实训 UI 和评分器保持专业原生能力。

## 6. 统一教师工作台应是全站唯一的

教师每天最短闭环：「选择班级/训练营 → 选择数学、英语、科学、职业课等已有资源 → 一次布置 → 学员在原组件完成 → 自动评分、汇总完成情况和薄弱点 → 一键复练」。老师不必逐项收录音、手工批每道题，也不需要在不同学科重新申请角色或输入密码。

B 端的学校/机构负责人管理教师与教学额度，不直接代替教师执行所有教学任务；企业 HR 采用 cohort/培训项管理，但仍用同一任务和证据服务。平台管理员可直接进入所有工作空间的 UI 与模拟预览，真实学生私有记录仍依赖服务端授权和留痕。

## 7. 收费方式：客户旅程分别设计，主站统一支付

- To C：基础免费学习、专项按次、月度/年度个人权益、跨科组合权益，按可交付能力和成本定价。
- To B 独立教师：可免费体验，再按学员席位/班级容量/AI 调用额度购买，功能核心是节约教学劳动量。
- To B 学校培训机构：按组织席位、课程、服务期限、教师配额购买，成员授权与购买者分离。
- To B 企业培训：按培训项目、cohort、使用量购买，不将招聘评估混同普通自主练习。
- 统一微信支付/订单/权益/发票与撤销；不给英语/数学/职业模块增加本地新计费权威。

所有定价为待验证商业设计，不声称已经存在这些产品套餐。可汗学院的非营利免费政策不照搬。

## 8. 实施顺序（不破坏当前可用功能）

**R0 盘点**：扫描全站路由、实际公网可用状态、源码/发布 SHA、用户库/计费库、各业务后台、教师页面和孤儿链接；产出「保留/迁移/合并/退役」逐 URL 映射。特别核验 `/workspace` 生产页面、`/resources` 的误定位与职业旧导航。

**R1 统一门户**：先调整公开主页和角色落点：个人学习、教师入口、学校/机构入口；已有六方向不消失；多角色切换。管理员不申请教师权限。

**R2 先整合两门学科的 B 端**：优先将已具备基础的数学作业/成绩与 AccentLab 发音作业/报告接入同一 `/workspace`，教师不再跨两套后台；原数学题库、发音评分仍各自运行。

**R3 接入其余学习服务**：AelOS 阅读、词语星球、校内课程、职业实训逐模块接入统一资源/任务/学习报告契约。没有真实可用课程的标签不产生空收费页面。

**R4 机构/企业与统一计费**：组织授权、教师/学员席位、课程包、支付权益与单位使用量；多组织、跨班越权、退款、撤权、未成年人音频权限要通过真实测试。

**R5 减法清理与正式切换**：清理重复菜单、教师自助申请、无用旧阅读、伪页面和孤儿路由；逐个迁移保留历史结果与深链接。发布仍只有必要的账号、计费、评分、核心路由、真实移动端、自动回滚硬门槛，不能用 HTTP 200 取代功能闭环。

## 9. 验收的最小真人旅程

1. C 端无老师学生：学习数学、英语和职业项目，保持一个账号与自己的学习进度。
2. C 端班级学生：从微信作业链接进入并返回指定练习，独立学习也可继续，不能访问其他学生录音和成绩。
3. B 端教师：一个身份、一个工作台，分别给同班布置数学与英语作业并看到自动成绩；不需要教师提交权限申请。
4. B 端学校负责人：给本组织老师授权和额度，查看合法汇总，不跨租户。
5. B 端企业培训主管：只看所属培训项目，不擅自使用员工私有自主学习或研究心理测评信息。
6. 平台管理员：可打开全部工作台及隔离的学生预览，不需要重新申请角色，真实数据管理行为可审计。
7. 全站验证：统一登录/微信回跳、订单权益、过期/退款、真实 AI 成本、原学科引擎、390px 手机、旧路由映射、失败自动回退、真实生产 SHA。

**定论：SOC THINK 是跨数学、英语、校内课程、考试、职业培训和测评的综合商业教育平台。To C 与 To B 是两套独立用户体验、共享一个账户与 AI 教育能力底座。可汗学院是主参考模型，但我们不复制其内容、代码或商业规则。**
