# SOC THINK 职业产品站：视觉与成交体验设计总纲 v1.0

生效方案：2026-11-04。配套于《SOCTHINK_SITE_ARCHITECTURE_MASTER.md》；不另建一套导航、CMS、支付、订单或学习记录。

## 1. 业务定义

**产品定位**：面向校招学生与社招求职/转岗人员的 AI 原生职业能力学习、实训与模拟服务。不是“所有考试的大全”、传统在线课程超市，也不是把开源原文收费转售的资料站。

**两个需要同时优化的结果**：
1. 对用户：从进入网站到找到匹配岗位/能力训练、判断能否学会、验证效果的时间与操作成本尽量低。
2. 对经营：真实服务展示→免费试用→核实的按次/包月订单→履约→继续训练→自愿复购的转化效率和留存质量尽量高。

没有实际开售的职业产品就不能写“立即付款”“仅剩名额”或填预估售价；不把生成购买页、HTTP 200、测试订单当作真实成交。

## 2. 信息架构，遵循三个用户任务

| 一级导航 | 用户真正想做的事 | L2 | 不能混入的内容 |
|---|---|---|---|
| 岗位方向 /career | 找到我想去的岗位和对应服务 | /career/paths, /career/roles | 仅有分类没有交付时不能冒充商品 |
| 学习与实训 /learn | 开始学、运行代码或完成案例 | 原创课程、实验、技术资料 | 未取得授权的原视频/整本资料 |
| 模拟笔试与面试 /practice | 验证技能与复盘表现 | 完整岗位笔试、编程、结构化面试 | 未实现的 AI 语义评分 |
| 账户与付款（工具，不升一级业务） | 明确价格与权益，完成付款，查看交付 | /login /account /membership /career/interviews/... | 数学训练和职业资料混售造成歧义 |

数学/K12 独立课堂从 /math 保留，后续物理拆分；职业搜索投影不可导入 EXAM_DIRECTORY 或数学源表后再客户端过滤。数学历史、试卷、支付账本仍受原权限保护。

## 3. 首屏与页面模板（单个页面一个主要任务）

### 首页 /：不做信息博物馆

首屏不超过一句价值主张、一句交付解释、一个岗位主 CTA、一个模拟次 CTA、一条实用搜索框。
- 首屏下：校招/社招两个入口，保留选择直至详情页。
- 第二屏最重要的是 4 条**有真实交付内容**的岗位路线，不是“270 岗位”数字及企业样本；
- 下方才是更新、技能书、证明资料、完整岗位分类。技术研究放进详情折叠区。
- 不弹窗强制注册、不给“免费领取”套上隐含付款；数学入口不混进职业主导航。

### 岗位路线列表 /career/paths

每张卡四个必要信息：**岗位名称、能获得什么、当前开放几个环节、查看路线/免费练习**。同一类项的卡片宽高、字体与行为一致。不得为尚未存在的专项服务显示“已开放”或价格。

校招可用真实项目、实习与课程作为证据，不要求工作年限；社招重点是生产经验、业务结果和可核验的项目贡献。两个阶段共用底层能力图谱，但不强制同一套题本。

### 岗位路线详情 /career/paths/[slug]

桌面：左侧岗位价值与结果，右侧**交付摘要 + 当前可点击的第一项训练**；移动端先显示标题与 CTA，再显示长内容。
随后：选择校招/社招、学习/实训/笔试/面试逐项列出，每项有状态和真实入口；需标记“尚未上线”的不出现支付按钮。原始参考、许可与边界放在可展开的证据区，仍然能查。

真正开售商品的**详情模板**必须包含：
- 具体价值：适合谁、训练哪些技能、购买后交付几次/几页/几题/多长时间；
- 真价：来自可交易账本的人民币价格、权益有效期、是否自动续费、按次与包月的实际场次；
- 试用：用户可先免费完成的有效活动和可见样例；
- 正式付款：同一个已审核商品、微信登录与原有 NativeCheckoutPanel，支付回执真正确认后才给予权益；
- 售后：数字商品条款与适用法律规定的救济情形在购买前清楚呈现。

### 考场、面试、报告

模拟考试和面试页面必须有明确的入场确认、题量时限、保存与退出方式。报告不应仅显示分数：要给技能分解、证据和下一次能训练的具体项目。若报告收费，未付费只能显示确实可生成的预览内容，不可拿假分数逼付款。

## 4. 设计系统

目标视觉：**专业、现代、可靠、克制、有成交能力**；不是儿童竞赛风，不是炫技 AI 深色仪表盘，也不是堆售卖口号的微商落地页。

- 颜色：主文字 #142F43；品牌主色 #125E7E；强调深色 #104C69；浅背景 #F1F7F9；主白 #FFFFFF；线 #D7E4EB；完成/已开放用低刺激度 #126D61。避免一个页面出现六种主要按钮色。
- 字体：优先系统中文字体；主标题 32–50px（移动 30–39），一级正文 16–19px，商品名称 >=20px，按钮 >=15px，说明文字不长期低于 13px；关键信息不用极细浅灰。
- 网格：宽屏最多 1440px，自适应 4→2→1 列商品卡；手机横向内边距至少 14px；一张商品卡尽量少于四行描述。关键 CTA 至少 44px 高，触控反馈清楚。
- 版式：主按钮深蓝、次按钮白底描边，价格比说明显著，商品卡展示具体数字而不是空泛标签。只给一个最重要的信息视觉优先权；不要重复的“菜单 + 快捷入口 + 服务卡 + 类目卡”反复出现。
- 可访问性：键盘焦点、清晰标题层级、手机横向溢出零容忍；尊重 reduced-motion。不追求无意义的轮播、自动播放或大面积动效。
- 全站共享 **现有**布局与变量，不新建第二套 CSS 框架。新增 career-specific 样式局部隔离；不改变数学考试页面的答题布局。

## 5. 诚实商业化状态机

| 商品状态 | 向用户显示 | 不允许显示 |
|---|---|---|
| 未开发 | 尚未上线、已开放的替代内容 | 价格/立即付款/“AI正式评分” |
| 开发完成但未通过授权/履约核验 | 免费且确实可用的部分、当前状态 | 收费承诺 |
| 真实上架但支付功能未就绪 | 价格/交付详情可审慎展示、不可下单状态 | 虚假二维码、假订单 |
| 全部验收且买家有购买资格 | 与账本一致的价格、按次与包月、清楚勾选条款、微信 Native 付款 | 隐藏自动续费、捆绑额外 SKU、默认勾选 |
| 付款待确认 | 原订单核对中、防重复支付提醒 | 先发权益或重复创建订单 |
| 真实付款成功 | 可验证权益、订单记录、下载或面试场次 | 以页面跳转替代支付核验 |
| 已完成训练 | 真正获得的报告、下一次有针对性的学习推荐 | 捏造评分、就业效果或虚构优惠 |

现查职业 AI 面试公开购买 API 两个 profile 的 available=false，因此本阶段做转化结构和免费试用，**不宣称已实现职业收费成交**。

## 6. 数据指标、增长与复购

北极星：**经过核验的职业付费交付与有效能力提升**。不以“新增页面数”“岗位数量”“点击假支付按钮”代替。

漏斗事件（先查现有后台是否具备后再实现，必须遵守隐私与授权）：
- discovery_search → role_path_view → trial_start → trial_complete → paid_offer_view → checkout_start → payment_verified → entitlement_delivered → repeat_purchase；
- 切分校招/社招、岗位、设备、来源、真实 SKU；报表区分浏览器事件、订单回执和交付回执，不可混算；
- 观察搜索无结果率、商品页→免费体验率、实操完成率、合法可购 SKU 的付款启动率、扫码失败率、经核验付款率、30 天复购率；
- 真实上线后用小流量比较文案、卡片排序、试用位置及套餐呈现，不擅自宣称“提升30%”等未经实验数字。

复购策略：在每次真实成绩与能力复盘之后，推荐**对应短板**的下一套训练/新场次；月包只对真实持续需求展示，权益上限与截止时间一目了然，非自动续费。无关资料不强推。

## 7. 上线顺序与边界

- **R0** 页面设计与发现：首页职业路线前置、校招社招分流、职业搜索脱离数学、产品详情交付摘要及真实试用 CTA；完成后桌面/手机真实浏览器核验。
- **R1** 商品：独立职业 SKU、真实价格、完整面试/报告履约，使用既有微信支付和订单系统。必须拿到第一笔真实收款+权益交付+售后查询回执，才称“可销售”。
- **R2** 数据驱动：漏斗仪表板、岗位弱点报告、续购关联推荐与 SEO/GEO 页面结构化数据。
- **R3** 数学物理迁移：数据对账后部署独立站点和独立运行环境；本轮仅隔离职业用户体验，不删原学生业务。

**回退**：沿既有 CI + 生产 SHA 回执 + 自动回滚，改设计不增加第二套发布审批。重大支付功能绝不通过 UI 改动“代替”真实订单/微信核验。
