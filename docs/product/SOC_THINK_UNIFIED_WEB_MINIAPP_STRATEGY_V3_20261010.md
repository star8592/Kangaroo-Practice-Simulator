# SOC THINK 主站与微信小程序统一定位及产品重构方案 V3

- 日期：2026-10-10
- 状态：产品战略与设计基线（待评审、尚未实现/上线）
- 作用范围：socthink.cn、微信小程序、统一后端 API、管理后台
- 适用既有设计契约：`docs/UI_DESIGN_SYSTEM.md`、`docs/OPEN_ACCESS_IDENTITY_MONETIZATION_V2.md`
- 原则：在独立分支实现；不得覆盖并行开发工作树；不得将设计完成表述为生产验收完成。

## 1. 产品定义

**主品牌：SOC THINK**  
中文类别定位：**全球数学竞赛与成长平台**  
英文类别定位：**Global Math Competition & Growth Platform**

一句话价值主张：帮助学生发现数学能力、进行高质量训练、参与适合自己的全球赛事，并将真实进步沉淀为长期成长档案。

**不**单独把平台定位为“计算器/口算工具”“真题刷题站”或“赛事公告网站”。“全球赛事管家”是差异化的旗舰业务，“计算训练”是高频留存入口，“竞赛模拟”是能力验证和专业服务，“数学成长”负责长期关系。中国赛事与国际赛事同等呈现，不以“国内/国外”建立产品等级。

### 核心对象与用户目标

| 用户 | 最重要的任务 | 立即可执行的动作 |
| --- | --- | --- |
| 学生 | 每天练习、参加模考、看到成长 | 直接开始训练/模拟 |
| 家长 | 找到适合孩子的赛事、报名提醒、解读学习结果 | 浏览赛事、选择孩子、订阅提醒 |
| 教师 | 布置训练、组织模拟、查看学情 | 教师工作台（后续按能力逐步开放） |
| 游客 | 低阻力验证平台是否有价值 | 不登录浏览、完成公开训练并查看基础结果 |

## 2. 四大业务域与共享底座

1. **数学训练中心**：G1–G12 计算与数学技能、知识点专项、限时训练、诊断和错题巩固。
2. **竞赛模拟中心**：按真实赛制组织真题/样题、计时、计分、答题卡、可控中英双语题干与选项朗读、赛后报告。
3. **全球赛事管家**：中国与国际赛事统一目录、主办方/赛区/年级/语言/日期/报名/赛制/费用/官方来源/校验日期、赛程日历、收藏和报名提醒、适配推荐与备赛任务。
4. **数学成长中心**：同一学生档案汇聚训练、模拟、错题、进步、赛事计划、真实奖项和“站内模拟荣誉”。真实奖项与模拟荣誉必须明显标注并验证来源，不得混淆。

共享平台服务：Identity & Household、Student Profile、Practice Attempt、Exam Attempt、Competition Catalog、Schedule & Reminder、Report、Entitlement & Payment、Content Provenance、Audit。Web/小程序共用 API 与权限模型，不为客户端另造一套赛事或学生数据。企业教师场景作为扩展，不挤占首版学生/家长导航。

## 3. 主站和小程序分工

| 能力 | Web 主站 | 微信小程序 |
| --- | --- | --- |
| 发现产品与公开内容 | SEO、可分享落地页、深度说明、赛制和题库目录 | 轻量发现、分享直达 |
| 计算训练 | 复杂输入、完整训练和打印 | 高频快速训练、触屏输入 |
| 竞赛模拟 | 大屏考场、完整试卷、深度诊断 | 移动仿真考试、双语朗读、续考 |
| 全球赛事 | 完整筛选、比较、官方来源、赛程专题 | 收藏、提醒、赛程卡、分享 |
| 成长档案 | 家长深度报告、打印、历史趋势 | 当日任务、最新进度、重要提醒 |
| 身份 | 游客优先；需持久身份时微信扫码/其他合规方式 | 低摩擦微信身份；公开体验不被登录失败阻断 |

两个端保持**同名业务域、同一学生身份、同一考试和学习历史、同一权限结果**；只按设备特征调整呈现，不追求像素级完全相同。

## 4. 信息架构与导航

### Web 一级导航（建议）

`计算训练` / `竞赛模拟` / `全球赛事` / `成长档案`；右侧为语言、身份/家长中心和权益入口。

- 首页：四业务预览 + 直接开始计算 / 查找赛事 / 开始模考。
- `/arithmetic`：保留已有路径，改进可发现性与游客路径。
- `/competitions`：优先承担全球赛事发现与综合目录；现有赛事训练页面拆分为对应赛事详情与试卷入口（兼容老链接）。
- `/exams`：新的竞赛模拟聚合入口；实际开发先做路由和兼容映射，再迁移。
- `/student`、`/parent`：整合到分角色的“成长档案/我的”，保留旧路由和数据。
- `/review`：作为训练/成长域的二级功能，而非顶层定位。
- `/verification`：作为学术质量、证书和题解验证的可信度入口，而非高频一级导航。
- `/membership`：权益透明展示，不预先承诺未交付能力。

### 小程序 TabBar（至多 5 项）

`首页` / `计算` / `模考` / `赛事` / `我的`。

首页首屏必须能一眼识别三大可执行动作：**开始计算训练、参加模拟考、查看赛事**。每个卡片点击进入真实可用流程；没有服务的模块不可伪装成已可用。成长档案、家长关系、订阅权益、荣誉以及设置在“我的”内按身份展示。

### 赛事目录组织

中国和世界其他地区赛事共用数据模型、搜索、筛选和展示组件，以地区/年龄/难度/时间为筛选维度；首页推荐不得只有英语或国外赛事。名称、主办方、官方 logo、举办日期、报名链接、竞赛规则均需来源/授权校验；日期状态显式标明已核实/待核实/过期。未经证实的竞赛不得以“正式赛事”背书。

## 5. 页面体验与视觉标准

沿用 `docs/UI_DESIGN_SYSTEM.md` 中 1200/1440/960/1040/820px 宽度层级、响应式断点和间距规范；新布局先修改统一 token / 共享组件，不在不同页面重复发明按钮、弹窗和表单。

- 首页：一个清楚的价值主张 + 一个明确的主要动作；训练/模考/赛事并列入口在首屏或紧邻首屏；避免让大量抽象方法论占据首屏。
- 训练页：按年级、知识点与难度快速开始，显示真实范围和可用内容，支持初高中；数学公式正确渲染、可输入、可回顾。
- 模考页：分步答题/跳题/标记/剩余时间/自动保存/成绩；完整朗读题干和所有选项；计分严格继承对应赛事赛制。
- 赛事页：按地区、年级、能力、报名截止日期过滤；官方信息与平台备赛服务清楚分层。
- 成长页：只有真实进度数据时才展示趋势；无数据使用明确引导，不显示无解释的“0分”仪表。
- 身份体验：公开训练不被登录墙阻断；微信身份及邮箱身份安全映射，不以昵称合并；会话过期、断网与续答需一致处理。
- 语言与无障碍：中英界面分开校对；聚焦态、键盘操作、屏幕阅读器标签、字号对比度和移动端触控目标均纳入验收。

## 6. 现状审查（2026-10-10）

公开页面与分支源码检查确认以下需要治理之处：

- 公开首页仍以“国际数学竞赛训练中心”和诊断为主要定位，四张赛事卡均为国外或国际项目；没有完整展示同等地位的中国赛事。
- Web 顶部导航现为计算训练、竞赛中心、错题复盘、验证中心；业务之间的关系不够清晰。
- 首页“开始能力诊断”实际指向 `/arithmetic`，文案/动作需一一对应。
- 对外权益说明写有游客基础计算可用，但本次公开访问 `/arithmetic` 被重定向到 `/login?next=/arithmetic`。这属于**需要真实浏览器和 API 再验收的问题**，不能仅凭公开抓取认定所有游客均不可用。
- 既有 `OPEN_ACCESS_IDENTITY_MONETIZATION_V2` 明确“无登录墙、匿名可训练、身份后置、跨端一致”，重构须沿用，不得反向退化。
- 现有 repo 多工作树并行开发，直接覆盖主线或发布属于高风险操作。

- [ ] 建立线上原始基线截图、移动真机录屏、性能/转化基线与回滚点。
- [ ] 统一产品字典、四大业务域及同名中英文展示。

### P1：设计系统与高优先级体验
- [ ] 完成 Web 桌面/移动版与小程序首页/导航高保真稿。
- [ ] 实现共享导航/卡片/账号入口，不改动稳定考试内核。
- [ ] 三大首页 CTA 均通过点击后可用的端到端测试。
- [ ] 游客计算和模考基础路径、微信登录、会话恢复完成验收。

### P2：全球赛事管家
- [ ] 中国和国际赛事统一目录与可用性状态。
- [ ] 赛事详情、赛程、筛选、官方来源/校验日期、收藏提醒。

## 8. 不可妥协的验收条件

1. 首页三大主入口实际完成对应任务；无不可点击按钮、空页、错链、死路由。
2. 公开可访问的计算/模拟与游客权限矩阵一致，敏感报告/正式权益必须服务端核验。
3. 每一套正式赛制题量、时间、评分、语音朗读、结果快照均有自动化回归证据。
4. 不因重新分类而丢失已收藏赛事、学习记录、历史链接或订单权益。
5. 赛事中外平等，来源可核验；虚假的报名截止倒计时/官方合作/模拟荣誉不得上线。
6. Web/小程序同一业务语义、数据和权限；实际发布和回滚单独验收。
7. 现有独立开发工作树不能被强制覆盖；此方案先以文档 PR 审核，再按各阶段实施。
