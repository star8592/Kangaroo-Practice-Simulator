# SOCTHINK 客户投诉证据化处理闭环 v1

原仓库：star8592/Kangaroo-Practice-Simulator。原系统已具备“考生本人考试后反馈”、管理员后台分类与优先级排序；本迭代仅补工单状态与可追溯证据。

## 生命周期
- 待核查(open) → 核查中(investigating)
- 核查中 → 已修复/有结论(resolved)，必须填写证据引用
- 核查中 → 已驳回(dismissed)，必须提供核查依据；不能仅凭投诉自动改答案
- 已修复/有结论 → 已复测(verified)，必须提供复测依据
- 已复测 → 已归档(closed)，必须有归档说明及证据
- 已修复/已复测/已归档/已驳回如发现问题可退回核查中

## 不可妥协的安全
- 只有现有管理员账号及会话能够修改状态；拒绝无会话、跨站、非法值和超长输入。
- 反馈记录保持原始只读，不覆盖原试题、答案、成绩、用户数据或支付信息。
- 每次处理操作必须提供≥8字说明，核查结论和复测必须提供证据引用。
- 所有状态变动以JSONL增量日志存于原生产私有数据目录 customer-feedback-case-events.jsonl；每条包含反馈ID、前后状态、递增版本、时间、处理人ID、核查说明和证据引用。锁定写入、fsync、旧版本冲突返回409，任何日志损坏都拒绝继续写入。
- 管理员页面只渲染字段，不将原始学生身份、电话、邮箱或Cookie带进可访问页面；现有匿名化边界继续沿用。
- 改答案仍须独立题源核对和数学验证，工单状态变化不会自动发布新题库或改已有成绩。

## 商业闭环
每天按真实数量观察：每类新投诉、待核查数、平均核查/修复周期、已复测数、可证实复测后复发数；零反馈不等于满意。
这阶段先确认功能“真实使用→真实反馈→核查修订→复测”，再决定低价单卷和会员的付费实验。
正式发布需通过项目全部质量门禁、桌面/手机真实Chrome测试、标准CI、部署SHA、原始试卷库存保护以及管理员会话保护。
